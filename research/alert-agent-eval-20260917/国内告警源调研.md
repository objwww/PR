# 国内告警源/告警生态调研（面向告警触发评测场景）

> 调研日期：2026-09-17
> 背景：现有系统为 "Alertmanager → webhook → RCA Agent" 单源形态，欲扩充"告警触发页面"，一键产生真实告警供评测。本文调研国内可自部署/可用的告警源、云厂商告警回调、告警分发平台、多源接入业界做法与告警语料库。

## 1. 国内主流开源告警系统（可自部署、可发 webhook）

### 夜莺 Nightingale（n9e）
- 中国计算机学会开源发展委员会托管项目（ccfos/nightingale），定位"先进开源云原生监控分析系统"。告警引擎兼容 Prometheus 生态：把 Prometheus/VictoriaMetrics/Mimir 等作为**数据源**，告警规则用 PromQL 编写，支持直接导入 Prometheus alerting rules YAML（见[为 Prometheus 告警规则增加 UI 管理能力](https://flashcat.cloud/blog/add-ui-management-capabilities-to-prometheus-alerting-rules/)）。
- **webhook 回调**：全局回调 + 规则级回调两种粒度，HTTP POST，Body 为告警事件 JSON（即 `alert_cur_event` 结构体序列化）。实测 payload 字段：`id / cate(prometheus) / rule_name / severity(1-3) / prom_ql / trigger_value / tags[] / tags_map / is_recovered / trigger_time / first_trigger_time / target_ident / annotations` 等，结构较扁平、带中文规则名。来源：[夜莺 v7 webhook 文档](https://flashcat.cloud/docs/content/flashcat-monitor/nightingale-v7/monitor/notify-webhook/)。
- 内置告警规则模板：`告警管理 - 告警规则 - 导入告警规则`，内置 `linux_by_categraf_zh` 等中文规则组（见[快速配置告警规则](https://flashcat.cloud/docs/content/flashcat-monitor/nightingale-v7/monitor/quick-config/)）。

### Zabbix
- 国内传统主机/网络设备监控事实标准之一，存量巨大。告警外发方式：**Webhook 媒介类型**（Zabbix 4.4+，内置 JavaScript 引擎，官方/社区模板支持钉钉、企微、Slack 等），或 AlertScripts 自定义脚本。payload 完全由 JS 模板自定义，无统一格式。来源：[Zabbix 官方文档 Webhook 媒介](https://www.zabbix.com/documentation/8.0/zh/manual/config/notifications/media/webhook)、[Zabbix JS Webhook 配置（腾讯云社区）](https://cloud.tencent.com/developer/article/1848055)。
- 结论：payload 形态取决于用户模板，对接时需按方约定，不适合做"标准格式"评测，但适合验证"异构格式适配"能力。

### Grafana Alerting
- 国内自建可观测栈常与 Prometheus 配套。webhook Contact Point 默认 payload 为 JSON：`{status, alerts:[{labels, annotations, startsAt, fingerprint, status...}], groupLabels, commonLabels, title...}`，结构**与 Alertmanager 高度相似**（fingerprint/labels/annotations 概念一致）。来源：[Grafana 官方 webhook notifier 文档](https://grafana.com/docs/grafana/latest/alerting/configure-notifications/manage-contact-points/integrations/webhook-notifier/)。

### Prometheus Alertmanager
- 现有接入形态。webhook receiver payload：`{version, status(firing/resolved), alerts:[{labels, annotations, startsAt, endsAt, generatorURL, fingerprint}], groupKey, commonLabels, commonAnnotations, externalURL}`。是业界事实标准格式，ARMS 甚至支持输出"开源 Alertmanager 格式"（见第 2 节）。

### HertzBeat（Apache 孵化，dromara 社区）
- 国产、无需 Agent 的一体化监控告警系统，全 Web 配置。告警通知支持 Webhook（还有钉钉/企微/飞书/邮件/短信等），支持按标签和告警级别分派的通知策略。来源：[HertzBeat 官网](https://hertzbeat.apache.org/zh-cn/)、[文档-通知](https://hertzbeat.apache.org/zh-cn/docs/next/)。GitHub：dromara/hertzbeat。

### 其他
- **Categraf**：夜莺生态的采集器（all-in-one collector），不是告警源。
- **Open-Falcon**：小米开源老一代监控系统，存量仍在，但活跃度低，不建议新增适配。
- **Flashcat/Flashduty 商业闭环**：夜莺团队商业产品，见第 3 节。

## 2. 国内云厂商告警 webhook 回调

| 厂商 | 产品 | 方式/格式 | 鉴权 | 来源 |
|---|---|---|---|---|
| 阿里云 | 云监控 CMS 1.0 阈值报警回调 | HTTP POST，**form-urlencoded**（非 JSON），字段如 alertName/alertState/curValue/instanceName/metricName | 无签名，依赖 URL 保密 | [官方文档](https://help.aliyun.com/zh/cms/cloudmonitor-1-0/user-guide/use-the-alert-callback-feature-to-send-notifications-about-threshold-triggered-alerts) |
| 阿里云 | CMS 2.0 通知对象 Webhook | JSON，含 userId/ruleId/workspace/traceId 等 | 支持自定义 Header/参数 | [通知对象文档](https://help.aliyun.com/zh/cms/cloudmonitor-2-0/notification-object) |
| 阿里云 | ARMS 告警 Webhook | **Go Template 自定义模板**，可自行拼 JSON；默认上下文含 `.alerts/.commonLabels/.startTime`；**支持配置为"开源 Alertmanager 格式"输出** | 自定义 Header（如 `Arms-Content-Type: json`），超时 5s | [ARMS webhook](https://help.aliyun.com/zh/arms/alarm-operation-center/use-webhook-to-send-custom-alert-notifications)、[Alertmanager 格式](https://help.aliyun.com/zh/arms/alarm-operation-center/format-of-alert-notifications-sent-by-using-webhooks) |

| 腾讯云 | 可观测平台（云监控）告警回调 | HTTP POST JSON：`sessionId/alertId/alarmStatus/alarmType(metric\|event)/alarmLevel/alarmObjInfo{region,namespace,dimensions}/alarmPolicyInfo{policyName,conditions{metricName,calcType,currentValue}}/firstOccurTime/durationTime/recoverTime` | 默认**无认证**；支持 URL 内嵌 BasicAuth；失败重试 3 次、超时 5s；可投递到 SCF 云函数 | [官方文档](https://cloud.tencent.com/document/product/248/50409) |
| 华为云 | AOM | 告警经 **SMN（消息通知服务）订阅**推送到 URL；payload 为 `events[]` 数组：`id/starts_at/ends_at/metadata{event_severity,event_type,clusterName,namespace,resource_type...}`（CloudEvents 风格） | SMN 订阅确认机制 | [AOM 数据订阅格式](https://www.huaweicloud.com/guide/productsdesc-bms_cf98fd250b13de767b06d1a27d8a189bsupport0_y)、[AOM 动作回调实践](https://hcbp.gitbook.io/hua-wei-yun-provider/zui-jia-shi-jian/aom/action_callback) |

**差异要点**：各家字段命名、嵌套深度、时间格式（秒/毫秒/字符串日期）、严重度表示（数字/文字）、恢复语义（is_recovered/alarmStatus/单独 resolved 事件）全部不同；鉴权普遍薄弱（无签名或 BasicAuth/IP 白名单）。只有阿里云 CMS 1.0 用 form-urlencoded，其余基本 JSON。

## 3. 告警接收/分发平台（聚合层）

- **OneAlert（睿象云/博睿数据）**：国内首个 SaaS 云告警平台，支持 Zabbix/Prometheus/Nagios/Open-Falcon 及阿里云/腾讯云/华为云等告警源统一接入，提供标准化字段映射、收敛、分派。来源：[InfoQ](https://www.infoq.cn/article/KcHIHADLmwYhEyGlHMTX)、[产品说明](https://www.linuxprobe.com/zabbix-alert-use-onealert.html)。
- **FlashDuty（快猫星云，夜莺团队）**：on-call + 聚合降噪平台，定位为"监控系统之后的统一告警响应层"，支持 Prometheus（Alertmanager webhook）、Zabbix、Grafana、云厂商、夜莺、SLS 等集成，提供路由/标签增强/Pipeline 清洗/值班升级。来源：[Flashduty 一站式 on-call](https://flashcat.cloud/blog/flashduty-one-stop-alarm-on-call-platform/)、[阿里云 SLS 集成文档](https://docs.flashduty.com/zh/on-call/integration/alert-integration/alert-sources/aliyun-sls)。
- **生态位置**：这类平台证明"多源异构告警 → 归一化事件 → 统一响应"是成熟需求；它们对我们系统的启示是"适配层"而非"直连每一家"。OneAlert/FlashDuty 本身也可作为**多源聚合层**反向喂给我们（订阅其 webhook 出口），但评测场景下没必要，直接模拟各源格式更可控。

## 4. 关键工程问题：多源告警接入的业界做法

参考 [Flashduty《云监控、Zabbix、Prometheus 告警统一接入》](https://flashcat.cloud/blog/unified-alert-ingestion-cloud-zabbix-prometheus/)：

1. **架构共识：不替换监控源，在其后建统一响应层**。接入方式是"每源生成一个集成入口地址（webhook）"，统一的是**响应模型**而非接入协议。
2. **格式归一化（适配层）是标配**：为每种源写一个 parser/adapter，映射到内部统一事件模型。最小统一字段集：`service / team / env / severity / resource / check / cluster / owner`（加上时间、状态 firing/resolved、标题、描述）。
3. **格式差异有多大**：很大。Alertmanager/Grafana 是"labels+annotations+fingerprint"流派；夜莺是扁平结构+tags_map；云厂商是"策略-对象-条件"三段嵌套（腾讯云）或 form 表单（阿里云老版）；Zabbix 完全自定义。差异点集中在：严重度编码、恢复语义、标签位置、时间单位。
4. **接入模式分类**：专属集成（一源一入口）vs 共享集成（一个入口+路由规则分流）；入口层做 Pipeline 清洗（丢弃/改写/提级/标签增强），路由必须有兜底。
5. **对我们"单源→多源"的建议**：在 webhook 入口前加适配层（adapter registry：`source_type → parser → UnifiedAlertEvent`），内部 Agent 只看统一模型；评测时按源生成样本覆盖各家典型 payload。

## 5. 告警场景语料库

- **awesome-prometheus-alerts**（GitHub: samber/awesome-prometheus-alerts）：按目录分类的 YAML 规则集（host-and-hardware、docker、k8s、databases、web-servers 等），是事实标准语料；夜莺官方教程演示直接导入夜莺（[来源](https://flashcat.cloud/blog/add-ui-management-capabilities-to-prometheus-alerting-rules/)）。
- **夜莺内置规则模板**：`linux_by_categraf_zh` 等中文告警规则组，可直接导入业务组使用（[来源](https://flashcat.cloud/docs/content/flashcat-monitor/nightingale-v7/monitor/quick-config/)）。
- **阿里云 Prometheus 告警规则模板**：控制台内置模板 + PrometheusRule 方式（[来源](https://help.aliyun.com/zh/cms/cloudmonitor-1-0/use-cases/use-prometheusrule-to-create-prometheus-alert-rules)）。
- **分类法**：可直接沿用上述规则的分类维度（主机硬件/容器 K8s/数据库/中间件/网络/应用服务/云资源/日志事件），并叠加严重度分级（P1-P4 / critical-warning-info）作为评测告警场景分类骨架。

## 6. 可接入性结论（面向我们的评测系统）

| 排序 | 告警源 | 接入方式 | 接入成本 | 理由 |
|---|---|---|---|---|
| 1 | Prometheus Alertmanager | 已有 | ★ | 现状 |
| 2 | 夜莺 n9e | 自部署 + 回调地址 webhook | ★ | 国产主流、docker 一键起、payload 是单条扁平 JSON、自带中文规则模板，最适合做"点一下产生真实告警"的触发页后端 |
| 3 | Grafana Alerting | Contact Point webhook | ★★ | 格式近 Alertmanager，adapter 几乎免费 |
| 4 | HertzBeat | 通知 Webhook | ★★ | 纯国产、全 Web 配置，适合演示；格式需适配 |
| 5 | 阿里云 ARMS | 可输出 Alertmanager 格式 | ★★ | 用其"Alertmanager 格式"开关可零适配；原生 Go Template 格式亦可模拟 |
| 6 | 腾讯云监控回调 | HTTP POST JSON | ★★★ | 无需真云账号——评测时按其文档样例 payload 构造回放即可 |
| 7 | 阿里云 CMS / SLS | form-urlencoded / 模板 JSON | ★★★ | 同上，样例回放为主 |
| 8 | 华为云 AOM | SMN 订阅 URL | ★★★ | 需经 SMN 中转，直接对接成本高于样本回放 |
| 9 | Zabbix | Webhook 媒介 JS | ★★★★ | payload 无标准格式，价值在"异构适配"测试，优先级可后置 |

**总体建议**：评测触发页按"两档"建设——
- **真实链路档**：本地起夜莺（或继续用 Alertmanager）+ 若干规则模板，点按钮→改指标/造数据→真实触发→webhook→Agent；
- **样本回放档**：内置各云厂商/各开源系统的典型 webhook payload 样本库（字段已在上文列出），点按钮→按所选源格式 POST 到统一适配层→归一化→Agent。回放档零外部依赖，是覆盖“多源格式差异”评测的最高性价比路径。
