# 告警日志 × Agent 日志 × 卡点可见性：现状盘点与建议

> 2026-09-11审查注：本文为原始盘点，类/表存在不证明RCA链已接线。旧model_call_ledger的review_run_id指向PR review_run，不能直接join出RCA在飞状态；STARTED也可能是待对账残留。证据全文读面仍需对象鉴权/脱敏，Loki新查询不能覆盖冻结快照。时间/卡点/费用的具体修订见[执行审查方案](../../docs/告警-评测中心与能力版本演进-审查及详细改造方案-v1.md)§一/三/五。

> 2026-09-11。回答四个问题：①告警的日志前端怎么看；②agent 的日志存在哪里；③程序员怎么在页面上验证 agent 给的证据；④agent 卡在某个阶段时能不能直接看出卡在哪（不扒代码）。

## 一、Agent 日志到底存在哪里（完整清单，已逐一核对）

我们的 agent 是**进程内执行**（`NativeInvestigationExecutor`，无独立日志文件），运行痕迹分两层：

### 结构化痕迹层（PostgreSQL，六张表——这是「agent 日志」的主体）

| 表 | 内容 | 关键列 | 前端可见性 |
|----|------|--------|-----------|
| `rca_event`（V14，V28 按月分区） | 调查事件流（**11 种事件类型**：RUN_STARTED / TASK_LEASED / TASK_DONE / TASK_RETRY_SCHEDULED / TOOL_CALL_STARTED / TOOL_CALL_FINISHED / TOOL_CALL_FAILED / CLAIM_CREATED / CLAIM_UPDATED / BUDGET_COMMIT / EVIDENCE_ATTACHED） | run_id + seq + event_type + **payload jsonb** + payload_digest | ✅ 调查详情「事件流」tab（SSE 实时推送 + REST 游标续传，`RunDetailView.vue:178-240`） |
| `rca_evidence`（V16） | **证据原文快照** | evidence_type / source / scope / time_start~end / **payload text（全文！）** / payload_digest / observed_generation | ❌ 无读端点（`EvidenceRepository` 仅 agent 内部消费）；前端只在 Claim 展开里看到 digest 引用 |
| `rca_tool_invocation`（V15） | 工具调用账本 | tool_name / tool_version / **action_digest** / state / reason_code | ❌ 无读端点（且只有 digest，无参数原文） |
| `model_call_ledger`（V5） | 每次 LLM 调用 | 模型 / prompt·completion·total tokens / cost_micros / latency / 错误码 | ❌ 无读端点（仅 `/agent-ops/summary` 聚合 24h 两个数） |
| `external_invocation_ledger`（V7） | 外部系统调用 | endpoint / request·response digest / tokens / state | ❌ |
| `tool_call` + `sandbox_job`（V6，引擎侧） | 工具入参 jsonb + 沙箱执行 | **tool_args jsonb** / state / truncated / exit_code | ❌ |

### 文本 stdout 层（容器日志 → 已接 Loki）

- `deploy/docker-compose.yml` 已部署 **grafana/loki 3.4.2 + OTel collector**（`/otlp/v1/logs` 双路接入，H-35），control-app / alert-web / notify-app 三容器日志全部 `json-file` + collector 进 Loki；
- **control-app 已有 `LogQueryExecutor`**（`infrastructure/tool/LogQueryExecutor.java`）：按 `service_name + 时间窗（≤900s）+ limit 201` 查 Loki，带 allowlist（fail-closed）、流式截断、三态无数据语义（EMPTY/SOURCE_UNAVAILABLE/QUERY_FAILED）——**但它目前只作为 LogsAgent 的调查工具被调用，没有暴露任何 REST 查询面给前端**；
- 应用侧无 logback 配置文件 → Spring Boot 默认 console 格式，结构化程度取决于代码里 `TracedTasks`（infrastructure/observability）注入的 trace 上下文。

### 告警（非 agent）日志

- 原始 webhook 事件全文在 `alert_event`（V7）+ `webhook_inbox`（V3）；
- 前端现状：IncidentDetail「证据」tab 的**事件负载**逐条展示 labels/annotations（`IncidentDetailView.vue:100-113`）——这是结构化投影不是原始 payload；原始全文无读面。

**一句话回答「agent 日志存在哪里」：事件/证据/调用痕迹在 PG 六张表（`rca_event` 是主时间线），文本 stdout 在容器日志且已经入 Loki——但除了 `rca_event` 事件流外，其余五张表和 Loki 在前端都没有查询面。**

## 二、业界对照（日志与证据验证怎么展示）

| 业界做法 | 我们差距 |
|---------|---------|
| Langfuse/Datadog LLM Obs：trace 详情里每次 generation/span 的完整输入输出（脱敏规则可配）、span 持续时间实时跳动（`screenshots/langfuse-trace-detail.png`、`datadog-llmobs-traces.png`） | 我们的事件流只有 11 类白名单事件摘要；调用参数/结果连后端都只存 digest |
| HolmesGPT：调查会话逐工具调用+返回全文直接可读 | 同上 |
| incident.io / Datadog Watchdog：**每条 AI 给出的证据带 deep link 回源系统**（点开就是那条 log 查询 + 时间窗），用户可自行核验 | 我们证据只有 digest 引用，payload 原文在库里没有读面——程序员验证证据目前要连 PG 查 `rca_evidence` |
| Grafana Loki 有现成 Explore UI / MCP 查询 | Loki 已部署但没有面向运维的前端查询入口 |

## 三、Agent 卡住时，现在能看出什么（不用扒代码）

### 已经能看出的（这部分做得不错）

1. **队列层**：卡住的 run 自动落「待干预」tab（bucket=stuck 判据：任务 BLOCKED / RETRY_WAIT / LEASED 超 deadline，`RunQueryService.java:176-184`）；行内「当前阶段」显示 **卡住/等待重试**，「卡点」列显示 `run.lastError` 或 `taskKey:STATE`（`RunsView.vue:68-73`）。
2. **DAG 层**：哪个节点卡住一目了然——11 态四重编码（色底+图标+边框+节点原文，`RunDagStatus.js`）+ SSE 实时变色；「仅看异常」一键过滤。
3. **任务抽屉**：lease 持有 worker + epoch、attempt 重试次数、deadline、上游/下游依赖各自状态（`RunDetailView.vue:143-168`）——「在等谁」已经能答。
4. **事件流**：TOOL_CALL_FAILED 带红色色条、「仅错误」筛选、按任务过滤、SSE 实时推（`RunDetailView.vue:178-240`）。
5. **全局**：监控页「就绪任务积压 + 最老等待」、SLA 横幅。

### 看不出来的（要查库/扒代码的六个盲区）

| 盲区 | 现状 | 真相在哪个字段/表 |
|------|------|------------------|
| **卡了多久** | 任务行只有 deadline，无已等待时长 | `RcaTask.readySince()` 在 stuckTask 内部用了但**不输出**（`RunQueryService.java:70-75`）；lease 领取时间、任务 startedAt 同样不投影 |
| **下次重试什么时候** | 显示「等待重试」但无 nextRetryAt | 退避时间在 worker 侧计算，事件流有 TASK_RETRY_SCHEDULED 但任务行不投影 |
| **正在等哪次调用** | 任务 RUNNING/LEASED，但卡在 LLM 流式？外部 API？工具审批？全不可见 | `model_call_ledger` / `external_invocation_ledger` 的 STARTED 未终态行 + `tool_call` state（三张表都有 task 归并键，零新采集） |
| **卡因分类** | blocker 是自由文本/状态码 | 可由 reason_code（TOOL 账本有 reason 枚举）+ 调用账本状态推导 |
| **证据原文** | Claim 展开只有 id/desc/digest/window | `rca_evidence.payload` text 全文在库里 |
| **agent stdout** | 无前端查询面 | Loki 里已有（OTel 已接入），`LogQueryExecutor` 查询能力已实现 |

## 四、建议（按优先级）

### P0-1 任务时间字段投影（后端小改，前端立即可显示）

`RunQueryService.detail()` 的 task 行补四个字段：`readyAt / leasedAt / startedAt / nextRetryAt`。前端任务抽屉与 DAG tooltip 显示：

```
状态：等待重试          已等待 37m
下次重试：14:32（退避 2m）
Attempt：3 次 ｜ Lease：worker-2（epoch 5）
```

队列行「当前阶段」列下加 `已卡 37m` 红字（>10min 变琥珀，>SLA 变红）。

### P0-2 「正在进行的调用」视图（卡点定位的最后一公里）

detail 投影 join 三张账本的进行中行（按 task 归并键）：

```json
"tasks": [{ ..., "inFlight": {
  "kind": "MODEL_CALL",          // MODEL_CALL | EXTERNAL | TOOL
  "target": "gpt-4o (route primary)",
  "startedAt": "…", "elapsedMs": 12345
}}]
```

前端任务抽屉显示「⏳ 正在调用 gpt-4o（已 12s）」/「⏳ 正在查 Loki service=payments（已 8s）」。**卡在哪一层（调度/模型/工具/外部源）从此一屏可见**——这是对「agent 卡在某个阶段」最直接的回答。

### P0-3 证据原文读面 + 一键核验（程序员验证证据）

- 新端点 `GET /api/rca-runs/{runId}/evidence`（可按 claimId 过滤）：读 `rca_evidence`（payload 本身就是白名单采集的快照，digest 自校验）；前端 Claim 展开显示**证据原文**（time window + source + generation）。
- 「在 Loki 验证」按钮：对 logs 类证据（source=loki），前端带 service + time window 调新端点 `GET /api/agent-ops/logs?service=&start=&end=&q=`（**直接复用已实现的 `LogQueryExecutor`**，allowlist 同款 fail-closed）——把同一时间窗的原始日志拉回来和证据 payload 并排对照。这就是 incident.io/Watchdog 的证据 deep-link 模式，我们只差一个 REST 壳。

### P1-1 运维日志查询页（Agent 日志 tab）

监控页或 RunDetail 加「日志」入口：service 选择（allowlist）+ 时间窗 + 关键词（run_id）→ 走上述 `/agent-ops/logs` 端点。Loki 已在栈里，后端查询器已写好，**只缺 REST 暴露 + 前端页面**。进阶：OTel 侧给日志行注入 run_id/trace_id 标签（检查 `TracedTasks` 现有上下文是否已带），即可在 RunDetail 直接看「这个 run 期间 control-app 的 stdout」。

### P1-2 卡因语义分类

blocker 后端归类为枚举：`DEPENDENCY_BLOCKED / RETRY_BACKOFF / MODEL_CALL_PENDING / EXTERNAL_SOURCE_UNAVAILABLE / APPROVAL_REQUIRED / BUDGET_EXHAUSTED`，队列列显示徽章（替代现在的自由文本），「待干预」tab 支持按卡因筛选。数据源：reason_code + inFlight + 预算账本状态。

### P2

- 工具调用参数/结果的**摘要级**回显（`rca_tool_invocation` 增加 args/result digest 对应的白名单摘要列——需过脱敏评审，thought/原始 prompt 红线不破）；
- 事件流 payload 的字段级文档（每类事件 payload schema 在前端 `EVENT_TYPE_ZH` 词典处挂说明）；
- Grafana Explore 直连 Loki 作为运维备用入口（已有 Grafana 栈时零成本）。
