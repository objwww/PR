## 一、OR-06 依赖故障有界（RR21~24）

### RR21 PG 暂不可写时发送告警及模型动作
- **注入**（独立窗，≤3 分钟有界）：对 deploy-postgres-1 执行 `ALTER SYSTEM SET default_read_only = on; SELECT pg_reload_conf();`——新事务全只读，连接池不断（比 stop PG 温和，恢复=改回 off+reload）。注：需 superuser；若被池长连接缓冲，则退化方案=短暂 `docker pause deploy-postgres-1` 60s。
- **断言**：①窗口内模型调用 fail-closed（rca_model_call 出现 FAILED+封闭原因码，**零伪造 SUCCESS**）；②控制面自身告警可见（StartupSelfCheck/ControlSelfCheck 或 gatus 面 PG 探针变红——落 gatus API 快照）；③恢复后同 run 重驱/对账幂等（无重复账行：uq 键位不破）；④审计链不断（outbox/事件在恢复后补投，不假 ACK）。
- **证据**：psql 会话日志+容器日志切片+gatus 快照+rca_model_call 行。

### RR22 模型 429/超时多层重试
- **注入**：复用 **r12 配额回落链**（`docs/测试证据/R7/e2e-脚本/e2e-r12-quota-fallback.sh` 已有 harness）：litellm admin 面压低配额触发 429 族。
- **断言**：①总物理尝试有界（step 级 DEFERRED→熔断→确定性未决收敛，R7RoleRunnerTest 已单测、真机复演）；②共享预算不被乘法放大（run 预算行 vs 各 attempt 消耗对账，总量 ≤ 预算）；③UNKNOWN 不返成可重花（BA 语义）。
- **证据**：a0 驱动日志+rca_model_call+预算账行。

### RR23 关键日志源不可用但模型可用
- **注入**：窗口内 `docker stop deploy-loki-1`（60~120s 后 start）。
- **断言**：①logs.query/logs.aggregate 调用失败诚实透传（NO_DATA/UNAVAILABLE 面，模型可见族=可修正重试）；②claim 不得引用伪造日志证据（evidence_refs 全可解析且证据行真实来源）；③两源缺一降级 HYPOTHESIS 而非硬造 ROOT_CAUSE（prompt v13 收敛纪律）；④恢复后无需人工即可继续（自动重驱收敛或如实 DEAD，无挂起）。
- **证据**：driver 日志+rca_evidence/rca_claim+Loki 恢复时间戳。

### RR24 备用模型不兼容/TLS/DNS 故障/时钟偏差
- **注入**：env override 把 OPENAI_COMPAT_BASE_URL 指向不可达地址（DNS 面）或自签 TLS 端口（复用 mock）；时钟偏差面=容器 date 偏移 5 分钟（docker exec date -s，需 privileged——若不可行记 N/A 理由）。
- **断言**：①错误分类有据（ROUTE_UNAVAILABLE/TLS/时钟码分族，不混一锅 UNKNOWN）；②能力拒绝/降级受控（fallback 模型切换按配置不逃逸）；③**租约无错误覆盖**（lease_epoch/config_epoch 栅栏——失败面不改写他人代际，R7ModelGatewayTest epoch 栅栏已单测、真机复演）。
- **证据**：override yml+错误码分布查询+租约账行。

## 二、OR-07 入口积压通知（RR25~28）

### RR25 同 firing 重投/匹配 resolved/新 episode 依次进入
- **注入**：复用 rr13-probe.sh 的 alertmanager webhook 面（轻注入，可在 CL-06 收官同窗顺跑）：同 payload 两次 POST（幂等）→ resolved POST → 新 summary 新 episode。
- **断言**：①重投幂等不铸新 run（BA-111 去重语义）；②resolved 不被吞（episode 状态推进）；③新 episode 开新 run 身份（incident generation +1）；④旧新 run 身份不混（task_key/run 绑定各钉各）。
- **证据**：webhook resp+episode/run 行序。

### RR26 阶梯增加入口负载并使 worker 变慢
- **注入**：traffic-up.sh（locust 3→30 用户阶梯）+ 窗口内将 AGENT_MODEL 指到高延迟端（或 flagd 全开加重模型链路）；观察 10 分钟。
- **断言**：①队列/最老等待可见（QUEUED run 的 oldest-waiting 指标或 rca_run created_at 分布落档）；②限流不假成功（被拒注入=4xx 诚实码，无 202 假收）；③控制通路可用（webhook/config API p95 仍 < 阈值——gatus 快照）。
- **证据**：locust 报告+run 队列时序+gatus 快照。

### RR27 接收器已收通知但响应丢失后重试
- **注入**：duty/notification 面（HOST2 duty-adapter 或本地 notify mock）：第一次投递返回超时（响应丢失）→ outbox 重试。
- **断言**：①幂等键在（重复投递不重复效果）；②不支持幂等的渠道明确"可能重复+UNKNOWN"文案（不装 DELIVERED）；③outbox 重试有界+时序可追溯。
- **证据**：outbox 行+适配器侧收据对比。

### RR28 渠道持续失败再恢复，混合恢复/触发通知
- **注入**：notify 渠道指向黑洞 10 分钟后恢复；期间制造 1 条 firing+1 条 resolved 混合。
- **断言**：①失败期无假 DELIVERED（渠道状态行诚实）；②恢复后重投身份正确（新通知带新 id，不复活旧投递）；③时序可追溯（outbox attempted_at 序）；④重试次数有界。
- **证据**：outbox/渠道状态时序表。
