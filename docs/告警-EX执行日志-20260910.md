   + errmsg 片段)`（截 120 字符）。空体→`OutcomeUnknown("empty_ack_body")`；
   非 errcode JSON→`OutcomeUnknown("unparseable_ack_body")`（回执形态不可证）。
   WebhookChannel.send() 把 response.body() 传入 fromStatus（原先丢弃响应体——
   这正是 NotificationAuditCharacterizationTest 钉住的审计锚缺陷：200+errcode=40014
   曾被标 SENT，翻面为 neverMarkedDelivered 断言 Retryable+business_code_40014+rejected）。
2. **最长通知期限**（FencedNotifyExecutor.retry() 墙钟闸）：
   `now > createdAt + maxNotificationAge` → 直接 DEAD
   (`notification_deadline_exceeded`)，last_error 带原分类原因。attempt 预算（次数闸）
   + deadline（时间闸）=「不无限退避」双封顶。notify_outbox.created_at 随领取带回
   （CLAIM RETURNING 增列），ClaimedNotification record 第 11 组件 createdAt
   `Objects.requireNonNull`。旋钮 `app.notify.max-notification-age-seconds`
   （默认 86400=24h，NotifyConfig @Value → Duration）。
3. **固定应急通道 oncall**（tier=LIVE）：compose notify-app
   `NOTIFY_CHANNELS:"test,oncall"` + `APP_NOTIFY_CHANNELS_ONCALL_TIER:LIVE` +
   `NOTIFY_CHANNEL_ONCALL_WEBHOOK: ${…:?}`（强制在场）+ SECRET 可选；
   control 侧 `APP_ALERT_NOTIFY_CHANNELS:"test,oncall"` 出口对齐。
   回执语义注记：**机器人接收 ≠ 值班员阅读**。
4. **errcode≠0 → Retryable 裁定**（评审 AM7 契约 2）：平台限流类业务码可恢复，
   进持久重试由预算+期限封顶；非 Permanent（4xx 确定性失败才是）；非 UNKNOWN
   （平台已明确回执，仅拒收）。

回执语义三态登记：Delivered（errcode=0，仅证机器人接收）/ Retryable（errcode≠0
或 429/5xx/连接失败——期限内重试）/ OutcomeUnknown（回执形态不可证——不自动重发，
不冒充 SENT）。
