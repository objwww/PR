# 告警 UX-02 值班仿真机器人后端 v1

> 2026-09-11，ev/eval-center 工作区（HEAD 61a9a83 起）。依据：`告警-评测中心与能力版本演进-审查及详细改造方案-v1.md` §六/§七 UX-02 卡、`告警-UX迭代-分类与值班机器人方案-v1.md` §二。范围：**后端**（迁移/意图识别/确定性回复/会话鉴权与边界）；前端 DutyChatView 与 195 部署截图验收不在本轮。

## 〇、归属裁定（UX-02 卡）

仿真机器人后端归 **control-app 认证域**（`/api/v1/duty-bot/**`，沿 /api/v1/** = ROLE_OPERATOR 矩阵）；**不进 duty-adapter**——后者是独立外部探针故障域，当前无 JDBC/security，不为聊天引入对数据库的依赖。本改动对 duty-adapter 零触点。仿真面**零真业务副作用**：只读值班表/incident/notify_outbox 真实投影，不回写 CaseCommand/通知/认领/静默状态（方案 §六"仿真回执无真业务副作用"）。

## 一、意图词表（`BotIntentRecognizer`，规则版本 `ux02-intents-v1`）

纯函数、确定性、首期不接 LLM（UX 迭代方案 §四"明确不做"）。输入先截 512 字符再匹配（复杂度有界）；关键词小写子串 + 三个有界小正则（ISO 日期/中文日期/服务词元/UUID），作用面都在截断后输入上。

| 优先级 | 意图 | 触发词（任一命中） | 参数提取 |
|---|---|---|---|
| 1 | HELP | 帮助 / help / 你会什么 / 能做什么 / 怎么用 / 指令 / 命令清单 | — |
| 2 | DUTY_ONCALL | 值班 / 当班 / 谁值 / oncall / on-call / on call | 日期：今晚/今天/今日=今天；明天/明晚=+1；后天=+2；昨天/昨晚=-1；`yyyy-M-d`；`M月D日`（年=今年，已过去 60 天以上视为明年）；非法日期（2月30日）如实放弃=此刻；无日期词=此刻 |
| 3 | NOTIFY_STATUS | 通知 / 投递 / 送达 / outbox / 发出去 | — |
| 4 | INCIDENT_DETAIL | 告警词 + 消息内含 UUID | incidentId=该 UUID |
| 5 | INCIDENT_QUERY | 告警 / alert / 报警 / 故障 / incident / 什么情况 / 怎么回事 | status：已恢复/已解决/resolved→RESOLVED；全部/所有→不过滤；默认 FIRING。service：`服务[:：=\s]xxx` 显式词元 |
| 6 | UNSUPPORTED | 零命中（裸 UUID 零语境不猜） | — |

优先级理由：值班词最具体（不被"告警"吞掉）；通知词先于告警词（"告警通知发出去没"是投递面问题）；UUID 只在告警语境升级为详情查询。相对日期词的"今天"锚 = 运维时区（`app.duty-bot.ops-zone`，默认 Asia/Shanghai，与 duty_schedule 默认 timezone 对齐）。

## 二、回复契约（`BotReplyComposer`，确定性模板，Git 审查演进）

所有回复只引用真实查询结果；无数据一律如实"查询无结果"，不编造、不补零。assistant 消息落 `chat_message.intent`（意图名）与 `references_json`（`[{type,id}]`，incidentId 等供前端跳转），文本与引用同源同真。

| 意图 | 数据源（真实只读投影） | 回复形态 | 引用 |
|---|---|---|---|
| DUTY_ONCALL | `DutyStore.loadSnapshot()` + `DutyResolver`（真值班表/顶班/通道链） | "2026-09-11 10:00（Asia/Shanghai）当班：alice（轮换）。升级链：…。通知通道：wecom-main(WECOM, P1)。"；无层无通道 → "查询无结果：值班表未配置…"；空解析 → "无当班人…仅剩应急通道：…" | 无 |
| INCIDENT_QUERY | `IncidentQueryReader.listIncidents`（status/service 过滤，Top 5） | "符合条件的告警共 N 条（status=…，service=…），最新 5 条：1. [CRITICAL] HighCpuUsage（order-arena）FIRING · 已持续 1 小时 2 分 · incidentId=…"；空页 → "查询无结果：没有符合条件的告警（过滤口径如实带出）" | incident ×N |
| INCIDENT_DETAIL | `IncidentQueryReader.detail` | 服务/严重度/状态/分类（生效面）/首次发生/持续时长/事件数/RCA run 状态；不存在 → "查询无结果：incident … 不存在（或 id 有误）" | incident ×1 |
| NOTIFY_STATUS | `NotifyStatusReader.summarize`（V9 notify_outbox；control_app 本持 SELECT，零新授权） | "notify_outbox 共 N 行，状态分布：DEAD=1 · PENDING=2 · SENT=38。失败/重试中最新 K 条：…（state/channel/reportId/已试次数/lastError/outboxId）"；total=0 → "查询无结果"；无 DEAD/RETRY_WAIT → "当前无失败或重试中的投递行" | notify_outbox ×K |
| HELP / UNSUPPORTED | 无（静态能力清单） | 能力清单四行；UNSUPPORTED 前缀"暂不支持这个问题。" | 无 |

已知取舍：失败面口径 = DEAD/RETRY_WAIT（PENDING/CLAIMED 是正常在途，不算异常）；DUTY_ONCALL 的 refs 恒空（值班成员非持久实体，无跳转目标）。

## 三、存储（V83）

- `chat_session`：id / title（≤80，默认"值班仿真会话"）/ owner（认证主体，≤64）/ created_at。无改名/删除面（insert-only）。
- `chat_message`：id / **seq identity**（单调插入序=分页游标+幂等重放配对锚，同事务两条 created_at 相同、随机 uuid 不保序）/ session_id FK / role∈{user,assistant} / content（≤2000 库面硬顶；用户消息应用面 ≤400）/ intent（与 assistant 同生同灭 CHECK）/ references_json（可空）/ client_message_id（仅 user 行；`uq(session_id, client_message_id)` 部分唯一幂等锚）/ created_at。
- 授权（V9/V43/V82 同构）：两表 `grant select, insert to control_app`（零 UPDATE/DELETE 开口）；`revoke all from publisher_app, notify_app, eval_app, public`；arena/chaos_admin 存在即 revoke。identity 序列权限随表托管，INSERT 走 DEFAULT 无需序列授权。

## 四、接口契约（/api/v1/duty-bot/**，ROLE_OPERATOR；actor=AuthenticatedActor 截断 64）

| 端点 | 语义 | 应答 |
|---|---|---|
| POST /sessions | body {title?} → 建会话 | 201 {id,title,owner,createdAt} |
| POST /sessions/{id}/messages | body {content, clientMessageId?} → 同步生成回复，两条消息**同事务**落库 | 201 {userMessage, botMessage, replayed:false}；同 clientMessageId 重放 → 200 replayed=true（原双行原样返回，零二次落库）；400 参数/超长（>400）；404 会话不存在或**非本人**（不泄露存在性）；409 会话消息数达上限（200 条，user+assistant 合计）；429 频率超限（30 条/分钟/用户，固定窗口进程内计数） |
| GET /sessions?cursor&limit | 本人会话列表（createdAt desc, id desc 键集游标 `epochMs/id`；limit≤50） | {sessions, nextCursor?} |
| GET /sessions/{id}/messages?cursor&limit | 消息流（seq desc 最新在前，cursor=seq 严格小于续页；limit≤100）；非本人 404 | {messages, nextCursor?} |

频率限制已知取舍：进程内固定窗口计数，多实例不共享、重启清零——演示面够用，真抗刷归网关（如实记录）。会话条数到顶即封会话，新建会话继续（消息 insert-only 无清理面）。

## 七、偏差与未做项

1. **意图面按任务卡收窄**：旧调研稿 §二列有"认领/升级/静默"仿真操作命令，本卡 UX-02 判据与任务定义聚焦三查询意图 + 兜底；"零真业务副作用"红线由不做写命令天然满足。仿真操作命令如需补，应另立 simulation 状态面（方案 §六"作用于 simulation 状态"），不在本迁移。
2. **频率限制为进程内简单计数**（固定窗口 30/min/用户），非分布式——多实例部署需网关或共享计数面，本轮如实标注。
3. **会话无改名/删除**：insert-only 纪律下标题只在创建时定（前端可在首条消息后提示用户另建会话）；如需改名应另开 update 面与新迁移。
4. **未做（卡外）**：前端 DutyChatView（气泡/乐观上屏）、195 部署截图验收、通知查询对 duty_delivery 六态的展开（本轮只读 notify_outbox；值班投递面可查 feed 端点，机器人未接）。
