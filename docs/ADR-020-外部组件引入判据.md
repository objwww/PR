# ADR-020 外部组件引入判据（六项目裁定）

> 状态：**设计输入 · 未冻结** ｜ 2026-08-31
> 来源：外部评审"适配性裁定" + 当日四路官方文档核查（证据 F-4~F-7，见 `docs/OSS-证据清单-v1.md`）
> 编号说明：评审原文建议的 "ADR-018" 与冻结文档已占用编号冲突（ADR-018=publication_resource
> 漂移建模、ADR-019=OSS 证据基线），本裁定顺延为 ADR-020。
> 里程碑纪律：本 ADR 只冻结判据与结论，**不涉及任何实现**；各条目排期见末节。

## 一、元判据（以后任何外部组件评估都过这六道）

1. **组件级采用 ≠ 部署整套平台**——先问"我能不能只借它的语义/协议/职责分离原则"。
2. **自托管资源底线对照机器余量**——官方最低配置是硬数字，不是建议（F-6）。
3. **稳定性状态决定要不要适配层**——目标接口若全部 Development 状态，适配层 + 版本锁是
   使用先决条件，不是可选加固（F-7）。
4. **信任关系与证明义务计入成本**——SaaS 引入的不只是费用，还有数据出境的脱敏证明义务。
5. **命名跟着能力走**——只实现了去重队列就不要叫 Router；没有的能力不进名字。
6. **不为"反过度抽象"而提前抽象**——第二个实现出现前，数据结构 + 测试 runner 就够，
   接口等到有第二个实现再抽。

## 二、六项目裁定（含对评审原文的措辞修正）

| 项目 | 裁定 | 修正后的精确表述 |
|---|---|---|
| OTel GenAI | **组件级采用**（观测语义层） | 不是"安装一个组件"：只采用语义字段命名、SDK 埋点与上下文传播协议；经内部模型适配当前仍在演进的 GenAI 约定。**强化点（核查后比评审更硬）**：GenAI 仓库 46 处 stability 全 Development、尚无 release、schema_url 为 TODO（F-7）——适配层 + 版本锁是使用先决条件。另：GitHub webhook 不携带 `traceparent`，**根 Trace 必须在 webhook 接收处自建**，再传播到 Run/Step/Outbox/Publisher；账本稳定关联仍用业务 ID，Trace ID 只做观测关联，不进账本身份。 |
| Langfuse | **不部署**（强烈同意） | 六组件全部必需（Web/Worker/PG/ClickHouse/Redis/S3），官方最低配置合计约 11C/25.5Gi，Compose 建议 4C/16Gi（F-6）——对照 195 余量约 2G，超出约 13 倍。这是硬约束不是偏好。 |
| promptfoo | **不引入框架** | 真实 Run 评测是本项目必须条件（promptfoo 评的是合成 prompt 响应）；但其断言类型目录（确定性断言/代码断言/模型 rubric 三层）可作为本项目评测断言分类的参考蓝本。 |
| Inspect AI | **不引入框架** | Dataset/Solver/Scorer 职责分离原则采纳；**修正**：不必急着建三个正式接口——先数据结构 + JUnit runner，第二个实现出现时再抽接口，避免为了"反过度抽象"又提前抽象（元判据 6）。 |
| Sentry | **不部署** | **修正措辞**："SaaS 必然泄露 Finding"过于绝对——技术上可以只发送脱敏 fingerprint；真正充分的否决理由是：额外信任关系 + 脱敏正确性的证明义务 + 运维成本，相对本项目自建账本告警的收益不值得。 |
| Alertmanager | **不部署** | **修正命名**：当前该组件应称为 `IncidentProjection`（或 `OperationalIssue`）去重队列，而不是 Alert Router——没有通知通道时，先不实现 silence/inhibition DSL；路由/分组/抑制语义留作能力成熟后的扩展方向。 |
