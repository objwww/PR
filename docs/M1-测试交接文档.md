## 3. 已知局限（不是 bug，不要报 FAIL）

1. stub 不建模权限：权限类断言只认 DP-11 的 DB 授权矩阵实测。
2. stub probe-list 恒空：RECONCILING 命令在 stub 下会重发写操作（真实 GitHub 下可认领
   已建资源）。E2E 注入若命中该路径，重发属预期行为，记录即可。
3. CT-05 skipped 是 M5 占位；`control-app` 里模型调用在 IT 中是 MockModelClient，
   真实模型质量不在本矩阵范围。
4. EX-13 安全告警/draft 预检/ReconcilerDegraded 在无 Run 可挂时落不了 execution_event
   （V1 schema 限制），以结构化 WARN 日志为准取证——这是已移交 G2 裁定的 M1-P9 留档项。
5. stub 固定 remote_id 的连锁伪影（TB-04 已裁定，非产品缺陷）：stub 对所有 PR 返回同一
   check-run/review id，`publication_resource` 的 `(resource_type, remote_id)` 唯一约束 +
   `ON CONFLICT DO NOTHING` 使**只有首个 PR 登记资源行**，后续 CONFIRMED 的 PR 零资源行；
   配合第 2 条 probe-list 恒空，已登记行首轮巡检即被标 MISSING。两者均为 stub 保真度
   局限——真实 GitHub 的 remote_id 全局唯一不冲突；drift 的 MISSING 语义只在真实模式验。
6. DP-01 迁移日志断言为双态（TB-06/INC-29 后）：首启轮含 `Migrating schema`、稳态轮
   （compose down/up 之后）恒为 `up to date`，两者均 PASS；真正的版本门禁是
   flyway_schema_history 最大版本 == 迁移文件最大版本。
