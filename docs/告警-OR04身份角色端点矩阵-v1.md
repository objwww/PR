默认账户/弱口令核查（OR-04 §7 要求）：
- env 引导 operator 密码经 `app.auth.operator.password-bcrypt` 注入，compose 以 `:?`
  强制非空（缺失即启动失败=fail-closed）；代码内默认 bcrypt 值仅 dev/无 compose 场景。
- 平台账号面 active=false 不可登录（V44 约束，登录权限与值班花名册分离）。
- 机器五 bearer 全部 env 注入、无代码内默认值。RR15（缺必填秘密启动运行 profile
  fail-closed）由 compose `:?` 语义承担——待独立验证窗实证（登记于台账 OR-04 行）。

## 3. CSRF 面与豁免

- 豁免（机器线，无 cookie 可伪造）：`/webhooks/**`、`/api/config-bundles/**`、
  `/api/canary/**`、`POST /api/duty/notifications`。
- 保留：operator 写面（浏览器 axios XSRF cookie→头）——含 cases/duty/eval/drills/mcp/
  auth/users 等 POST/PUT/DELETE。
- SSE：GET stream permitAll 但凭一次性短 TTL 票；换票 POST 走正常认证。

## 4. 已知边界与如实登记

- 无独立 REVIEWER/PUBLISHER 角色：评测评审、发布查询（release-assets）均复用
  OPERATOR——单人运维项目的现状口径，非违规；多角色化留给后续需求触发。
- 机器线与用户线同权面（operator-line ≅ 会话 operator）按设计如此；审计上
  auth_event 只记用户线登录/登出，机器线调用审计在各业务表（幂等键/发布审计列）。
- 工具/MCP 调用不出 control-app HTTP 面（Agent 进程内工具口，服务端注册制，
  OR-05 范畴）；本矩阵仅覆盖 HTTP 暴露面。
