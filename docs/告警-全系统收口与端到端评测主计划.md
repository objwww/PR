## 四、终态端到端评测方案（系统建成后的考卷，现在定死）

### 4.1 评测对象矩阵（三维，每维独立版本化）

| 维 | 取值面 | 版本锚点 |
|---|---|---|
| 模型 | glm-5（现役，经 litellm）；deepseek-v3（旧基线参照）；后续候选模型逐一进矩阵 | litellm 配置 digest + UsageLedger 出账 |
| 提示词 | NATIVE prompt 按 ConfigBundle 版本化，每变体独立 digest | ConfigBundle digest |
| Skill | Phase 6 后 Skill 编译成有界 DAG；候选 Skill 只在 EVALUATING 态参评 | Skill 版本域 + 状态机约束 |

一次评测 run = 矩阵中一个确定组合 × 一个数据集版本 × 一个指纹（采样/配置/引擎指纹全记，AM5 已有口径）。

### 4.2 双层评测结构

**第一层：Live E2E（已有，继续用）**
- 载体：`EvalRunnerMain` 一次性容器（跑批→出基线报告摘要→退出），结果 insert-only 落 `eval_run`/`eval_case_result`。
- 数据集：金标 `deploy/alert/eval/eval-scenarios.yml`（registry v1，5 场景 S1~S5 展开 47 Case，串行 slot=1，上轮 resolved 未归并禁入下轮）。
- 产出指标（AM3 §6.4 冻结公式）：symptom_coverage / conditional_accuracy / **end_to_end_hit_rate（北极星）** / unresolved_rate + 症状 TP/FP/FN + 报告 digest。
- 定位：**真实链路连通性与端到端命中的事实来源**，但答案与输入同源，不作晋升依据。

**第二层：离线盲评（Phase 4 新建，晋升唯一依据）**
- 载体：ReplayEvalRunner + ReplayToolGateway（已有雏形）+ BlindScorer（新建）+ 秘密 HOLDOUT（四分区物理隔离，RLS 保证 Agent/RAG 查询结果为 0）。
- 三臂盲评：①参考臂（历史最佳配置）②现役臂（active pointer 指向）③候选臂——评分器不知道哪臂是哪臂，MATCHED 才允许晋升，未过门 active pointer 零变化、零放量（AM5 E2E-AM5-01 口径）。
- 泄漏纪律：按 `scenario_family_id` 整组分区（47 Case 统计上只有 ~5 个独立 cluster，禁止当 47 个独立样本）；生成某 Skill 的事故不得进入该 Skill 的晋级 HOLDOUT；盲评 run 工件 digest 完整且 leakage guard=0 才被接受。

### 4.3 指标与统计纪律

- 主指标：end_to_end_hit_rate（北极星）；辅助：AC@k/Avg@k（不用单一 F1，M5-08）、unresolved_rate、症状 TP/FP/FN。
- 效率指标：端到端延迟、单 Case 模型成本（UsageLedger 三态出账已有）、自一致性（同 Case 多轮结论一致率）。
- 小样本纪律：chance/lift 基线校正 + 整组分区 + "n 不足一律 INCONCLUSIVE 不放行"——禁止把低样本波动改写成通过。

### 4.4 终态评测考卷（"搭建完"验收时首次全量执行）

1. **基线层**：金标 47 Case 全量 Live E2E（现役模型×现役提示词），确认链路连通与命中水位。
2. **矩阵层**：模型×提示词候选组合各跑盲评（HOLDOUT），三臂对比出结论。
3. **Skill 层**：首批候选 Skill 走 VALIDATING→EVALUATING，引用 SEALED 数据集盲评 run。
4. **回归层**：RCA-100 v1.1 外部一致性门 + RCAEval RE2/RE3 辅助回归（M5 三层数据集口径，辅助门不单独决定上线）。
5. **门禁层**：D1~D8 逐项核销 + 迁移后 E2E 验证矩阵（Phase 11 §5.1）+ 前端核心链路真连抽查。
6. 全部产出归档评测报告（digest 锚定），G2 呈签材料必须含本考卷结果——缺质量面的 G2 按已立法硬门直接打回。

## 五、评测阶段现在启动：Native 确定性基线重测（第一动作，v1.2 口径纠正）

**为什么现在跑**：0/47 是 Holmes/deepseek-v3 时代旧账；当前生产链是 NATIVE 确定性流水线（**主链零 LLM**，审计 F01）。重测目的=确立**当前管线的参照原点**+验证评测链路本身健康（注入→firing→评分→落库→出账）。

**口径纠正（评审 P1-08，v1.2 落锤）**：本批次按实际执行引擎标注为 **Native 确定性基线**，**不得标注为"glm-5 基线"**——litellm 配置指向 glm-5、单独 chat 成功、容器运行正常，都不能证明 RCA 运行调用了模型。只有 run→task→attempt→模型请求/供应商回执关联完整，才能标注"真实模型臂"（该标注在里程碑 A 之后才可能出现）；连接探针（litellm chat 往返）单独归类为链路探针证据。运行水位观测（容器 Up/内存正常/快照轮数）只支持运行状态，不推出 RCA 质量或 LLM 在环。

**前置检查（执行前逐项确认）**：
1. rsync 主传输完成（磁盘 IO 避让；传输期间不跑）。
2. 195 available ≥ 3GiB（memory-gate 现水位 3.49GiB，one-shot 容器限额内）。
3. eval one-shot 容器配置记录在案（模型元数据字段按在场模型如实填写，但证据与报告一律标 NATIVE 引擎）。

**执行步骤**：
1. **Smoke**：S3 单场景 1 轮（靶场 Gauge 面 firing 快，max_firing_wait=300s），验证 注入→firing→RCA→评分→落库 全链；检查 UsageLedger 出账。
2. **全量**：5 场景 × 2 轮 = 47 Case 串行（slot=1）。S1/S2 双窗烧损收敛慢（max_firing_wait=1500s/轮），全量墙钟粗估 **3~5 小时**。
3. **归档**：eval_run/eval_case_result 落库 + 基线报告 digest + 证据目录 `docs/测试证据/eval/native-baseline-<ts>/`；PROGRESS 记时间线。
4. **产出裁定**：Native 基线命中率 = 后续一切阶段"收敛贡献"的参照原点；若命中率为 0 或近 0，直接坐实 R5（真实工具）+R7（LLM loop）为最高优先——这正是预期的诊断价值。

**成本提醒**：NATIVE 链零模型调用，token 成本≈0；全量成本大头是 S1/S2 烧损物理等待。UsageLedger 出账照常留痕。

## 六、质量门怎么卡（已立法 + 本计划挂接）

1. **G2 质量指标硬门**（milestone-workflow 已改）：每阶段 G2 材料必含 ①北极星指标现值 ②LLM 在环状态变化 ③本阶段收敛贡献；缺节直接打回。
2. **任务树红线**：任何阶段任务树必须能答出与北极星指标的关系；连续两阶段零关联 → 主会话主动叫停提交排期修正（§二表格已逐包标注，即是执行此红线）。
3. **评测口径冻结**：R3（Phase 0）把 SLO/验收口径/指标公式冻结成文档+配置，之后改口径 = 走变更评审，不许执行中漂移。
4. **晋升唯一通道**：模型/提示词/Skill 的任何晋升只认 §4.2 第二层盲评 MATCHED；Live E2E 分数再好看也不构成晋升依据。

### 8.4 R7 重定义：真 LLM 多 Agent RCA 设计契约（用户裁定落码）

**三角色**（可共用同一模型，不同上下文/工具权限/输出协议）：

| 角色 | 职责 | 输出 | 权限 |
|---|---|---|---|
| 指标调查 Agent | 分析异常时间/错误率/延迟，选择后续指标查询 | 异常观察、候选原因、证据引用 | 指标只读工具 |
| 日志与变更调查 Agent | 按指标 Agent 圈定的范围查错误与变更，找支持/反证 | 错误特征、变更关联、反证 | 对应只读工具 |
| RCA 诊断 Agent | 综合两侧结果，判断证据缺口 | 根因假设、补证请求、最终结论 | 默认无执行权，补证向 Supervisor 提议 |

**统一 ActionGuard 固定顺序**（所有模型与工具动作必经）：Run 活跃 → 取消检查 → generation 匹配 → owner/leaseEpoch 有效 → deadline → 工具与参数获准 → 原子预留预算 → 记录调用 → 执行 → 有界读取保存 → 结果准入校验 → 结算预算与任务状态。要点：**执行前查一次、结果写入时再查一次**；预算属整个 Run（工具次数/模型次数/token/费用/总时间），子预算不超父预算，重试不重置；**账本不可写 = 零触网**；UNKNOWN 保守占用待对账。以上全部由代码强制，不写进 prompt 凑数。

**模型只输出 ActionProposal 或 Findings**：ActionProposal 限已注册工具与参数，禁止自由 SQL/任意 URL/shell。

**RCA 模型上下文字段**：runId/taskId/attemptId/agentId/agentVersion/leaseEpoch/inputSnapshotDigest/runDeadline/taskDeadline/budgetReservationId；账本关联 RCA 真实实体，记录请求摘要/prompt 版本/模型路由/开始/成功/失败/UNKNOWN/实际 token 用量/费用/供应商请求 ID。第一期单模型路由，主备切换在账本正确后再接。

**身份三分**：configDigest（配置版本）/ inputSnapshotDigest（调查输入）/ evidenceSnapshotDigest（实际证据集）；创建 Run 时冻结服务范围+告警时间窗+配置，排队/重试不得静默移动窗口。

**Claim 四类型**：SYMPTOM（已观察异常）/ HYPOTHESIS（待验证原因）/ ROOT_CAUSE（满足核验条件：因果机制解释+必要现场证据）/ EXCLUSION（已排除方向）。指标+日志交叉确认同一错误 = 症状确认，不等于根因；缺证据允许 UNKNOWN，不得为完成率强行确认。模型提解释，程序查引用/时间窗/来源/类型/必要证据条件。

**任务所有权裁定**：一个 Run driver 持执行权，内部有界并行调查任务，每任务持久 checkpoint；driver 租约定时续期、失租停新动作；上游完成立即推进依赖；required/optional 失败分别处理；重启读 checkpoint 不重新猜进度；汇总等本轮收敛再冻结证据。子任务独立租约的跨 worker 升级留待确有需要时。**并行前必须通过两 worker 竞争测试**。

**验收红线**：必须看到真实模型请求、真实工具返回、模型观察确实改变下一步动作；禁止预置 Claim 后检查报告能否生成。
