# 告警前端逐页体验改造与后期优化方案

日期：2026-09-10。依据：当前 alert-web 的13个路由页面、AppShell、tokens、评测子组件和官方设计资料。本次是源码布局评审与方案，不是生产浏览器截图验收，没有修改前端实现。包含追加需求：提示词运行期间热更新。

## 一、为什么现在看起来挤

当前界面把线框图里的说明、实现细节、状态字段和操作一起搬进了产品。多数元素同样小、同样带边框、同样醒目，没有形成“先看问题，再看证据，最后展开技术细节”的顺序。

可定位的原因：

| 文件 | 代码事实 | 影响 |
|---|---|---|
| src/styles/tokens.css | .btn 12px，padding 3px 12px；tag 11px | 操作目标偏小，标签比内容更抢眼 |
| src/layouts/AppShell.vue | 侧栏172px，内容padding14px；深色侧栏加深色顶栏 | 页面框架拥挤，正文缺少清晰标题和留白 |
| OverviewView.vue | 五卡flex并排、11px跳转说明、黄色设计说明常驻 | 每张卡都塞长句，第一屏像说明书 |
| AlertsView.vue | 六列统计卡、8px区块间距、11.5px表格、常驻facet | 过滤器与表格争宽度，列表被多个顶部区域挤下去 |
| RunDetailView.vue | 摘要里同时放进度、三种预算和三个操作；DAG下常驻11态图例 | 看调查结果之前先被运行细节包围 |
| DutyView.vue | 当班、测试发送、成员、通道、排班编辑全部展开 | 浏览任务与编辑任务混在一起 |
| EvalView.vue | 九个平级页签；再嵌子组件及子页签 | 信息架构复杂，使用者难知道下一步 |
| NotificationsView.vue | 多枚badge、标题、时间、操作在同一flex行换行 | 长标题时行结构不稳定 |

AppShell 中“生产环境”“operator”“SSE已连接”还是模板常量；总览仍有 holmes 对照标记。它们需要按真实能力显示，不能只美化成漂亮的假状态。上述是前端源码事实，不据此断言当前远端部署版本相同。

## 二、设计方向与公共规则

建议采用清爽的浅色操作台：中性色背景、白色主工作区、一个蓝色主操作色；红橙只用于需要关注的异常。减少渐变、卡片套卡片、长条黄色说明和装饰性emoji。不用通过全屏大数字或动画来体现Agent能力。

建议尺寸是本项目设计起点，并非外部标准强制值：页面标题24px、区块标题16px、正文14px、辅助信息12px；页面边距24～32px，区块间距24px，卡片内边距20～24px；输入/按钮通常36～40px高。表格默认48～56px行高，另提供紧凑密度，长文本允许增高而非强制裁断。

侧栏建议208～224px，按“工作台：总览/告警/调查/处置；运营：值班/通知；质量：评测；系统：监控”分组。群模拟放入演练工具二级入口，演练标记始终保留。后期资产管理归入质量分组，不再把每项能力都塞一级导航。

统一 PageHeader、Toolbar、DataTable、StatusBadge、EmptyState 和 DetailDrawer 的样式与交互；只抽多页确实重复的公共件。保留Vue3和Vue Flow，不为美化重写框架。

每页一个主要任务、一个主要操作。少量高频筛选直接显示，其他收进筛选面板；批量操作只在选中后出现。长表格占据主要宽度，详情过长就独立路由。Carbon官方也建议给表格充分空间、通过展开/侧面板逐步呈现细节。[Carbon表格设计](https://carbondesignsystem.com/components/data-table/usage/)

## 三、13个页面分别怎么改

### 1. 总览 /overview

目标：值班人员十秒内知道现在要处理什么。

页头只放“工作总览”、当前值班人与数据时间；第一行保留三个行动指标：待处理、调查异常、通知失败。评测回归移到质量区入口，READY内部状态改成“最长等待”。

主区约2/3宽展示按风险排序的待办列表，右区约1/3放交接摘要和简洁健康状态。数字下最多一行解释，移除“点击带筛选参数跳P3”等文案。点击整个卡片与键盘操作保持一致，并有清晰链接语义。

### 2. 告警 /alerts

目标：筛选并找到应该调查或处理的事故。

合并统计卡与状态切换为简洁状态计数行；一条搜索工具栏，常用状态/服务/时间筛选紧邻。DSL改成高级搜索模式，普通使用不要求输入表达式。左facet默认可收起，窄屏使用抽屉，不把整个筛选栏堆到表格上面。

默认列只放严重度、告警/服务、状态、持续时间、负责人、调查状态、操作；ID与复杂labels在展开区。过滤结果写URL，返回列表保持筛选与滚动。无数据、筛选无结果、加载失败分开显示。

### 3. 告警详情 /alerts/:incidentId

目标：回答发生了什么、影响哪里、原因是否确认、谁在处理。

页头使用告警名与服务，严重度和状态分开；主操作根据权限与状态显示。八页签收敛为“概览、调查、证据、时间线”，报告并入概览/调查，源数据进高级详情。

概览上方显示影响与当前结论，明确“待确认原因”；下方展示证据摘要、处置进度。11步横向过程不要默认全部展开，改成关键阶段摘要，深入调查时再显示任务细节。

### 4. 调查队列 /runs

目标：找到失败、等待、需要干预的调查。

导航“审查台”统一为“调查”，与页面名称一致。保留进行中/待干预/已结束分组；表格默认显示所属告警、当前阶段、耗时、预算风险、状态。完整runId、config digest和worker不占首屏列。异常只在受影响行或上方简短摘要中出现。

### 5. 调查详情 /runs/:runId

这是最值得先精修的展示页。默认显示“调查摘要”，而非一打开就面对DAG和11态说明。

顶部：告警名、调查状态、耗时、已用费用；次行：当前结论与待补证。主要内容分“摘要、执行过程、证据、运行详情”。执行过程保留Vue Flow，画布占主要空间；选节点才开约360～420px详情面板，小屏切独立详情。完整图例收进帮助。

多Agent展示角色、当前动作、依赖、补证轮次和可审计结果，区分串行与并发；不伪造正在思考的文本。预算分项与lease放运行详情。取消放次级危险操作，提示写成“补充线索”，UNTRUSTED语义由简短帮助解释。

### 6. 处置 /cases

采用稳定主从布局：左侧约320～360px待办，右侧剩余空间显示选中处置；在窄屏先列表后详情。当前按比例均分会让两边都不够用。

列表仅展示主题、优先级、负责人和期限；右侧先显示下一步操作与处置记录，再展开调查证据。认领/转派/解决分清主次，冲突在相应操作附近解释，不整页堆警告。移除“OperatorCase”等数据库术语。

### 7. 历史 /history

作为告警的历史视图或独立归档路由，但共享搜索工具栏。移除“随机打开一条”主按钮，它适合演练而非用户日常检索。

先给全宽结果列表，点击进入快照详情；归档摘要里呈现服务、发生时间、原因状态和报告，不首屏暴露manifest字段。归档不可用继续保留明确异常，不能当成空列表。

### 8. 值班 /duty

这是第二个最需要拆分的页面。默认只展示“当前值班+未来七天排班”，可用简单周视图，不必先做复杂拖拽日历。

二级导航分“排班、成员、通知通道”；新增成员、编辑通道、临时替班均用独立表单抽屉，不能同时展开全部表单。测试通知放通道详情中。快照过期只在当班区域显示。首次没有排班时提供受权限控制的创建流程，页面不应要求用户直接插数据库。

### 9. 通知 /notifications

采用收件箱布局：每条上行标题和时间，下行服务/来源/投递摘要；未读用圆点或字重表达，避免再叠一枚UNREAD标签。点击后展示正文、通道尝试和关联事故。

未读、业务告警是否恢复、消息是否送达是三个维度，不能统一染绿。保留“已读不等于接单”的简短帮助，但不常驻一整段后端去重说明。

### 10. 群模拟 /duty/chat

保留模拟标识，改名“通知预览”，放演练工具中。消息区控制阅读宽度，旁边可切“消息预览/投递记录”，不把所有账本状态塞进消息气泡。滚动到旧消息时新消息不强制拉底。

此页证明模板可读，不证明真实企微/钉钉送达；前端文案必须维持这个区分。

### 11. 评测 /eval

九个一级tab拆成有路由的“实验、数据集、评审”，发布转到版本中心。实验详情再包含概览、案例、比较、成本，评分器校准归评审。发起评测变成明显主按钮。

逐子页面处理：数据集用版本表+详情；发起评测用分步表单；批次改为可筛选实验表；分析默认四项结论再下钻；案例使用列表+证据详情；评分器显示分歧样本；人工复核单条聚焦；比较并排固定基线/候选，突出退化项；发布门显示未满足的具体条件。

页签与选中实验进URL，刷新不丢上下文。费用对账与质量结论分开。移除“从跑一次看三个数扩为……”等开发说明。

### 12. 监控 /monitor

先显示系统可用性和最需要处理的异常，再分“主机、执行器、模型/工具、通知”四区。小趋势图必须有时间窗、单位和新鲜度，不能仅显示累计数字。

195、外部探针、评测机按实际部署展示；未采集显示未知，过期显示陈旧。资源饱和、积压、错误率关联相应调查，不复制一个大而全Grafana。Grafana官方建议围绕使用目的组织仪表盘，并控制无序增长，适合这里的摘要到下钻结构。[Grafana仪表盘实践](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/)

### 13. 登录 /login

保留单列简单登录，卡片建议380～420px、标题24px、输入40px；移除FUT-34、机器Bearer、auth_event等内部说明。显示实际登录错误、账号支持方式和明确环境，不承诺未经后端确认的8h会话行为。

## 四、新增版本中心：同时解决提示词热更新

建议后期新增一个版本中心，内部管理Prompt、Skill和发布组合，不新增三个一级导航。

版本列表显示名称、现役版本、候选状态、最近评测、更新时间。版本详情分“内容、差异、评测、发布记录”；编辑区与预览区只在编辑模式并排，运行模式优先显示资格和影响范围。

### 4.1 服务运行期间热更新：推荐默认模式

可以，无需重启服务。流程：编辑生成不可变候选 → 校验/评测 → 发布事务CAS切换active指针 → 新Run读到新组合，旧Run继续固定原组合。复用ConfigBundle，不依赖Redis或文件监听。

若要求“发布完成后创建的Run立即使用新版本”，新Run准入时从PG主库读取当前指针并固定，缓存只按digest缓存内容。不要依赖各实例每30秒轮询却在界面承诺立即生效。并发创建与发布以数据库事务的读取/锁定规则定义先后，测试边界竞争。

发布面显示：候选版本、与现役差异、评测资格、影响的新Run范围、旧Run数量、回滚目标。服务热更新不等于每一轮都读取latest。

### 4.2 已运行调查中途换Prompt：可做，但需要显式切换点

首期建议仅在一个完整调查轮次结束、没有该Run在飞模型/工具调用时切换；不能替换已经发往供应商的请求，也不能把回来的旧结果标成新版。

控制命令携runId、expected_revision、目标release_digest、原因，落持久事件；driver到安全边界领取并校验权限、资格、schema和上下文兼容性，写入新的config_epoch。后续动作固定新epoch；原有证据保留来源，剩余预算和deadline不重置。

多个Agent同时在飞时应等待全Run安全点。等待超时明确失败或保持待切换，不能在一半角色已换、一半未换时宣称完成。可取消待切换命令；driver崩溃后恢复命令状态，防止丢失或重复切换。

首期只允许兼容的Prompt调整；Skill DAG结构、工具权限、模型协议变更则创建关联的新调查，不在原DAG中强换。切换后报告显示曾用版本和生效轮次，该Run标记MIXED_CONFIG，不作为单版本质量实验。

### 4.3 前端发布操作必须把范围讲清楚

默认按钮：“发布到新调查”。高级操作：“在安全点更新此调查”，先显示兼容性检查、等待中/已应用/已拒绝状态。回滚默认也只影响未来Run，进行中调查如需回退走同一安全点流程。

新增验收：发布与新Run创建竞争、缓存过期、数据库不可用、两操作者争同revision、切换时取消、driver重启、旧epoch结果晚到、预算不重置、回滚依赖缺失。

## 五、后期优化按实际收益排序

| 阶段 | 内容 | 进入条件与收益证据 |
|---|---|---|
| 近期体验修整 | 全局字号间距、删除开发说明、真实状态、总览/告警/调查详情重排 | 不等待RAG；用实际长数据与多尺寸截图验证 |
| 核心页面收口 | 值班拆页、评测路由化、列表/详情与错误状态统一 | 核心API稳定；完成查告警→读证据→处置的任务走查 |
| 版本运营 | Prompt组合热更新、评测对比、发布回滚 | 版本资格与CAS后端到位；可追溯一次真实发布 |
| 方法积累 | Skill候选与反例、RAG轻量目录 | 有真实复核轨迹；证明开关对照收益，不以文件数量验收 |
| 扩展接入 | 确有需要的MCP、更多只读证据源 | 原生接口缺口明确；权限/版本/成本受统一守卫 |
| 可靠性与效率 | 查询缓存、并发调度、日志保留、容量与恢复优化 | 以延迟、积压、资源水位、RPO/RTO实测触发 |

补充性能纪律：先分页、按需取详情、隐藏页面停止轮询、请求取消及防旧响应覆盖，再根据实际长列表决定虚拟滚动。SSE新事件不要打断选择和滚动；只追加提示并提供“查看新事件”。不要为了后期扩展一次性引入全部基础设施。

## 六、视觉与交互验收

先精修三张代表页：告警列表、调查详情、值班排班；统一语言后再迁其他页面。只先调tokens会改变密度，但不会解决九页签和表单混排。

建议以1366×768、1440×900、1920×1080及窄屏测试；正文200%缩放保持可用，宽表格/图可在自身区域滚动，避免整个页面横向拖动。WCAG2.2的目标尺寸条款通常要求24×24 CSS像素或满足规定例外/间距；本项目主要按钮建议36～40px是更舒适的设计选择，不将它误称标准强制值。[W3C目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)

每页覆盖：加载、空数据、错误、无权限、陈旧数据、超长标题、完整UUID、中文长日志。检验键盘焦点、语义按钮/页签、抽屉关闭后焦点恢复。告警颜色必须配文字，不能只靠红绿。

最终验收提交每页同尺寸前后截图及三条任务走查：找到最紧急告警；定位结论支持/反证；完成认领或查看通知失败原因。构建成功不等于界面好用。本轮尚未进行渲染截图实测，因此尺寸建议需要原型与实际页面验证后定稿。
