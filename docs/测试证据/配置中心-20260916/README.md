| 参照物 | 实践要点 | 本页对齐 |
| --- | --- | --- |
| 得物 Troubleshooter 告警类型配置 | 分类/排查开关/推送开关集中配置 | 「告警分类」页签：九类实时分布 + 规则/人工来源拆分 + 未分类覆盖率（人工修正入口在告警详情逐事件） |

## 三、SQL 对账（2026-09-16 真机）

```sql
select coalesce(category,'UNCLASSIFIED') as cat, count(*)
  from incident group by 1 order by count(*) desc;   -- UNCLASSIFIED=8, APPLICATION=7, INFRA=1
select count(*) from incident;                        -- 16 = 面板"事件总数"
```

## 四、验收（方案 §6 逐项）

1. 零错误数据：分类分布与 SQL 一致；接入姿态与部署环境变量装配同源 ✔
2. 零裸枚举：分类与来源经 `zh.js`（CATEGORY_ZH/CATEGORY_SOURCE）中文化；机器线角色为标识符展示（属身份常量，状态文案全中文）✔
3. 零可点必失败：启停/测试发送复用既有已验证端点；未装配面显示空态口径 ✔
4. 空态即引导：无事件时说明"事件接入后自动出数"；未配置 HMAC 时写明 bearer-only 姿态 ✔
5. 无新增迁移（读面 + 既有读写面聚合）✔；权限沿 `/api/v1/**` 与 `/api/duty/**` 既有矩阵 ✔

## 五、遗留

- 告警"排查开关/推送开关"（得物式按类型控制）当前实现为事件级 override 与白名单路由放量，暂无按告警类型的全局开关表——如需业界同款粒度，待产品裁定后加 `incident_category_policy` 表（本批不造无源配置）。
- 渠道"测试发送"为全局测试通知（值班域既有语义），非单通道定向发送——单通道定向需 notify-app 支持，列入通知域增强。
