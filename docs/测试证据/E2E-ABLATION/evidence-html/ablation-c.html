消融C：资源互斥锁 有锁无锁

对象：ResourceCoordinator / resource_mutation_lock（同资源写互斥：BUSY 显式拒绝、不排队不覆盖；锁释放绑定 Operation 终态）。
对照组设计：同一意图（chaos.resolve → res://demo/checkout/ablation-c，Guardian 自动批 grant 均已就绪），唯一差异 = 该资源上是否存在另一操作的 HELD 锁行。

① 有锁：HELD 锁占住资源 → plan 整体拒绝

lock=res://demo/checkout/ablation-c|state=HELD|epoch=7   ← 占锁方 op（UNKNOWN 持有中）
plan_with_lock={"status":"REJECTED","reason":"LOCK_BUSY"}

BUSY 是显式结果：宁可串行不可并发 mutation；planner 整体回滚（意图/授权/锁/出箱五步全不出半步）。

② 无锁：删掉锁行后同一 plan → 直通执行到完成

lock_rows_after_delete=0
plan_without_lock={"status":"PLANNED","operation_id":"1af7d612-4b41-4a8d-a2fe-baf149b9c350",
  "resource_epoch":1}
op_final=COMPLETED|dry_run=true
locks_left=0                              ← 终态自动放锁
plan_without_lock 后 outbox→dispatch→VERIFIED→COMPLETED 全链 14s 内走完

没有锁的世界里同一副作用畅行无阻——对照证明锁是并发 mutation 的唯一串行化点。

③ 结论

状态plan 结果副作用
有 HELD 锁REJECTED / LOCK_BUSY零（整体回滚）
无锁PLANNED完整执行（COMPLETED）

组件差异：锁把"同资源并发写"从竞态变成结构不可能；其代价（BUSY 拒绝）由 Reconciler/人工裁决面有序收口。
