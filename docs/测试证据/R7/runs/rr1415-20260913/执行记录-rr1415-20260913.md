## 三、执行环境连环修（全部留档于 probes/ 与 scripts/）

1. **down -v 插值依赖雷**：清场 `compose down --env-file` 读到残破旧 env → 插值失败 → 卷没删 → 旧密码卷 vs 新铸 secrets → flyway "password authentication failed" 死循环。修=资源级硬清场（docker rm/volume rm/network rm，不依赖 .env）。
2. **compose 网冠前缀 DNS 断链**：phase0 挂外联容器到裸网 `rriso-net`，但 compose 自建网实名 `rriso_rriso-net` → control-app 与 litellm 不同网。修=compose 声明 `external: true + name: rriso-net` 定名共网。
3. **18080 端口被占**：共享 195 他方 otel-demo 容器绑 127.0.0.1:18080（应答 "Otel Demo" 404）→ control-app "port is already allocated" 卡 Created。修=iso 换 18091（对方容器零触碰）。
4. **孤儿 compose 客户端持 flock**：pkill 杀 runner 名不杀其子 docker compose CLI（继承 fd 9）→ 下轮启动被 flock 误拒。定性=瞬时残留，重发即过；restart2 的 pkill 面应含 compose 客户端模式（登记待改）。
5. **姿态漂移**：standing deploy/.env 被多执行方活跃编辑（AGENT_MODEL 已变）→ 不可作派生基座。修=冻结姿态模板 rr-iso.posture（首铸=运行中容器快照+固定字面量，与 .env 解耦）。
6. **测试脚本三雷（BA-143）**：审计 SQL `status`→真列 `state`（V48:41，BA-134 同族）；RR15-B 固定 sleep 25s 采样竞态（1CPU 栈 Spring 到校验点可 >30s）→ 双门观察窗（拒启动行/health 200 二择一，180s）；"新键有效"断言把模型可靠性（全数成功）混入凭据面 → 改 succ≥1 且 authden=0。
7. **qwen3-max-preview 配额耗尽**（共享环境现实）：三轮定性后换 deepseek-v4-flash-0731（唯一有配额），键面 models 白名单同步换模。
