## 三、SQL 对账（2026-09-16 真机）

```sql
select count(distinct scenario_name) from drill_job;                    -- 1  = 已演练场景
select count(*) from (select scenario_name, target_env
 from drill_job group by 1,2) t;                                        -- 1  = 已演练组合（覆盖率 1/5=20%）
select count(*) from drill_job where state='RECOVERY_FAILED';           -- 1  = 恢复异常卡
```

## 四、验收（方案 §6 逐项）

1. 零错误数据：矩阵/四段/摘要全部与 drill_job、模板注册表 SQL 对账一致 ✔
2. 零裸枚举：演练状态经 `DrillsView` 内 `DRILL_STATE_ZH` 中文化（排队中/预检中/注入中/观测中/恢复中/恢复核验中/已闭环/恢复失败）✔
3. 零可点必失败：洞察读面缺席时区块整体隐藏（`v-if="matrix"`/`fourPhase.length`），不影响既有列表 ✔
4. 空态即引导：未演练组合显式标"未演练"——正是韧性缺口的呈现方式 ✔
5. 无新增迁移（纯读面聚合既有表）✔；权限沿 `/api/v1/**` OPERATOR 矩阵 ✔

## 五、诚实边界（不造假声明）

- **韧性得分口径**：当前覆盖矩阵维度 = 场景×靶场（与 drill_job 真列一致）；方案原文的"服务×故障模式"粒度需要靶场服务清单来源（CMDB/服务目录），待 3.13 服务目录出数后升级维度，本批不虚构服务维度。
- **四段中的感知/定界**：当前唯一演练 RECOVERY_FAILED 且未关联 incident/run——两格如实标"未关联"，待演练全链（注入→告警→调查→恢复）跑通后自然点亮。
