### 首轮 8 类根因与修复（生产 3 + 测试 5）

生产（UT 内存件测不出 PG 约束语义，IT 首跑即炸）：

1. **PostgresClaimStore**：`sources`/`refs` 参数 varchar 直插 V17 jsonb 列（42804）→ SQL 内 `cast(:x as jsonb)`（insertRow/revise 两处）。
2. **PostgresRunBudgetLedger.settleFrom**：无条件 `settled_at = now()`，违反 V13 ck 的 PROVISIONAL 悬挂态要求（settled_at 必空）→ 按目标态条件化赋值。
3. **PostgresIncidentBudgetLedger.sumWindow**：`:window` 参数一名两用（window_kind 等值要 `'24H'`，interval 字面量要 `'24 hours'`）→ 等值恒不匹配、SUM 恒 0、**限额永远放行** → 拆 `:kind`/`:span`。

测试：

4. **V12StateExpansion**：seedAlertChain 的 QUEUED run 占住 `uq_rca_run_active_incident` → seed run 先置 SUCCEEDED 释放谓词。
5. **V18TaskEdgeRunScope**：同 incident 双活跃 run 撞同一谓词，且约束在 **INSERT 瞬间**校验（出生后 UPDATE 为时已晚）→ 伴生 run 以 SUPERSEDED 终态出生（边域断言与 run 状态无关）。
6. **GenerationFence.staleFinish**：fresh run 未插任务（claimNext 空）+ taskId 无租约（先撞 LEASE_REJECTED）→ 先 claim 旧任务拿真实租约，再 supersede，再 fresh+补插任务。
7. **Am4E2E08.itE08_2**：change 录制键与 tool 扰动行完全同键（HIT 非 MISS）→ change 键 args 错开（until=270）；toolVersion='2' 走 registry 白名单 UNKNOWN_TOOL（分型单独断言）。
8. **DagPromotion 并发**：首轮判"环境毛刺"放宽 10s→30s 仍挂满 → **实为生产死循环**（见三轮）。

### 二轮 7 类

1. **DagExecutionService.transition（生产，最重）**：CAS 失败分支原样 return，本地 states 残留 BLOCKED，不动点迭代永远重评同一任务 → **并发回执必现死循环**。修：CAS 败者同步本地视图为终态（非 BLOCKED 即不再重评）。
2. **PostgresRunBudgetLedger.findStaleReservations（生产）**：pgjdbc 不识别 `Instant`（`setObject` 直接抛）→ 显式 `Timestamp.from`。
3. **itL01**：`JdbcClient.single()` 拒 NULL 列值（TypeMismatchDataAccessException；`query(Object.class)` 分支缺 wasNull 检测首轮表现为 `Object@...`）→ 行映射 list 断言 `containsExactly((String) null)`。
4. **itC1**：verdict helper 单源 `["metrics-agent"]` 与断言双源矛盾（首轮被 jsonb 错误掩盖）→ helper 补齐。
5. itE08_2 UNKNOWN_TOOL 分型（同首轮 7）。

### 三轮 3 类

1. **PostgresRunBudgetLedger.probe（生产）**：`single()` 对无限额行（未 ensureLimit 的 run）抛 EmptyResult——**reserve 拒绝路径自己炸**。修：optional 化，无行按零消费 fail-closed 给 rejected(0,0)；itB09 补 TOKEN 限额行（独立性对照面前提）。
2. staleFinish 顺序（同首轮 6，先领后取代）。
3. **V18 "to 任务不存在"**：由 V8 简单 FK（`rca_task_edge_to_task_id_fkey`）先拒，到不了 V18 组合 FK——195 psql 实证后期望约束名归位；V18 组合 FK 的专属触发面 = 任务存在但挂别的 run。
