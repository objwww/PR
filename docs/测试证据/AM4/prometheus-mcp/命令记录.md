## 2. 启动（带内存限额 + 只读白名单）

关键参数语义（`docker run --rm <image> --help` 实测，全文 `raw/p6_help.txt`）：

- `--mcp.tools`：默认 `all`；`core` = 9 个纯查询工具（docs_list/docs_read/docs_search/query/range_query/metric_metadata/label_names/label_values/series）；**其余取值按"在 core 之外追加"的允许列表解释；quit/reload/config/alertmanagers 等不在 core 内，不写即不加载**；
- `--dangerous.enable-tsdb-admin-tools`：`delete_series`/`snapshot`/`clean_tombstones` 需显式开启，本次未开；
- `--mcp.transport`：`stdio`（默认）或 `http`；http 模式监听 `--web.listen-address`（默认 :8080）。

```bash
# 踩坑记录①：--mcp.tools 传逗号串不展开——整串被当作一个工具名，
# 日志 WARN "Failed to find tool to register tool_name=core,alertmanagers,…"，实际只加载 core 9 个。
#   → 必须逐个重复旗标。
# 踩坑记录②：--docs.auto-update=false 触发 kingpin 报错 "error: unexpected false" 拒启动 → 去掉该旗标。

$ docker rm -f p6-prom-mcp
$ docker run -d --name p6-prom-mcp \
    --network alert-net \
    --memory 256m --memory-swap 256m --cpus 1 \
    --read-only --security-opt no-new-privileges \
    -p 127.0.0.1:18090:8080 \
    ghcr.io/tjhop/prometheus-mcp-server:latest \
    --mcp.transport=http \
    --web.listen-address=:8080 \
    --mcp.tools=core \
    --mcp.tools=alertmanagers  --mcp.tools=build_info  --mcp.tools=exemplar_query \
    --mcp.tools=flags          --mcp.tools=healthy     --mcp.tools=list_alerts \
    --mcp.tools=list_rules     --mcp.tools=list_targets --mcp.tools=ready \
    --mcp.tools=runtime_info   --mcp.tools=targets_metadata --mcp.tools=tsdb_stats \
    --mcp.tools=wal_replay_status \
    --prometheus.url=http://prometheus:9090 \
    --prometheus.timeout=10s \
    --log.level=info
```

## 3. MCP 协议验证（Streamable HTTP）

请求端点 `POST http://127.0.0.1:18090/mcp`，Accept 头须带 `application/json, text/event-stream`，响应为 SSE 帧（`event: message` + `data: {jsonrpc…}`）；初始化后所有请求须带响应头返回的 `Mcp-Session-Id`。

```bash
# ① initialize → 响应头 Mcp-Session-Id: ZS6VNSDERGNYDHS2AYCQUSCSWF（每次会话不同）
$ curl -s -D - -X POST http://127.0.0.1:18090/mcp \
    -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
    -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"p6-probe","version":"0.1"}}}'
# → HTTP 200，SSE：capabilities{logging,resources,tools} + instructions(SRE persona)

# ② notifications/initialized → HTTP 202

# ③ tools/list → 22 个工具，白名单外的 mutating 工具 0 出现（raw/p6_tools_list.txt、raw/p6_tool_names.txt）
$ grep -o '"name":"[a-z_]*"' p6_tools_list.txt | sort
alertmanagers build_info docs_list docs_read docs_search exemplar_query flags healthy
label_names label_values list_alerts list_rules list_targets metric_metadata query
range_query ready runtime_info series targets_metadata tsdb_stats wal_replay_status
$ grep -oE '"name":"(quit|reload|delete_series|snapshot|clean_tombstones)"' p6_tools_list.txt | wc -l
0

# ④ tools/call（id=10..31，原始响应见 raw/p6_q_*.txt，解码样本见 查询样本.md）
```

## 4. RSS 实测

| 时点 | docker stats | cgroup v1 memory.stat rss | 备注 |
|---|---|---|---|
| 启动后空载（up ~6s） | 67.87 MiB / 256MiB（26.51%） | 71,163,904 B（67.9 MiB） | CPU 0.00% |
| 22 次工具调用后 | 65.34 MiB / 256MiB（25.52%） | 68,513,792 B（65.3 MiB） | CPU 峰值 0.04%，无增长趋势 |

```bash
$ docker stats --no-stream --format '{{.Name}} mem={{.MemUsage}} ({{.MemPerc}}) cpu={{.CPUPerc}}' p6-prom-mcp
$ grep -E '^(rss|total_rss) ' /sys/fs/cgroup/memory/docker/$(docker inspect -f '{{.Id}}' p6-prom-mcp)/memory.stat
```

**结论：实测 65~68 MiB，高于官方宣称的 20~50MB（超出上界约 36%）；在 256M 限额下占用约 1/4，余量充足；查询负载不推高常驻内存。**
