## 1. tools/list——core 模式（--mcp.tools=core）

| 工具 | readOnlyHint | title |
|---|---|---|
| docs_list / docs_read / docs_search | true | List/Read/Search Documentation |
| runbooks_list / runbooks_read | true | List/Read Runbook |

| metric_metadata | true | Metric Metadata |
| label_names / label_values | true | Label Names / Label Values |

**负向（core 模式，白名单外工具调用被服务端拒绝）**：

```text
tools/call delete_series {"match[]":"up"} → {"error":{"code":-32602,"message":"unknown tool \"delete_series\""}}
tools/call quit          {}               → {"error":{"code":-32602,"message":"unknown tool \"quit\""}}
```

服务端日志同步记录 `unknown tool`；无任何对 prometheus-am0 的请求发出。

## 2. tools/list——all 模式对照组（--mcp.tools=all，dangerous 开关保持默认关）

30 个工具（全文 `raw/tools_all.tools_list.json`）。core 之外的 19 个：

```text
alertmanagers build_info clean_tombstones config delete_series exemplar_query flags healthy
list_alerts list_rules list_targets quit ready reload runtime_info snapshot targets_metadata
tsdb_stats wal_replay_status
```

⚠️ **quit / reload / delete_series / snapshot / clean_tombstones 在默认 all 模式的工具清单中实际在列**（help 文本所称 dangerous 开关只约束"启用使用"，不约束"列出"）。

**quit 代理行为实证**（all 模式一次性容器上调用，未触碰生产）：

```text
tools/call quit {} → isError:true
  "failed making quit api call: failed to make Prometheus Management API call to /-/quit:
   received non-ok HTTP status code: 403"
服务端日志：level=WARN msg="triggering Prometheus shutdown"
MCP 容器自身未退出（quit 的靶子是 Prometheus 管理端点，不是 MCP 进程）
```

即：all 模式下 LLM 一次误调用 = 对生产 Prometheus 发起关停；本次止于 403 仅因 prometheus-am0 未开 `--web.enable-lifecycle`。

## 5. 传输与会话行为

- streamable http：`POST /mcp`，SSE 响应（`event: message` + `data:`）；`Mcp-Session-Id` 每会话唯一；`notifications/initialized` → 202。
- keepalive 30s：探测脚本遗留的未完成会话 30s 后被服务端主动回收（日志 `keepalive ping failed; closing session` → `session disconnected`）——符合 `--mcp.keepalive-interval=30s` 默认值。
- `GET /`、`GET /metrics` 均 200：MCP 与自指标/根路径同监听 ：8080，部署面必须仅 127.0.0.1 绑定或容器网络内可达。
