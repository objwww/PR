# 告警-评测执行方案 v1（执行者交接版）

> 2026-09-09 主会话。上游：`docs/告警-全系统收口与端到端评测主计划.md` v1.1 §四/§五。
> 本文 = 可执行拆解：执行者按 §4 领任务，按 §5 纪律执行，按 §6 取证。
> 回答用户核心关切：**"模型随时切换（哪个预算充足用哪个），每换一个就全量重跑代价太大"——见 §1 与 §3，结论是：当前阶段不需要，未来阶段用触发矩阵 + replay 底座把成本压到 1/5 以下。**

---

## 1. 先说清一个决定成本的事实

**当前 NATIVE RCA 生产链不调用 LLM**（源码审计 F01：模型标记常量 `native-deterministic-v1`，全链无 ModelGateway 调用）。由此：

1. **现在换模型，评测结果一个字都不会变**——管线是确定性的。所以"每换一个模型就重跑"在当前阶段**不成立，也不需要**。
2. Native 确定性基线**只需跑一次**：目的是确立参照原点（替代 deepseek-v3/Holmes 时代的 0/47 旧账——"47"为旧断言展开口径，当前 registry 展开为 **10 Case**）+ 验证评测链路本身健康（注入→firing→评分→落库→出账）。跑完就冻结，不因模型切换重跑。
3. "换模型要做回归"从**里程碑 A（LLM 真正入环）起**才成为日常需求。那时的成本控制方案见 §3——设计上日常切换只花全量 1/5 以内的代价。
4. 费用侧另有硬护栏（§5.4）：per-run 预算硬拦 + usage 三态对账，任何一层跑飞都会被拦住并对账出来。

## 3. 分层评测与模型切换触发矩阵（降本核心）

| 层 | 内容 | 墙钟 | 用途 |
|---|---|---|---|
| Tier-0 链路探针 | litellm 真实 chat 往返 + eval profile 配置核查 + 权限反断言抽检（不注入故障） | ~5 分钟 | 切换后确认"链路活着" |
| Tier-1 冒烟 | `eval-scenarios-s3.yml`（S3 单轮） | ~15 分钟 | 注入→firing→评分→落库全链验证 |
| Tier-2 核心子集 | `eval-scenarios-s345.yml`（S3~S5） | ~1~1.5 小时 | 模型/提示词变更的常规回归 |
| Tier-3 全量基线 | `eval-scenarios.yml`（5 场景×2 轮=**10 Case**，registry v2） | ~3.5~5 小时 | 只在门点跑 |

**触发矩阵（里程碑 A 之后生效；当前阶段只跑 §4 首批）**：

| 事件 | 执行层 | 说明 |
|---|---|---|
| 模型同档互换（预算驱动的 glm-5 ↔ deepseek 类替换） | T0+T1+T2 | 与上一模型**同子集结果**对比；退化未超阈即放行，**不跑全量** |
| 新模型首次引入 / 大版本或供应商变更 | T0→T3 全量 | 建立该模型全量基线 |
| 提示词变更（ConfigBundle digest 变） | T2 | 退化超阈升级 T3 复核 |
| Skill 变更 | R6 盲评底座（建成后） | 不经 Live E2E，走盲评 MATCHED 晋升制 |
| 工具/配置/规则变更 | T1 | 链路级回归 |
| 里程碑 G2 / 双周定期 | T3 | 基线刷新，门禁材料附件 |

**退化判定**：同子集对比，end_to_end_hit_rate 出现 cluster 级差异（注意 10 Case 统计上只有 5 个独立 cluster，按 scenario_family_id 整组看，不当 10 个独立样本）或 conditional_accuracy 降 >5pp → 标 SUSPECT 并升级 T3 复核；复核前不回滚也不放行，只挂起结论。小样本一律 INCONCLUSIVE 不放行（M5-08 chance/lift 校正口径）。

**长期降本（已排进主计划 R6）**：盲评底座建成后，模型/提示词回归以**离线 replay**（冻结快照重放，无故障注入、无 firing 等待）为主，Live E2E 退到门点。那时同档互换的回归成本从"1~1.5h + 故障注入"降到"分钟级 replay"。

## 5. 执行纪律（不可破）

1. 串行 slot=1；**上轮 resolved 未归并确认前禁入下一轮/下一场景**；失败不中断、落档、finally 清理（M3-17 冻结）。
2. 评测流量全 `chaos-` 前缀，live 零污染（INV-AM2-1/INV-AM3-4）。
3. **BA-19 纪律**：flagd JSON 只许精确改写目标 flag 的 defaultVariant 单键，禁 sed 正则批量替换。
4. **预算护栏**：单 run 预算上限硬拦（max_budget 账面化）+ usage 三态对账（MATCHED/PARTIAL/UNMATCHED）+ 超限停跑上报。
5. **只测不改**：发现的任何缺陷登记 BUGLOG（下一编号 BA-64 起），不在评测过程中顺手改实现、改阈值、改注册表；注册表/口径要改走变更评审。
6. 评测期间 195 生产告警链保持运行——评测是注入受控故障，出现非预期 firing（非 chaos- 前缀流量告警）立即停跑上报。

## 6. 取证格式（照 AM3 模板）

每批交付三类文件进 `docs/测试证据/eval/<批次名>-<timestamp>/`：
- **运行日志**：eval-runner stdout/stderr 全量（含四指标摘要行与 usage 对账行）；
- **链断言**：注入回执（chaos on/off + generation）、告警 firing/resolved 时间线（PromQL 截图或查询输出）、incident/run/report 落库行、报告 digest 回读；
- **DB 快照**：eval_run / eval_case_result 本批行导出（含 scenario_id、verdict、症状计数）。

格式参照：`docs/测试证据/AM3/e2e-m3-02-批量运行日志-d批.log` 与 `e2e-m3-02-批量链断言-d批.log`。
