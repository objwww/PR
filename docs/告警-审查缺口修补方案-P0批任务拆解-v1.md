## 二、P0-1：MC22 对峙呈堂 + MC21 question 上界

**目标**：R7 主模式报告中，同 claimKey 的 TRUE/FALSE 双断言不再 REVISED 覆盖，强制 UNKNOWN+MULTI_SOURCE_CONFLICT 并集呈堂；委派 question 自由文本加长度闸。

1. `alert/application/agent/PrimaryFinalClaimProjector.java`（投影 :80-97）：投影前对同 claimKey 组内做状态冲突检测——复用 `ClaimReducer.reduceGroup`（:70-115）裁决规则或直接注入 ClaimReducer 调用；冲突组强制 UNKNOWN+CONFLICT，证据全组并集呈堂（对齐 ClaimReducer:122-125 语义）。EXCLUSION→FALSE 的"确认排除"语义（:90-94）不动。

3. `infrastructure/persistence/PostgresDelegationDecisionRepository.java`：列注释同步（若选定截断语义）。
4. `ClaimStore.java:10-14` 四分支**不改**（REVISED/SUPERSEDED 是修订语义，保留）；冲突检测只加在投影缝，保证存储面历史不丢。

**测试落点**（新案补进 `PrimaryFinalClaimProjectorTest`/`DeterministicSupervisorTest` 同族文件）：

## 三、P0-2：MC24 查询规范化 + 同现场复用

**目标**：同参数不同措辞（空白/语序差异）的工具查询识别为重复；同 run 同 actionDigest 的重复查询复用已有证据行而非重打工具；新现场（新冻结窗）指纹必变，不受影响。

**改动落点**：
1. 新类 `alert/domain/tool/ArgsNormalizer.java`（或同族命名）：args 语义规范化（初版范围=字符串字段空白折叠/trim + Map 键序无关——canonical JSON 已管键序，规范化器只管字符串值）；javadoc 钉死"规范化范围白名单，逐字段扩面需评审"。
2. `ActionDigest.of`（domain/agent/ActionDigest.java:9-38）计算前接规范化器；**两计算点同源**：`ToolGateway.invoke`（:89-92）与 `SingleToolEvidenceAgent.investigate`（:132-134）。
3. **MCP 面并列防漂移**：`McpToolInvoker.java:57,106` 的第二套 actionDigest（args-only）同接规范化器，或裁定向主路径 ActionDigest 收敛——**实施时先裁定收敛还是并列，结论写进本文件偏差节**。
4. 同现场复用：`BoundedLlmRoleRunner.driveToolCall`（:201-247）invoke 前按 actionDigest 查本 run 证据账本（读面 `evidence.findByRunId`，:413-418 已有），命中则回喂已有 evidenceId 并落一行"复用"台账（不新扣工具预算？——**扣预算语义须裁定**：建议复用仍计一次工具调用防 DoomLoopGuard 豁免被绕，理由写 javadoc）。
5. 与 DoomLoopGuard（:55-78）协调：复用命中不得重置其"连续无进展"计数语义。

**测试落点**：
- MC24 主案 A：同参数换措辞（多余空白）→ digest 相同 → 第二次调用复用证据、零新工具执行（假件计数断言）。

- 既有 DoomLoopGuard 案回归不翻面。

**验收口径**：MC24 E；新现场必须重查由冻结窗结构性保证，验收只需断言面（审计③）。

## 四、P0-3：MC31 人工补充消费缝

**目标**：HINT/FEEDBACK 人工补充以 UNTRUSTED 身份段进入模型信封；人工根因判断不覆盖事实、不冒充独立来源；payload 有界。

**前置**：P0-1 已合并（同碰 PrimaryClaimAdmission/Projector 面）。

**改动落点**：
1. 消费缝：`ContextAssembler.assemble` 增 operator_command 读面——新端口方法按 runId 取 APPLIED 的 HINT/FEEDBACK（`OperatorCommandRepository` 增查询方法，Postgres 实现只读 SELECT 授权内）；以 UNTRUSTED 身份段入信封，条数/字符双上限（仿 MEMORY_SLOT_LIMIT 截断面 ContextAssembler:41,362-378）；空集=零段落，不造占位。
2. `OperatorCommand.java` 紧凑构造器：payload 大小闸（≤2048 字符，超限 400）；`RunCommandController.submit`（:46-91）同步校验。secret 不得入 payload 既有注释（:14-16）升级为**发送前扫描密钥词形拒绝**（对齐 R2 redacted 档惯例，`RcaModelGateway` 脱敏面同款词表）。
3. Claim 面（仅当人工补充含根因判断时）：必须走 `PrimaryClaimAdmission.admit`（:76-79 零有效引用→降级 HYPOTHESIS）同等准入；来源标签加 `operator:<actor>`（PrimaryFinalClaimProjector:80-88 同源推导点）——人工来源**不计入** MULTI_SOURCE 独立源数（与 MC22 同源折叠同律）。
4. 缝合既有不一致：`OperatorCommand.java:14-16`/`CommandService.java:31-32` 注释承诺的"上下文 UNTRUSTED 注入"由本卡兑现，注释语义与实现对齐。

**测试落点**：
- MC31 主案：HINT 含无引用根因判断 → 信封含 UNTRUSTED 段；若进 Claim 面 → 降级 HYPOTHESIS+operator 来源标签，不覆盖既有 TRUE/FALSE。
- 界案：payload 超限 400；密钥词形拒绝；条数/字符截断可追溯（omitted 标注）。
- 并发案：同 revision 双提交 → expectedRevision CAS（CommandService:89-91）REJECTED_STALE（MC32 顺带钉）。

**验收口径**：MC31 E、MC32 E（CAS 部分）。

## 五、P0-4：验证与 digest 小活（可全程并行）
