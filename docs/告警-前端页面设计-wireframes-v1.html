应用壳说明

① 页面清单：7 个一级入口 + 详情子路由

一级导航保持稳定；把队列、详情、实验比较和发布门组织成子路由，覆盖操作员完整工作路径
P0 登录页最小账号登录。架构 FUT-34 硬性要求：浏览器不得复用机器 Bearer，必须有用户会话。没有它，后面所有页面都没有合法身份。
P1 总览行动首页：逾期 Case、卡住/失败 Run、最老 READY、发布失败与评测回归优先；计数卡作为补充。
P2 告警中心/alerts 分类分诊；/alerts/{incident_id} 展示实例、阈值、端到端调查步骤、证据与报告；/history 检索历史调查摘要与归档证据。
P3 调查队列与审查/runs 是全部 Run 的工作队列；/runs/{run_id} 是 DAG、任务诊断抽屉、Attempt、事件流、Claim/证据/报告及人工干预详情。
P4 处置中心/cases 管理 OperatorCase 的认领、SLA 和闭环；“通知”作为同页标签，仅表达投递与已读状态。
P5 评测中心数据集治理 / 发起评测 / 批次运行 / 六维分析 / 案例诊断 / 人工复核 / 实验对比 / 发布门八个子视图；HOLDOUT 只返回聚合门禁结论。
P6 Agent 监控预算与成本之外增加队列积压、最老 READY、Outbox 延迟、调和积压、worker/slot 饱和度和异常跳转。

一级入口仍为 7 个：告警历史、Run 详情与评测八个视图均为子路由；配置发布页（ConfigBundle/Canary，属 AM5 后期）和用户管理页仍不在第一期。
