# 告警 DR-02 故障演练持久化作业链 v1

2026-09-11 落码。方案：`docs/告警-前端逐页体验改造与后期优化方案.md` 第七章（§7.2 页面契约 / §7.3 后端接法 / §7.4 状态机 / §7.5 DR-02 卡 / §7.6 用例矩阵）。本卡交付"命令与作业"：持久化作业 + 幂等 + 权限 + 服务端预检 + 环境互斥 + 执行器骨架（注入相位如实 NOT_IMPLEMENTED）。

## 一、状态机（§7.4 逐条落码）

```
QUEUED   → PRECHECK | CANCELLED            注入前取消可直接 CANCELLED
PRECHECK → INJECTING | FAILED | CANCELLED  预检失败零副作用可直接 FAILED
INJECTING → OBSERVING | FAILED | RECOVERING
           FAILED 仅"注入确定未执行"（零副作用）合法；注入可能发生即必走恢复路径
OBSERVING → RECOVERING                     停止/持续期满都先进恢复路径
RECOVERING → VERIFYING | RECOVERY_FAILED   恢复超时/残留 = RECOVERY_FAILED 保留占位
RECOVERY_FAILED → RECOVERING               处理入口：人工核验后重试恢复
VERIFYING → CLOSED | RECOVERY_FAILED       CLOSED 唯一来源 = VERIFYING
```

钉死面（三因子：DrillLifecycle 纯函数 + DrillJob 构造器 + V86 CHECK）：

- **CLOSED ≠ 成功**：outcome（PASS/FAIL/INCONCLUSIVE）另存，仅 CLOSED 落值；CLOSED 必带 outcome+closedAt，非 CLOSED 零 outcome/closedAt（`ck_drill_job_closed_shape`）。
- **环境互斥原子占位**：`uq_drill_job_active_env` 部分唯一索引，活动集 = QUEUED/PRECHECK/INJECTING/OBSERVING/RECOVERING/VERIFYING/**RECOVERY_FAILED**——恢复未核验前阻止下一场（DU15）；不同 faultType 同靶场同样互斥（§7.3）；终态（CLOSED/CANCELLED/FAILED）让位。
- **worker_lost 对账**：孤儿 CLAIMED 超龄——QUEUED/PRECHECK（未触及注入零副作用）重排队身份稳定不换 id；INJECTING 及以后先进 RECOVERING 再 RECOVERY_FAILED 保留占位（不越级直落、不冒充现场干净）。

## 三、端点契约（/api/drills，ROLE_OPERATOR；actor=AuthenticatedActor 不采信自报）

| 端点 | 契约 |
|---|---|
| GET /api/drills | `{items:[{drillId,scenarioId,scenarioName,targetEnv,operator,state,outcome,createdAt,closedAt}], summary:{active,recoveryFailed}, nextCursor, asOf}`；state 过滤 + 键集游标（limit≤200）；字段与前端 DrillsView 对齐 |
| GET /api/drills/templates | 真实场景目录（drill-templates.yml，派生 eval-scenarios.yml registry v2）：id/名称/类型/故障源/驱动/症状/影响/时间参数/参数白名单/execution{ready,reason}；**公开 DTO 零 GT**（expected_root_cause 不属于本面）；本批五场景 ready=false 带原因 |
| GET /api/drills/{id} | 详情：顶层四要素 + terminalReason + templateDigest + 冻结 params + 八阶段时间线 `[{key,name,phase,status,enteredAt}]`（enteredAt 只取真实事件，无事件=null）+ related{incidentId,runId}（null=尚未关联）；未知 404 |
| POST /api/drills/preview | 服务端预检：SCENARIO_KNOWN/TARGET_ENV_WHITELIST/ENV_OCCUPANCY/EXECUTION_READY = 真值 OK/FAIL；TARGET_HEALTH/RESOURCE_HEADROOM/RESIDUAL_FAULT/MGMT_PLANE/RECOVERY_CAPABILITY = **UNKNOWN 如实**（control 读面无授权通路，不造假）+ computed（duration/ttl/total 后端计算，TTL 公式沿 ArenaChaosScenarioDriver）；canLaunch=无 FAIL |
| POST /api/drills | body `{idempotencyKey,scenarioId,targetEnv,durationSeconds?,trafficScale?,linkedEvalVersion?}`；先对幂等锚（同键同计划 200 REPLAYED 原 drillId、异计划 409）→ 预检重执行（FAIL 409 带 checks）→ 落 QUEUED 202 `{drillId,state:ACCEPTED}`；并发竞态占位 409 CONFLICT_ENV 带 occupantDrillId；参数白名单服务端强制（DU04 篡改 400） |
| POST /api/drills/{id}/stop | body `{idempotencyKey}`；受理 202：注入前 CANCELLING、注入可能发生起 RECOVERING（**受理≠恢复完成，核验完成才 CLOSED**）；同 stop 键 200 REPLAYED；异键重复停止 200 ALREADY_REQUESTED 零新副作用（DU14）；终态/RECOVERY_FAILED 409；未知 404 |

偏差说明（对前端骨架）：前端只消费 GET 两端点字段，完全一致；preview/create/stop 前端尚未接线（DR-01 后续），契约以本文为准。时间线子阶段（产生测试流量/Agent 调查）无独立事件，enteredAt 如实 null。

## 四、执行器（DrillWorker，eval profile 同 EvalRunnerMain 进程，eval_app 身份）

- SKIP LOCKED 领取（沿用 EV-04 EvalRunWorker 模式）→ 相位边界查停止面 → PRECHECK（预检重执行落 PRECHECK_RESULT 事件）→ INJECTING → DrillInjectionPort。
- **本批诚实边界**：注入接线未交付（DR-03/DR-04 卡，含 `settleSwitchboard` 中断即退出、activate 回执先持久化等源码债务），唯一实现 `NotImplemented` → 确定零副作用 → INJECTING→FAILED（`INJECTION_NOT_IMPLEMENTED`），不假装注入成功。UNKNOWN → 必先进 RECOVERING 再 RECOVERY_FAILED 保留占位。OBSERVING 以后推进随真实接线交付。
- 因此模板目录五场景 execution.ready=false：preview/create 的 EXECUTION_READY 预检 FAIL（已知能力面不冒充 UNKNOWN，不开放假启动）；worker 内 NOT_IMPLEMENTED 分支为纵深防御 + 单测面。

## 五、安全面（§7.3）

- 浏览器只走认证后 /api/drills（SecurityConfig 矩阵 OPERATOR）；CHAOS_ADMIN_TOKEN 不进 control-app 任何 /api 面，管理面零直连。
- HTTP 面读写同权但 DB 面收口：control_app 对 drill_job 状态机推进零开口（只 insert + stop 两列），推进归 eval_app worker——伪造写请求在 DB 层同样被拒（双因子）。
- 模板目录为发布展示 DTO：GT/预期根因/labels_frozen 指纹面不在 jar 资源内（白名单装载天然剥离，单测钉死）。
