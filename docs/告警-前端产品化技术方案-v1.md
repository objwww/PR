# 告警 Agent 前端产品化技术方案 v1（页面 × 数据 × 接口 × 验收）

> 目标：把告警 RCA 操作台从"研发自证投影"升级为**可上生产环境的告警 Agent 前端**。
> 方法论来源：观测云/得物 Troubleshooter/AegisOps/ITGix 七页工作流 + Datadog Bits/PagerDuty SRE Agent/OpenRCA/AIOpsLab/Grafana OnCall/Langfuse/华为云 MAS/阿里云 STAROps 调研（2026-09-16，四轮合并）。
> 纪律：每页验收 = 195 真机截图 + 数据可溯源（能指到表/API），沿既有波次纪律（实现→部署→验收→台账→提交）。

---

## 0. 四条铁律

1. **真源**：页面数据一律接真实账本（incident/rca_run/rca_event/rca_model_call/rca_tool_invocation/approval_*/operator_case/…），不模拟、不用旧账本；后端没有的数据先建接口建表，禁止前端造数。
2. **内容只增不减**：每页模块 ≥ 业界清单所列；业界没有而我们账本更强的（哈希链审计、审批安全面），必须亮出来。
3. **全中文**：所有界面文案、状态、枚举值一律中文（如 SUCCEEDED→已完成、TIMEOUT_OR_ABSENT→超时或缺失、ESCALATED→已升级人工）。前端建统一字典 `src/dict/zh.js`，禁止裸枚举上屏。
4. **配色沿用**：现有蓝白体系（主色 #1c4d8f 系、状态色绿/红/黄/蓝灰）不变，只重构信息架构不改视觉身份。

## 2. 全站公共规范

- **中文字典** `alert-web/src/dict/zh.js`：run 状态（排队中/调查中/报告组装中/已完成/部分成功/失败/已升级人工）、操作状态（已计划/已派发/已确认/未知/对账中/已升级人工/人工裁定完成/人工确认失败）、判定（可判定/证据不足/超时或缺失）、严重级（致命/警告/提示/页面/普通）、等待原因（等待路由放量/背压暂扣/无）。所有徽章/筛选/表格经字典渲染。
- **实时性**：实体详情用既有 SSE（`/api/rca-runs/{id}/events/stream`）；列表页 30s 轮询 + 手动刷新（与业界 WebSocket 等效，第一版不新增推送基建）。
- **权限表达**：会话角色 OPERATOR；写面按钮按角色渲染；机器线专属操作显示"该操作由发布管线签发"而非可点必失败。
- **错误数据零容忍**：任何面板数字必须能与库内 `select count` 对上，验收时逐面板对账。

## 3. 页面规格

### 3.1 总览 Dashboard（增强）
模块与数据：
- 健康评分卡：分数 = f(开放事件, 待审批积压, 通知失败, 调查失败率)——`GET /api/v1/overview/summary`（已有）扩展 `healthScore`
- 告警统计卡：按致命/警告/提示计数下钻 —— `GET /api/v1/incidents`（已有）
- 实时洞察流：最新已结案报告结论 + 待审宣，徽章/时间/标题可展开 —— `GET /api/v1/overview/insights`（**新增**：聚合 rca_report 最近 N 条 + incident 状态）
- 待审批提醒：PENDING 审批数 + 最近 3 条 —— `GET /api/mutation/pending-approvals`（**新增**）
- 值班卡：当前主/备值班 —— `GET /api/oncall/current`（**新增**，值班域）
- 趋势图：降噪率、MTTA/MTTR 近 7 天 —— `GET /api/analytics/trends`（**新增**，Analytics 域）
- 预测卡（P2）：容量/性能趋势 —— 确定性统计外推，不引入 LLM
验收：五秒内可见"是否健康/最紧急三件事/谁在值班/有没有等我的审批"。

### 3.2 告警中心（增强）
- 新增列「AI 处理状态」：已调查（有 run 且终结）/ 调查中 / 等待路由放量（WAITING_CAPABILITY）/ 背压暂扣（DEFERRED）—— incident 投影补 `waitingReason`+`runState`（**新增**投影字段，来源 incident 表既有列）
- 视图切换：事件视图（incident 聚合，默认）/ 告警视图（alert_event 原始流水）—— `GET /api/v1/alert-events`（**新增**投影）
- 行内快捷操作：排查（=发起重驱/新 run）、确认、忽略 —— 复用 case 动作或 incident override 接口（部分已有）
- 状态筛选 + 严重级筛选（已有）+ 全中文化
验收：每行能看出"AI 管到没有、为什么没管"。

### 3.3 告警详情（增强）
- AI 结论区：结论三态徽章（支持/反对/未决→中文）+ 置信度 + **确认 / 驳回**按钮（写 `conclusion_feedback` 标注表，**新增** POST `/api/incidents/{id}/conclusion-feedback`；此表同时是 precision 指标数据源）
- 证据链：按时间窗聚合、可跳原始源 —— 复用 rca_evidence/EV-05 投影
- 时间轴：rca_event 时间线 + 变更事件叠加（演练/发布事件拉入同一轴，**新增** `GET /api/incidents/{id}/timeline-merged`）
- 关联告警：同 incident_key 历史 episode + 同服务近 24h —— **新增** `GET /api/incidents/{id}/related`
- 操作：重新排查（**新增** POST `/api/incidents/{id}/reinvestigate`，走既有 RERUN 触发路径）、生成工单（ITSM 出向，P2）、加入对话（跳 AI 对话页带上下文）
验收：确认/驳回后 Analytics 的采纳率数字变化。

### 3.4 AI 对话/诊断页（新建，Wave 4）
- 会话列表 + 聊天流 + 上下文卡（当前告警/服务）+ 快捷动作（生成报告/创建工单/执行修复）
- 第一版真实语义 = **诊断会话视图**：选告警 →"开始排查"=发起调查 run，对话流渲染 run 的任务推进/工具调用/中间结论（全真数据回放+追加提问走调查提示词）——不做自由聊天假 AI
- 后端：POST `/api/chat/sessions`、GET `/api/chat/sessions/{id}`（会话=incident+run 绑定）

### 3.5 审批与处置页（新建，Wave 1 本轮）★
- 待审批列表：工具/目标资源/风险级（R1-R3 中文）/请求时间/**有效期倒计时**/所需票数与已投/请求人 —— `GET /api/mutation/pending-approvals`（**新增**，查 approval_request PENDING + decisions 聚合）
- 操作详情：参数 JSON、快照锚、dry-run 预览（复用 dry-run 链）、绑定 run/意图
- 升级人工裁决列表：ESCALATED 操作 + 锁持有状态 —— `GET /api/mutation/escalations`（**新增**）
- 隔离区放行列表：QUARANTINED 告警 + 命中特征 —— `GET /api/inbox-admin/quarantined`（**新增**）
- 决策动作：批准/拒绝（含意见）、裁决（完成/确认失败）、放行 —— 全部复用既有 POST 端点
- 执行轨迹：操作事件链（已派发/未知/对账中/…中文渲染）—— 复用 run 事件查询
验收：评审员从发现待办到完成裁决全程页面内闭环；消融 A 的 UNCERTAIN 案例可在页面完成人工批准。

### 3.6 配置中心（新建，Wave 5）
告警类型配置（分类规则/排查开关/推送开关——复用分类规则库+config bundle）、接入管理（webhook 清单+HMAC 状态）、通知渠道管理（渠道 CRUD+测试发送——notify 渠道面）、权限与角色（复用 /api/auth/users）。全部走既有表/配置包，前端新表单页。

### 3.7 处置中心（增强）
case 详情补「整改项」清单（action_items 表，**新增**，复盘闭环）、同名 UNRESOLVED case 按原因+服务聚合分组展示。

### 3.8 值班管理（重建，Wave 3）
新表 `oncall_schedule`（排班规则：成员/时区/周期）、`oncall_shift`（班次实例）、`escalation_policy`（升级链步骤）、`assignment_rule`（标签→排班分派）。
- 排班日历视图 + 我的班次 —— `GET /api/oncall/schedules|shifts|current`
- 升级链配置页（三段式模板预填 5/15/30 分钟）
- 分派策略页（标签匹配 + 兜底）
- **升级执行器**（新增后台循环）：case/incident SLA 超时（认领期限/解决期限字段已存在）→ 按升级链发通知 → 写升级记录
验收：一条致命告警走完"通知→认领→超时升级→兜底"全链真机演练。

### 3.9 通知中心（增强，Wave 3）
通知行挂实体实时状态（关联 incident/case 状态+认领人）、渠道管理页、静默窗口（maintenance_window 表 **新增**）、升级记录页签；IM 群定位=入口消息收敛（总量+最高级+处理链接）。

### 3.10 监控（修复+增强，Wave 1 本轮 + Wave 4）
- **切源修复**：`llm_calls_24h/tokens_24h` 从 `external_invocation_ledger`（已停写）改 `rca_model_call(created_at, total_tokens)`；工具 TopN 改 `rca_tool_invocation(tool_name, started_at)` 真实工具名
- 性能概览：AI 请求数/平均与 P99 耗时/错误率/模型调用次数/Token——环比对比上一窗口（**新增** `GET /api/agent-ops/latency-layers`、costs）
- 分层延迟：端到端(rca_run created→finished)/任务(rca_task)/模型调用(latency_ms)/工具调用(started→settled) 各层 p50/p95 —— SQL 聚合直出
- 成本归因：定价配置表 `model_pricing`（**新增**，单价入库→cost_micros 已有列）+ 模型/工具占比
- 风险审计：GUARDIAN_REVIEWED/审批拒绝/隔离命中事件列表，锚到 run 轨迹
- 执行器活性：沿用四源租约推导（rca_attempt/rca_task/eval/drill）
验收：24h 模型调用次数与 `select count(*) from rca_model_call where created_at>now()-'24h'` 逐一对账。

### 3.11 评测中心（增强，Wave 5）
- 评测集分层：数据集打标签（冒烟/回归/探索/红队），红队集来源=注入扫描特征库+Guardian UNSAFE 用例
- 废批治理：实验打标（有效/废批-超时/归档）+ 一键重跑（复用发起端点）
- 判定三式：确定性断言（已有根因命中）+ 关键词 + **LLM 评审**（新增评分器，评报告可用性）
- 三维评分（对标 RCA-100 口径）：实体一致性（claim.component vs 注入靶）/ 调查路径（rca_event 轨迹覆盖关键证据节点，哈希链保证可信）/ 结论复核（claim↔evidence 引用解析）
- 持续回流：SUCCEEDED run 自动转候选案例 → 人工评审页准入
- 成本列：接入定价表后费用真实化

### 3.12 演练（增强，Wave 5-6）
故障模式库（fault_mode 表：条件/现象/影响，**新增**）→ 演练规划（执行人/时间窗/接单）→ 任务执行（已有）→ 报告页（注入/感知/定界/恢复四段 + 韧性得分 = 服务×故障模式覆盖矩阵）→ 演练自动注册评测候选案例。

### 3.13 服务目录（新建，Wave 6）
服务清单聚合页：owner（值班路由绑定）、依赖（拓扑/调用链推导）、近 30 天事件数/MTTR、告警路由关系。起步=只读聚合（从 incident 标签 + 演练靶 + catalog 工具元数据），后续接 CMDB。
`GET /api/services/**`（**新增**聚合投影）。

### 3.14 Analytics（新建，Wave 2）
`GET /api/analytics/**`（**新增**）：MTTA/MTTR 趋势、降噪率（原始事件数→incident 收敛比）、告警→事件转化率、precision/recall（precision 来自结论确认/驳回标注，recall 来自漏报回填）、AI 采纳率/纠正率、成本趋势。全部现有表聚合，零新数据源。

### 3.15 复盘（新建，Wave 6）
事件 RESOLVED → 自动起草（聚合报告+时间线+处置记录）→ 人工编辑 → 整改项清单（action_items）→ 闭环状态。AI 仅起草与建议，定性由人。

### 3.16 Prompt 工作台（新建，Wave 5）
- 资产列表补透出：显示名/逻辑版本/状态（release-assets 数据面**新增**字段透出）
- 编辑器 + 版本 diff（版本不可变快照，沿 config bundle 修订模型）
- 试跑（Playground）：对指定 golden 单案例发起 dry 诊断
- 发布：对某版本打「生产」标签 = 触发受控发布（走 R2 审批链——发布也是有副作用的操作，恰用自家安全面）
- 评测联动：版本 × 数据集发起对比实验（复用评测中心）

### 3.17 调查详情 Trace 页签（Wave 4）
run 内 span 瀑布：任务节点→模型调用（耗时/Token）→工具调用（起止/状态）→事件锚点（Guardian 评审/审批/裁决），全量来自既有四张表，零新采集。

## 九、收官纪律（2026-09-16 追加，铁律级）

### 9.1 真数据铁律（UI-DATA-1）
- 页面**每一个子标题/卡片/指标位**都必须接实时真数据；`EmptyState` 仅允许出现在"真实数据源为空"的场景，且必须写明数据源口径。
- **禁止硬编码假数据**：占位文案（如旧版"健康数据未接入"）、写死数字、mock 字段、无源的装饰性图表一律视为验收不通过项。
- 无数据源的区块两条出路：①接真源（建表/建端点均可）；②从页面移除。不允许"标题在、数据假"。

### 9.2 业界对齐铁律（UI-IND-1）
- 每开发一个新页面/新功能，必须先给出业界参照物（PagerDuty / Grafana OnCall / Datadog Bits AI / Rootly / incident.io / OpenRCA / RCA-100 / Google SRE 等）与对应实践，再动手；"内容只可多不可少"沿 v1 总纲。

### 9.3 自驱收官协议（UI-LOOP-1）
- 每个页面完成并通过验收截图后，**不等指令**，自动进入方案内下一个未完成页面/功能，直到本方案 v1 覆盖的**所有**前端页面收官。
- 收官判据（逐页核对）：零错误数据、零裸枚举、零可点必失败、空态有口径说明、每个子标题实时真数据（9.1）、业界参照留痕（9.2）。
- 每页收官后在本节末尾追加台账：页面 / 完成内容 / 业界参照 / 验收截图 / 提交号。
