# 测试交接规范（委托测试的强制约定）

> 版本 v1.0 ｜ 生效范围：所有里程碑的工序 5（测试验证）如委托给其他 agent/会话执行
> 制定原因：测试执行者与被测代码的作者不是同一人时，必须有书面契约，
> 否则会出现跳测、带病通过、临时脚本污染、失败信息不足无法修复四类事故。

## 一、角色边界

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 用户 | **指定执行 agent**（主会话不指定、不推荐人选）；转交交接文档与测试回流结果 | — |
| 主会话（作者） | 出交接文档、定测试矩阵、修复缺陷、验收测试报告 | 不干预执行过程；不指定执行 agent |
| 执行 agent（测试员） | 按交接文档逐项执行、取证、记录 | **不修复任何产品代码和测试代码**；不跳过任何用例；不改断言；不新建规范外文件 |

## 二、执行纪律（违反即返工）

1. **禁止跳测**：每个用例必须执行并给出 PASS / FAIL / BLOCKED 三态之一。
   - 某用例因环境/依赖**无法进行** → 记 BLOCKED，写清阻塞原因，**继续执行后续可执行的用例**，
     不允许"前面挂了就停"。
   - 全部 FAIL/BLOCKED 汇总后交回主会话修复，修复后**全量回归**（不是只回归失败项）。
2. **禁止临时脚本污染**：
   - 不创建一次性验证脚本。确有必要时，只能放 `deploy/test-tmp/`，用例结束后**删除**，
     并在测试文档"清理登记"一节记录"已删除"。
   - 不改动 compose 配置、`.env`、数据库数据（测试用例自身要求的故障注入除外，且注入后必须复原）。
   - 服务器上任何破坏性操作前先备份，备份只增不删。
3. **取证即交付**：FAIL/BLOCKED 的价值取决于主会话能否仅凭记录定位修复。

## 三、测试文档模板（每用例一条）

```
| 用例 ID | 结果 | 证据路径 | 备注 |
```

FAIL / BLOCKED 必须附故障详情卡（缺一不可）：

1. **现象**：期望什么、实际什么（一句话）；
2. **复现步骤**：完整命令序列（可复制直接跑）；
3. **退出码与输出**：stdout/stderr 尾部（截取关键 50 行内）；
4. **环境快照**：相关容器状态（`docker ps`/`docker logs --tail`）、
   相关数据库行（inbox / review_run / outbox_command / execution_event 的涉事行 SELECT 结果）；
5. **时间线**：故障注入点、各事件发生的先后顺序；
6. **初步猜想**（可选，必须标注"猜想"，不作为修复依据）。

## 四、主会话出具的交接文档必须包含

0. **背景简报**：附上 `docs/测试交接-背景与服务器现状.md`（项目是什么/进度/服务器现状/
   禁碰区/真实成本警告），并在出具前核对刷新——执行 agent 没有任何项目上下文；
0.5 **主会话预验义务（2026-09-02 用户订立，硬性前置）**：凡能在目标服务器（195）真环境
   验证的，主会话必须在出具/更新交接文档**之前**亲自在 195 预验通过——至少含：交付物
   全部同步到位（脚本 bash -n、代码 jar 实证含新改动）、镜像重建起栈自检、受影响链路的
   全量预跑（能跑多全跑多全）。预验发现的问题由主会话修完再交接；**禁止把"没真跑过"的
   交付物直接甩给执行方去撞**。预验不替代执行方的正式回归（作者不自测自评纪律不变），
   它是交接的前置门，目的是消灭"已知未知"造成的空转轮次；
1. 测试矩阵全清单（从方案 §11 导出，逐条含：场景、执行方式、预期断言、取证要求）；
2. 执行顺序与依赖（哪些用例可并行、哪些必须串行、哪些是部署门）；
3. 环境锚点（服务器、密钥路径、起停栈命令、数据库连接方式）；
4. 故障注入工具清单（每个 E2E 故障怎么注入、怎么复原）；
5. 清理清单（测试结束后应删除/复原的一切）；
6. 回本规范的遵守声明。

## 五、修复回路（结果如何回到主会话）

```text
执行 agent 逐用例执行
  ├─ 实时写三文档（测试进度.md=三态+下一步指针；测试记录.md=证据原文；
  │   测试BUG清单.md=TB-NN 故障卡，只增不删）
  └─ 收工 → 告知用户执行完毕
       → 用户把回流结果转交主会话
       → 主会话逐条核对 FAIL/BLOCKED 故障卡
            ├─ 信息不足：退回补充取证（指明缺哪一项）
            ├─ 产品/脚本缺陷：主会话修复 + 补/改回归测试 + 更新 TB 状态为「已修复待回归」
            └─ 设计内行为：主会话裁定关闭并写明依据
       → 主会话重新出具交接文档（版本号递增，写明变更点）
       → 执行 agent 全量回归（不是只回归失败项）→ TB 全部「已关闭」才允许进 G2
```

要点：

- 执行 agent 与主会话**不直接交互**，一切结论以三文档为凭、经用户转达；
- 主会话只看证据不看转述——故障卡六要素缺一不可；
- 任何一轮存在未关闭的 FAIL/BLOCKED，本轮测试不算完成。

*—— 规范完。本规范由 M1 G1 评审要求订立，后续里程碑沿用。*
