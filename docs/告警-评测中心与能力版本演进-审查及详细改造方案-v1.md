# 告警评测中心与能力版本演进：审查及详细改造方案 v1

> 2026-09-11。范围：用户指定的四份调研、分类/值班仿真/列表方案，以及实际评测页面与查询代码；补齐Prompt、Skill、MCP/Tool、RAG、多Agent策略的版本演进和评测。本文是待实施规格，本轮不修改运行代码、不发布配置、不执行注入或真实模型跑批。源码核对只代表本地工作区，历史文档里的部署结论不自动视为本轮实测。

## 一、先给审查结论

当前评测中心是批次结果查询器，距离“能发起实验、知道卡在哪、解释失败、比较版本并决定发布”的工作台还有实质差距。改字号、加token列或准确率折线都不够。改造应围绕四个动作组织：发起一次实验、排查一个失败案例、比较一个候选版本、处理一项发布资格。

评测与监控共享Run和调用事实，但页面职责不同：监控回答系统是否正常，评测回答某项变更是否更好。故障演练负责制造与恢复现场，不能合并成一个“运行成功”状态。Prompt/Skill/MCP是被测资产，不是评测页角落里几个无版本的标签。

## 三、页面结构：把评测中心变成可以完成任务的工作台

顶层只保留“实验”“数据集”“人工评审”“能力版本”四个入口；评测中心默认进入实验列表。版本对比是选择实验后的工作区，不再在每个实验详情中放一个空对比tab。故障演练保留`/drills`独立导航，与实验互相链接。

| 页面 | 拟定路由 | 用户来这里完成什么 |
|---|---|---|
| 实验列表 | `/eval/runs` | 找正在跑/待处理实验，选择基线和候选 |
| 新建实验 | `/eval/new` | 选择模式、被测版本、数据集和预算并提交 |
| 实验详情 | `/eval/runs/:runId` | 看阶段、卡点、结果和失败案例 |
| 案例详情 | `/eval/runs/:runId/cases/:caseExecutionId` | 检查输入、报告、证据、调用与评分 |
| 对比工作台 | `/eval/compare?baseline=…&candidate=…` | 定位改善/退化，核查发布资格 |
| 数据集详情 | `/eval/datasets/:version` | 查版本、案例适用范围和分层覆盖 |
| 人工评审 | `/eval/review`及具名任务子路由 | 按冻结标准复核一个案例并提交 |
| 能力版本 | `/eval/assets`及`/:kind/:id/:version` | 查Prompt/Skill/MCP/Tool/RAG/策略候选、依赖与实验 |

### 3.1 列表页：一眼知道哪些实验需要处理

页头只放标题、最近更新时间和“新建实验”。第二行是三个可点过滤项：执行中、待处理、已结束；不得把运行失败、质量未达标和费用待对账全部塞进一个失败状态。筛选栏放名称/ID搜索、数据集、被测资产类型，模式和时间进展开筛选。

默认表格控制在七列：实验名称与模式、版本差异摘要、数据集与样本数、执行阶段/已结清案例、质量摘要、费用状态与耗时、创建时间/操作。名称可读，UUID缩写可复制；模型和Prompt全量digest放详情。质量摘要主显端到端命中“18/24”，副显错误确认/未决；分母缺失显示未统计。token与成本可切换列，不默认同时堆两列均值。

选中两条实验后出现上下文操作条“设为基线 / 比较”，不常驻一排无关按钮。增加候选三臂比较时，摘要可列三臂，逐案例只显示基线与一个候选，切换候选保持案例定位。排序由后端执行；不能把加载的前50条本地排序伪称全量最老优先。

### 3.2 新建实验：四步，配置能回看

第一步选模式：确定性全链测试E、冻结输入的质量对照B、真实模型与靶场L。用中文说明是否触发真实模型/现场副作用。Replay不得标“真实端到端”。第二步选基线与候选release，显示实际变化的Prompt/Skill/MCP/schema/模型/调度策略，默认一次只变一个因素；多因素变更允许组合验收但不能声称识别单因素收益。

第三步选数据集版本、案例切片、重复次数、分层及固定运行顺序策略。HOLDOUT不可通过普通操作者页面浏览答案，不允许对训练用集反复调参后宣称盲测。第四步选总预算、并发和截止时间，查看前置检查与不可用能力。L模式涉及现场时复用drill编排和环境互斥，不另造第二个注入器；实验启动用持久化命令，返回202即进入详情而非一直旋转。

运行费用预估可显示区间和假设，数据不足就显示未知；不能承诺固定耗时。重复点击、网络重试通过服务端幂等键去重，浏览器禁按钮只是体验增强。

### 3.3 实验详情：运行时看进展，结束后看结论

第一屏固定“身份/版本 + 执行状态 + 当前阶段 + 最后有效进展时间”，下方质量摘要不超过四项。运行中主区为阶段时间线和当前案例；完成后主区为质量结论与退化/失败案例列表。配置详情默认折叠，完整摘要不占据首屏。

主区页签为“案例结果”“执行轨迹”“用量与对账”“配置与资格”。案例结果默认展示需要处理的样本，提供全部/错误确认/未决/结构失败/缺席/基础设施失败筛选。评分状态与执行状态并排独立显示，脚本退出0不等于质量通过。

案例进度展示“已结清18/24，成功12、未决3、执行失败3”，不能显示18/24的绿色成功条。R7动态子任务数量会改变，因此任务done/total只是当前计划完成度，不能当固定剩余时间。实验计划的案例数量在启动时固定，变更案例需新实验；新建子Agent不改变实验案例分母。

卡点区域回答四件事：在等什么、等了多久、谁持有、下一次自动动作是什么。明确区分等待靶场资源、排队、退避、工具调用、模型响应、等子Agent、等报告、等恢复、等评分和费用对账。每项显示来源、asOf、deadline/nextRetryAt；没有直接证据就写“当前动作未知”，不从STARTED残留行推断仍在触网。长告警窗口写“等待观测窗口”，不自动标故障卡死。

### 3.4 案例详情：让人判断为什么错

桌面宽屏使用两区：主区约65%展示报告、支持/反对证据；辅区约35%展示评分、错误原因和版本。宽度不足时上下堆叠；原始长文本只在本区滚动，不将两区都缩成窄栏。调用轨迹作为独立页签，左侧树按主Agent/子Agent/task/attempt展开，右侧显示选中动作。

证据展示冻结快照、来源、范围、时间、digest、截断/脱敏标记。提供“查看当前数据源”另开查询结果，明确它是新观察，不覆盖实验快照；源日志过期也不影响已有快照的身份。证据访问按run及用户权限校验，禁止通过输入任意evidenceId跨对象读取。禁止执行日志中的HTML或将Markdown链接当可信管理链接。

待复核者可看到参考答案的前提是获得该数据集权限。先盲看输出再揭示参考答案可作为任务策略；模型被评系统绝不获得评分器专属GT。工具参数显示经过字段级白名单处理的摘要，密钥、完整敏感Prompt和隐藏思维链不进入界面。

### 3.5 对比工作台：先看能否比较，再看有没有变好

顶部展示数据集/案例版本、输入快照、模型、预算、评分器与规则版本的可比性检查。完全一致标严格配对；公共子集比较必须显示交集与缺失数量；不同数据集默认不生成一条笼统提升百分比。三臂策略比较沿R7 v2.1，保证工具能力和总预算可比。

首屏是基线与候选的指标差值、样本量及不确定性；主表按“退化、改善、两者失败、结果不完整”切片。每行匹配case_uid+输入digest+重复轮次/种子，不仅匹配scenarioId。结构化根因和证据引用逐项diff，文本差异与评分变化分开，不把措辞变化当质量提升。

重复轮次不是独立故障样本。统计单位按预先冻结的incident/场景簇处理，置信区间与最小独立簇门槛沿现有PairedTrialStats/QualityGate核对；少量样本只展示观察结果和“证据不足”。图表不跨不可比版本连线，也不在一次偶然胜出后自动发布。

### 3.6 数据集与人工评审

数据集列表显示版本、来源、案例数、适用工具和故障族；详情提供版本diff、切片覆盖和案例预览。案例新增/修正产生新版本，不覆盖旧实验输入。显示重复/泄漏风险，训练、开发、盲测分区分别授权。

评审页采用任务列表→单例工作区。领取使用服务器CAS和有界租约，两人提交同一revision时明确冲突；草稿与最终提交分开，最终结论追加审计。评分项使用冻结rubric，允许“无法判定/来源不足”，必填理由与证据引用，不要求审核者强行二选一。

评分器先上程序规则和人工复核，再接经过校准的LLM judge。机器分、人工分、两者分歧分别保留；人工也会误判，支持复核裁决。judge异常不是被测Agent得0分，记录SCORER_ERROR并允许单独重评分，不能因此重新触发故障。生产抽样质量称“抽样评审通过率/一致性”等，缺真实GT时不标全量准确率。

## 四、Prompt / Skill / MCP等能力如何演进与评测

### 4.1 一个版本中心，多个资产类型

复用增强线的不可变资产与release manifest，不能再造第二个active注册表。版本列表按资产类型过滤，每行显示逻辑ID、版本、digest、状态、被哪些release使用、关联实验、可用运行器和兼容性。详情固定四块：内容/差异、依赖与权限、实验结果、发布记录；raw配置置于高级视图。

| 类型 | 固定哪些内容 | 该测什么，不能只测什么 |
|---|---|---|
| Prompt | 系统模板、变量schema、模型/解码配置、输出schema | 根因/证据正确性、弃答与注入抵抗；不能只测能输出JSON |
| Skill | 指令、资源/脚本digest、适用条件、输入输出、工具要求 | 应触发/不应触发、步骤安全、反例、版本回退；不能只测文件加载成功 |
| MCP | server身份、协议/传输、工具列表与schema摘要、权限策略、部署能力版本 | 握手、断连、授权、schema漂移、未知结果、撤权、预算、真实业务收益；不能只测initialize成功 |
| 原生Tool | 代码版本、参数/返回schema、服务范围、错误语义 | 参数边界、真实取证、截断/空数据、无副作用、可追溯性 |
| RAG | 语料/切片/索引/embedding版本、过滤与检索策略 | Recall@k/反证召回、误召回、过期/越权、最终报告收益；不把引用存在当faithfulness |
| 多Agent策略 | 角色目录、Profile、委派策略、总预算/深度/批次限制 | 简单零委派、必要专家、重复调查、恢复及费用；不以启用角色数作为质量 |
| 上下文与压缩策略 | contextPolicy、compactionPrompt、摘要schema、token估算器及模型能力配置的固定版本 | 不压缩/确定性/LLM三组对照；关键反证保留、来源准确性、恢复一致性、总费用与延迟 |

凭证值不进入manifest、diff或导出；保存受控凭证引用和授权策略版本，轮换通过运行时安全机制完成。MCP工具list变更必须先刷新能力快照并发布，不在旧Run中悄悄扩大工具集合。协议定义相同也不代表后端行为相同，记录已知server部署版本；第三方无法固定实现时明确不可完全重放。

### 4.2 从编辑到生效的闭环

候选内容DRAFT→静态校验VALIDATED→绑定测试计划TESTING→资格评审→PUBLISHED或REJECTED。这是资产发布流程，与实验executionState及资格verdict三个对象独立。不得把后端不存在的状态枚举仅在前端画出来。发布事务CAS切换既有active指针，前端不决定资格。

在版本详情点“创建回归实验”时，自动带入候选、现役基线和适用案例切片，但用户能查看完整计划。Prompt变更跑输出/引用/安全及场景回归；Skill变更额外跑触发反例；MCP/schema变更额外跑协议契约与真实工具；共同跑取消/预算/版本冻结的执行回归。只有相关资产变化才跑相应增量集，同时保留固定核心回归集。

新增Skill的LLM沉淀只产生DRAFT，页面显示来源调查、人工复核状态、适用边界、脱敏结果和反例。默认无发布权限；不得读取HOLDOUT答案训练自身。人工修改、生成模型、源Run和脚本资源都有digest。先验证可复用方法，再决定是否转为正式Skill，不能用“生成了很多skill”证明自进化。

### 4.3 三道资格门，分别展示原因

质量门：必要程序断言、同预算对照、独立样本充分性、人工/已校准judge结果。运行门：取消恢复、错误率、时限、资源与数据源能力。资产门：依赖已部署、schema兼容、授权、完整性和可回滚。费用未决在费用面单列，是否阻止发布按冻结策略判定；“对账MATCHED”不是质量晋升。

版本页顶部显示每道门的PASS/FAIL/INCONCLUSIVE/NOT_RUN和具名原因/实验链接，禁止一个总分遮蔽安全失败。资格针对精确release digest，改一个字后旧资格不能自动继承。发布按钮只提交服务端命令，前端隐藏按钮不替代权限。

### 4.4 热更新：服务不停，运行不串版本

默认“发布到新调查”：事务切换active，新Run固定新release；旧Run保留原版本。高级操作“在安全点更新此调查”：显示兼容性、在飞动作、等待原因、deadline、旧/新epoch及应用结果。R7主任务WAITING_CHILDREN不换主Prompt，等待整批结清后再校验；安全点失败不自动改成强制替换。

兼容Prompt/Skill内容是否允许迁移由增强线schema与执行契约判断；工具权限、角色目录、Skill结构、不兼容MCP/schema变化必须新Run。紧急撤权阻止后续动作并保留审计。混合配置Run标MIXED_CONFIG，可查看过程但不得作为某一单版本纯对照样本。回滚也必须完整恢复可用依赖；撤回active指针不等于已发送网络请求被撤回。

## 五、数据与后端接口：先把数字和身份定义正确

### 5.1 身份链与状态分面

持久化experimentId→caseExecutionId(case_uid、case版本、输入digest、重复轮次)→drillId（可空）→rcaRunId→taskId/roleId→attemptId→logicalActionId→physicalRequestId；review_run单独域，不与evalRun合并。一个case可能关联多次重试Run，显式记录计分选中的报告与选择规则；保留所有费用，不能只算最终成功那一次。

查询返回executionState、phase、qualityVerdict、recoveryState、usageStatus、freshness分别表达。兼容旧state不改原语义；新增阶段由worker落事件/投影，不在前端猜测。stageEnteredAt、lastProgressAt、leaseHeartbeatAt不是一个时间戳：worker活着但任务没有进展应能区分。UNKNOWN结果必须对账，不能当“仍运行”永久展示。

### 5.2 指标词典（需要作为可点击说明）

| 指标 | 正确定义/展示 |
|---|---|
| 根因可判定覆盖率 | decidable / total，沿ScenarioMetrics原公式；不叫任务执行覆盖率 |
| 条件准确率 | hits / decidable，必须显示分母，不能靠高未决掩盖低覆盖 |
| 端到端命中率 | hits / total，失败/缺席保留在冻结总分母 |
| 未决率 | unresolved / total；“合理未决”要额外GT或人工依据 |
| 症状TP/FP/FN | ScenarioEvaluator症状集合交集/多报/漏报；与根因命中是不同粒度 |
| 错误确认 | 可判定但根因错误的案例数及比例；与症状FP分开命名 |
| Token | 按唯一物理调用计input/output/total与usageMissing；预留额不是实际消耗 |
| 费用 | 已确认、待对账、估算分开；currency和pricingVersion必带，不同币种不直接相加 |
| 用量覆盖 | 已知usage调用数/所有应记账调用数；部分未知不显示“总费用已确定” |
| 时延 | 排队/执行/评分/恢复分开；并行子span耗时不能求和作为wall-clock |

旧ScenarioMetrics零分母输出0.0是存量序列化契约，本次不静默修改。新增DTO返回numerator/denominator/status，分母0时UI显示“不适用/无样本”，保留原数值字段供兼容；null展示未知，真实0展示0。列表和详情同口径、同asOf快照，过滤后分母明确，禁止把当前加载页作全量分母。

### 5.3 API清单与实现落点

以下是拟新增/扩展契约，复用现有路径前缀；分页、鉴权、DTO沿项目已有规范。

| API/读写 | 返回/动作 | 文件级落点 |

## 六、分类、仿真机器人与积压的具体修订

分类保留业务/应用/依赖/基础设施/网络/数据/安全七类，PLATFORM和UNCLASSIFIED拆开。分类是描述告警所属面，不预断根因；severity独立。规则按优先级和稳定ruleId裁决，多命中展示依据，未校准权重称“规则优先级/命中依据”，不展示0.93概率。人工override单独存actor/reason/revision，规则重算不覆盖人工值，提供显式撤销override。历史重分类需批次与版本，不能改写过去报表而不标记。

facet计数须说明是在当前时间/状态/服务过滤下的数量，单选主分类不能重复计数。窄屏用筛选抽屉，桌面分类栏可收起；不要为了新facet让告警主表再次变窄。

仿真聊天写面放control应用的认证域，消息归session及操作者；读真告警/当班信息只返回现有授权投影。仿真认领/静默作用于simulation状态，不触发真实CaseCommand/通知；回执写“模拟已认领”，不要用真假难分的“操作成功”。命令目标改incidentId或选择卡片，不用可能重名的告警名。提交带clientMessageId，消息与处理结果幂等，权限失败、发送失败、重试状态明确。duty-adapter保留外部探针故障域，不新增聊天数据库依赖。

积压至少分接收入箱、待调查/策略等待、已排队任务、待投递通知四类。webhook_inbox是已核对的V3表；其他告警入口需按实际Repository/迁移核对，不能把文档中的alert_inbox当同一张表。自动抑制、不适用、正在去抖的告警不一律计“未处理异常”。当前episode起点用来算本轮等待，firstSeen用于历史首次出现，不能混用。

积压深度历史需要周期快照或状态迁移事件回放；只有今天的状态不能画出昨日真实曲线。接收速率/处理速率不凭两个瞬时数量推算。未知或监测失联显示缺数，不补0让趋势看起来正常。
