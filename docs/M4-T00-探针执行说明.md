## 一、探针是什么

一个带 `main()` 的独立程序（不依赖 Spring 容器），用项目已引入的
docker-java 3.7.1（httpclient5 transport，显式 `api.version=1.44`）逐项探测
方案 T00 的 9 项清单，每项打印一行：

```text
[T00-①] PASS docker-java 连接与 API 协商 :: ping=ok serverApi=... clientApiVersion=1.44 ...
```

退出码：**任何一项 FAIL → `System.exit(1)`；全绿 → 0**。① 失败（dockerd 不可达）时
后续 ②~⑨ 无探测意义，直接中止并退出 1。

```bash
  dependency:build-classpath -Dmdep.outputFile=target/probe-cp.txt
```

### 2. 运行探针

**方式 A（推荐）：容器内跑，挂 docker.sock** ——与 Broker 真实运行形态一致
（⑦ 兄弟容器语义就是这条路径）：

```bash
cd /opt/build/pr
docker run --rm \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /opt/build/pr:/ws -v m2repo:/root/.m2 -w /ws \
  -e PROBE_BIND_SRC=/tmp/t00-probe-src \
  eclipse-temurin:21-jre \
  java -cp "sandbox-broker/target/classes:$(cat sandbox-broker/target/probe-cp.txt)" \
  com.objwww.pr.broker.selfcheck.DockerFeasibilityProbe \
  2>&1 | tee /tmp/t00-probe.log
```

执行前先备好 ② 的 bind 源目录（**宿主路径**，容器内创建的目录对 dockerd 不可见）：

```bash
mkdir -p /tmp/t00-probe-src
```

**方式 B：宿主机直跑**（仅当 195 宿主装有 JDK 21；⑥/⑧ 的 `/dev/kvm`、`/sys/fs/cgroup`
证据此时是宿主真实视图，最准确）：

```bash
cd /opt/build/pr
# probe-cp.txt 里是容器路径 /root/.m2/...；宿主直跑需先把 m2repo 卷内容导出或在宿主重建 classpath
java -cp "sandbox-broker/target/classes:<宿主本地仓库 jar 路径列表>" \
  com.objwww.pr.broker.selfcheck.DockerFeasibilityProbe
```

方式 A 下 ⑥/⑧ 的 `/dev/kvm`、`/sys/fs/cgroup` 证据反映的是容器视图，判读以
dockerd 侧证据（`info.swapLimit`）为准——探针输出里已自带这条提示。宿主
/dev/kvm 真实状态可补一条手工命令留档：`ls -l /dev/kvm; which kata-runtime`。

### 3. 可调环境变量（均有默认值，一般不用改）

| 变量 | 默认 | 含义 |
|---|---|---|
| `DOCKER_HOST` | `unix:///var/run/docker.sock` | dockerd 地址 |
| `PROBE_API_VERSION` | `1.44` | 显式协商的 API 版本（与 BrokerConfig 一致） |
| `PROBE_IMAGE` | `eclipse-temurin:21-jre` | Job 候选基础镜像（INC-09 实测可跑默认 seccomp 的族） |
| `PROBE_BIND_SRC` | 现场临时目录 | ② 只读 bind 的**宿主**源目录（容器内跑探针时必须显式指定） |

镜像不在本地时探针会先 pull（一次性前置；运行期禁 pull 是 Job 剖面纪律，与 T00 探针无关）。
