# 告警 EV-08 数据集与人工评审（后端）v1

方案锚：`docs/告警-评测中心与能力版本演进-审查及详细改造方案-v1.md` EV-08 卡 /
§3.6 数据集与人工评审 / §5.3 API 清单（"GET/POST /api/eval/reviews/... 队列、领取、
CAS 提交——独立评审记录与 rubric 版本，不覆盖原机器评分"）。迁移 **V87**
（号段：V80~V83、V85、V86 占用，V84 空置声明）。

## 1. 交付范围

- **数据集读面增强**：列表/详情投影——名称/版本/来源/分区身份/案例计数
  （HOLDOUT 分区只出计数与元数据，GT 原文永不进投影）+ rubric 版本随数据集透出。
- **评审任务模型**（V87 两表）：`review_assignment`（run/case 引用、评审人 actor、
  状态 PENDING/IN_PROGRESS/SUBMITTED、有界租约、revision CAS 锚）+
  `review_verdict`（insert-only：评分/标签/理由、冻结 rubric 版本、提交时刻）。
- **命令面**：领取（服务器 CAS + 幂等重放）、提交评分（rubric 必带/理由必填/
  提交后不可改）、任务生成（ensure 幂等）。
- **盲评**：HOLDOUT 案例只给症状与系统输出，不给 GT 答案。
- **分歧与重评分**：同案例两评审结论不一致清单；重评分 = 新任务 + 新行，
  旧行永不覆盖。
- **读面**：任务列表（我的/全部）、run 级进度分桶（已评/待评/进行/分歧）。

## 2. 迁移 V87（`V87__ev08_eval_review.sql`）

- `review_assignment`：状态-字段形状 CHECK 三态双向钉死（V86 同律）；revision
  CAS 锚；`uq_review_assignment_active_reviewer` 部分唯一索引——同一评审人对同一
  案例至多一条进行中任务（双份评派给不同人）；
  `uq_review_assignment_id_run_case` 复合唯一 = 结论表三列冗余直挂的 FK 目标
  （V21 冗余列复合 FK 同构）。
- `review_verdict`：**insert-only**（control_app 只授 select,insert，接口层无
  update/delete 方法面）；`uq(assignment_id)` 一任务一结论；verdict 封闭值域
  `CORRECT/PARTIAL/INCORRECT/UNDECIDABLE/INSUFFICIENT_SOURCE`（"无法判定/来源
  不足"是一等结论，§3.6 不强行二选一）；reason 去空白非空 CHECK；score 1..5 可空。
- **授权**（V85/V86 同律）：control_app 对 `review_assignment` = select,insert +
  **列级 update 六列**（reviewer/status/revision/claimed_at/lease_expires_at/
  submitted_at——run_id/case_execution_id/created_by 落档后不可改）；
  `review_verdict` = select,insert；eval_app/publisher/notify/arena/chaos/public
  显式 revoke 归零。
- **HOLDOUT 计数针孔**：`case_version_partition_counts()`（security definer，
  `search_path` 钉死）——case_version 有 RLS（V21/V45），control_app 连 HOLDOUT
  行数都拿不到；函数只出 `(dataset_version_id, partition_class, count)` 聚合三列，
  案例行内容与 GT 原文永不经过此面；execute 只授 control_app。

## 3. 端点契约

全部挂在 `/api/eval/**`（ROLE_OPERATOR 既有矩阵）；actor 唯一来源 =
AuthenticatedActor，请求体不自报；400/404/409 应答沿用 `{"error": ...}` 惯例。

| 端点 | 语义 |
|---|---|
| `POST /api/eval/runs/{runId}/review-assignments` | 任务生成。body `{caseExecutionIds?, assignmentsPerCase?}`（默认 1，双人评审 = 2，上限 4）。ensure 幂等：每案例补足 N 份开放任务（PENDING + 租约有效的 IN_PROGRESS 计开放），重复调用补 0。run 未知 404；外来 caseExecutionId / perCase 越界 400。201 `{created, openTotal, perCase}` |
| `POST /api/eval/reviews/assignments/{id}/claim` | 领取。单行条件 UPDATE CAS（谓词 = PENDING 或 IN_PROGRESS 且租约超时）——行数 1 赢 / 0 重读归因。200 `{claimed:true, replayed:false, assignment}`；同人持有效租约重领 200 `{replayed:true}`（幂等）；他人持有效租约 409 CONFLICT_HELD；已提交 409 CONFLICT_SUBMITTED；同人对同案例已有另一份进行中任务 409 CONFLICT_SELF_ACTIVE（uq 兜底）。租约 30 分钟 |
| `POST /api/eval/reviews/assignments/{id}/submit` | 提交评分。body `{rubricVersion, verdict, score?, labels?, reason, evidenceRefs?, expectedRevision}`。rubricVersion 必带且须在注册表（未知 400，不自造版本锚）；reason 必填 400；expectedRevision 必带（CAS 锚）。CAS 四锚（id+reviewer+IN_PROGRESS+revision）。201 `{verdictId, revision}`；409 CONFLICT_STATE/CONFLICT_REVISION（租约被回收重领后旧持有者提交必撞）/CONFLICT_ACTOR/CONFLICT_DUPLICATE。提交后不可改 |
| `GET /api/eval/reviews/assignments?runId&scope&status&cursor&limit` | 任务列表。scope=mine（默认）/all；status 按**有效状态**过滤（租约超时的 IN_PROGRESS 如实 PENDING——惰性回收投影，存储列原样携带）；键集游标 `<createdAt>/<assignmentId>`，limit ≤200。runId 必填，未知 404 |
| `GET /api/eval/reviews/assignments/{id}` | 单例工作区：任务 + 盲评案例投影 + 本案例结论历史（重评分全留档）。未知 404 |
| `GET /api/eval/runs/{runId}/review-progress` | 进度分桶：caseCount/totalAssignments/pending/inProgress/submitted/reviewedCases/disagreementCases（原始计数，如实零） |
| `GET /api/eval/reviews/disagreements?runId` | 分歧清单：同案例 ≥2 名评审，取每人**最新**结论行，verdict 或 score 不一致即入列（重评分新行自然取代旧行参与判定） |
| `GET /api/eval/datasets` | （增强）列表项新增 name/sourceClass/partitionClass/partitionCounts（含 HOLDOUT 真实计数）/rubricVersion（当前生效评分细则）；旧字段 version/source/caseCount/families/createdAt 原样保留——caseCount 仍是 RLS 可见行计数，partitionCounts 才是全分区计数 |
| `GET /api/eval/datasets/{name}/{version}` | （新增）详情：列表项全量 + knownRubricVersions（冻结版本全表）。name+version 精确键（uq 天然唯一），未知 404 |

## 4. 盲评边界（EU31 / EV-05 裁定同律）

- 案例身份经 case_version 精确键解析（`dataset_version.version` + `case_key`）；
  **HOLDOUT 行 RLS 不可见 → 解析缺席 → blind=true**（解析命中但分区 HOLDOUT 的
  防御分支同判 blind）。
- blind=true 时投影**只给症状与系统输出**：actualRootCause 摘要 /
  actualSymptomCodes / failureSample / machineVerdict / latencyMs / 报告人读摘要
  （系统输出面，可见）。**GT 三字段恒 null**：expectedRootCause /
  expectedSymptomCodes / rootCauseHit。
- 非 HOLDOUT（身份可见且分区非 HOLDOUT）→ blind=false，GT 透出。
- case_version.payload（GT 原始 artifact）不进任何投影（EV-05 裁定不变）；
  数据集面 HOLDOUT 只出计数与元数据（§2 针孔）。

## 5. rubric 版本

- `eval-rubrics.yml` 随 jar 封装（classpath；DrillTemplateCatalog 同律白名单装载，
  current 恰一条、版本锚唯一 fail-loud）。当前版本 `eval-review-rubric-v1`。
- 冻结语义：评审提交把 rubric_version 钉死在 review_verdict 行；rubric 变更 =
  注册表新增一行新版本，旧版本行永不改写（已落档行的版本锚永远可解析）。
- 数据集列表/详情透出当前版本与已知版本全表。

## 6. EU 用例逐条状态（EV-08 相关）

| 用例 | 状态 | 证据 |
|---|---|---|
| EU29 两人同时领取/提交评审（CAS、租约、版本冲突，保留审计） | ✅ 后端已实现 | 领取单行 CAS 只一人赢（单测 claimCasSingleWinner + IT NOT_RUN）；同人重领幂等 REPLAYED；提交 revision 四锚，租约回收重领后旧提交必撞 409（submitConflictsOnActorAndRevision）；全程 revision/审计列留痕 |
| EU30 judge 异常或与人工分歧（重评分不重跑故障） | ◐ 本卡覆盖"重评分"半面 | 重评分 = 新 review_assignment + 新 review_verdict 行，不触碰 eval_case_result 机器评分、不重触发故障（rescoreIsNewRowNeverOverwrite）；SCORER_ERROR/ judge 异常面属评分器侧，不在本卡 |
| EU31 猜 HOLDOUT ID（API 隔离，不只隐藏按钮） | ✅ 盲评边界 | 工作区投影 blind 判定 = RLS 解析缺席；GT 三字段恒 null（workspaceBlindProjectionHidesGt）；数据集面 HOLDOUT 只出计数（IT NOT_RUN 验证 RLS 0 行 + 针孔计数） |
| §3.6 机器分/人工分/分歧分别保留 | ✅ | 机器评分列不触碰；review_verdict insert-only；分歧清单独立读面 |
| §3.6 复核裁决（人工也会误判） | ✅ 机制具备 | 重评分新行 + 结论历史全留档（workspace verdictHistory）；裁决本身 = 再一轮评审任务 |

## 7. 偏差与未做项

1. **草稿面未交付**：方案 §3.6"草稿与最终提交分开"——本卡提交一次性完成，
   无草稿存储面。前端工作区需草稿时另起小卡（表或会话存储均可）。
2. **租约回收惰性化**（任务卡授权"选简单可靠的"）：无 worker 无定时任务——
   读面投影与领取谓词双路判定超时租约；不产生回收事件行（审计靠 revision 与
   claimed_at 序列）。方案原文未强制回收面形态。
3. **rubric 注册表 = classpath YAML，非 DB 表**：冻结版本锚语义等价（变更 =
   新版本行）；运行期不可改正是"冻结"的兑现。DB 化留待多团队自服务需求出现。
4. **任务生成 ensure 幂等取代幂等键**：生成是"补足 N 份开放任务"的收敛式语义，
   重复调用天然零副作用，故未引入 idempotencyKey（与 EU09 不同面：生成不产生
   异计划冲突面）。
5. **案例预览/版本 diff/切片覆盖/泄漏风险展示**（方案 §3.6 数据集详情段）
   未在本卡交付——EV-08 卡面只要求名称/版本/案例计数 + rubric 透出；diff 依赖
   跨版本 payload 比较面，另卡。
6. **IT 全部 NOT_RUN**（本机无 Docker）：`PostgresEvalReviewIT` 4 例（领取/提交
   CAS、insert-only、授权矩阵、HOLDOUT 针孔）待真 PG 环境执行；迁移 V87 的
   CHECK/索引/授权同样待 IT 验证。
