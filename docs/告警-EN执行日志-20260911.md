## 三、EN-02 发布资格（§8.2 评测证明契约 + §九撤权语义）

**范围**（对照卡行：发布资格记录、激活/回滚统一资格门；关联用例 E05/S09、P06/P07/P11）：

- `ReleaseQualification`（证明行）：candidate/baseline digest（FK 钉已发布面）、
  dataset_manifest_digest、runner/grader 版本、quality_verdict（PASS/FAIL/INCONCLUSIVE）、
  usage_status（MATCHED/MISMATCH/UNKNOWN——**只入账不入门**，E05/S09）、granted_scope/by/at、
  撤销三件套（revoked_at/by/reason 要么全空要么全在，域构造 + DB CHECK 双面钉）。
- `ConfigBundleService.activate/rollback` **统一过资格门**（P11：回滚不得绕过有效性）：
  fail-fast 预检（QUALIFICATION_ABSENT / QUALITY_NOT_PASS(verdict) 原因码）+ 事务内权威重验
  （仓储语句级 EXISTS 为第二道）。
- `expectedActiveRevision` 由客户端显式携带（0 = 从未激活；服务端**不替用户推算预期**，
  P06）；重复激活当前 digest = 幂等重放，先于资格门（在位指针不被追溯降级，§九）。
- `activateQualified`（仓储）：FOR UPDATE 锁资格行（P07——激活与撤销同行互斥）→
  revision CAS UPDATE（含 EXISTS 子查询资格重验）→ moved 才落 change_event（EX-B1 同律）。
- 授予/撤销服务面（`grantQualification` 返回 proof id / `revokeQualification` 仅写撤销三列）；
  **HTTP 授予端点归 EN-09/EN-10**，本卡只立服务契约。
- `release_qualification` 表（V61）：candidate/baseline FK→config_bundle、verdict/usage
  CHECK、撤销三件套 CHECK、candidate 索引、control_app 授 select,insert,update（撤销=
  UPDATE 三列）、delete 零授、他角色 revoke all。
- 不做（越界推迟）：评测执行本身（EV 线面）、资格 HTTP 端点（EN-09/10）、
  自动重评/降级在位指针（§九明令禁止）。
