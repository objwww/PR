## 一、这个项目是什么

**AI Code Review Agent**：监听 GitHub PR webhook，用 LLM 自动评审代码，把结论写回 GitHub
（Check run + PR Review）。按支付系统标准设计：评论不能重复发、崩溃后要能恢复、
旧代码的结论不能写到新 commit 上。

架构双进程（DDD 四层，Java 21 + Spring Boot + Spring AI，Maven 多模块）：

- **control-app**：收 webhook（HMAC 验签 → 落 webhook_inbox → 202）、InboxProcessor
  异步处理、下载代码快照、调模型、把"要写 GitHub 的意图"存进 outbox_command 表。
  **物理上不能写 GitHub**（无写凭证、DB 角色也只准 INSERT）。
- **publisher-app**：全系统唯一写出口，从 outbox 领命令、过 fence 校验、调 GitHub 写 API；
  另跑 DriftReconciler（只检测不修复）。
- **shared-kernel**：纯枚举/值对象，零框架依赖。
- **PostgreSQL**：唯一状态源（inbox/outbox/账本/投影全在库里；无 Redis、无 MQ）。

代码仓库：`https://github.com/objwww/PR.git`（本系统）。评审对象仓库：
`https://github.com/objwww/mall_R`（真实联调用，GitHub App 装在 objwww 全部仓库）。

### 146.56.195.225（部署/构建/测试机，下称 195）

- 登录：`ssh -i ~/.ssh/id_ed25519 root@146.56.195.225`
- **运行中的栈**：`/opt/build/pr/deploy`（docker compose，项目名前缀 `deploy-`），四容器：
  | 容器 | 作用 | 端口 |
  |---|---|---|
  | `deploy-control-app-1` | control-app | webhook `127.0.0.1:8080`（stub 模式） |
  | `deploy-publisher-app-1` | publisher-app | 无端口发布 |
  | `deploy-postgres-1` | PostgreSQL 16 | 仅栈内 |
  | `deploy-github-stub-1` | GitHub stub（WireMock 3.13） | admin `127.0.0.1:19090` |
- **当前模式：stub 模式**（`GITHUB_API_BASE=http://github-stub:8080`，
  `GITHUB_INSTALLATION_ID=555000`）。**业务表已清空**（flyway_schema_history 保留，
  迁移版本 V1+V2+V3）。
- **数据库**：库名 `pr_agent`（不是 postgres）。查账（必须 `-i`）：
  `docker exec -i deploy-postgres-1 psql -U postgres -d pr_agent`
- **构建现场**：`/opt/build/pr`；在 195 跑全量测试（含 IT，必须挂 docker.sock）：
  ```bash
  docker run --rm -v /opt/build/pr:/workspace -v m2repo:/root/.m2 \
    -v /var/run/docker.sock:/var/run/docker.sock -w /workspace \
    maven:3.9-eclipse-temurin-21 mvn -s maven-settings-aliyun.xml verify
  ```
- **配置与密钥**：
  - 持久配置 `/opt/projects/pr_agent/.env`（**不得打印、不得外泄**）；
    模式备份：`/opt/projects/pr_agent/.env.stub.bak`（stub）、`.env.realmode.bak`（真实），
    互切 = 复制对应备份覆盖 `.env` 后 `docker compose up -d --force-recreate control-app publisher-app`。
  - GitHub App 私钥两份挂载点：`/opt/projects/pr_agent/keys/github-app-key.pem`（主）与
    `/opt/build/pr/deploy/keys/github-app-key.pem`（compose secret 源，0444）。
    **不得复制到别处、不得覆盖、不得删除**。
  - 真实模式辅助脚本 `/opt/projects/pr_agent/gh-api.sh`（App JWT→installation token→REST，
    只能从 `/opt/projects/pr_agent` 目录执行）。
- **宿主机怪癖**：内核 3.10 → postgres 容器需 `seccomp:unconfined`（已在 compose 里，INC-09）；
  宿主机 JDK 17 不参与运行，应用全部容器化。
- **stub 已知保真度局限**：① 不建模权限（stub 下权限类用例只能查 DB 授权矩阵）；
  ② probe-list 恒空 → RECONCILING 命令在 stub 下会重发（真实 GitHub 下可认领已建资源）；
  ③ stub journal 清零用 `DELETE /__admin/requests`（WireMock 3，不是 2 代的 POST reset）。

## 五、出问题时看什么（自查顺序）

1. 容器日志：`docker logs deploy-control-app-1 --tail 200` / `deploy-publisher-app-1`
2. 收件箱：`SELECT delivery_id, github_action, state, attempt_count, last_error FROM webhook_inbox ORDER BY received_at DESC LIMIT 10;`
3. 账本：`SELECT event_type, payload, occurred_at FROM execution_event ORDER BY position DESC LIMIT 20;`
4. 发件箱：`SELECT command_type, state, aggregate_sequence, publication_epoch, last_error_code FROM outbox_command ORDER BY created_at DESC LIMIT 10;`
5. 投影：`SELECT repository_full_name, pr_number, state, draft, publication_epoch FROM pr_subject;`
