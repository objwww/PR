EV-05 卡执行记录（方案依据：告警-评测中心与能力版本演进-审查及详细改造方案-v1.md
EV-05 任务卡 / §3.4 案例详情 / §5.3 API 清单第四行与末行 / EU27/EU28/EU31）。
分支 ev/eval-center；**无新迁移**（纯读面，全部读表已有 control_app SELECT 授权，

## 1. 端点契约

全 GET、零写面，挂 /api/eval/** 矩阵（ROLE_OPERATOR，SecurityConfig 既有规则，
/api/v1/** 同式）；400/404 应答沿 {"error": ...} 惯例。

| 端点 | 参数 | 应答 |
|---|---|---|
| GET /api/eval/runs/{runId}/cases/{caseExecutionId} | 双路径键（UUID） | 200 案例详情投影；UUID 非法 400；runId+caseExecutionId 双键定位不到（含跨 run 猜 id）404 |
| GET /api/eval/runs/{runId}/evidence-summary | runId | 200 Run 证据汇总（按案例分组）；未知 run 404 |
| GET /api/eval/log-compare?baselineRunId=&candidateRunId=&scenarioId= | 恰三参数 | 200 受限日志比较；参数缺/非法/两 run 相同 400；任一 run 未知 404 |

### 1.1 案例详情（EvalCaseDetailResponse）

```
{ caseExecutionId, runId, scenarioId, roundNo, selectionPolicyVersion,
  verdict, rootCauseHit, expectedRootCause, actualRootCause,
  expectedSymptomCodes[], actualSymptomCodes[], tp, fp, fn, latencyMs,
  silencePenalty, failureSample, createdAt,
  scenarioIdentity: { scenarioId, datasetVersion, resolved,
                      caseKey, scenarioFamilyId, contentDigest, partitionClass,
                      datasetName, sourceClass, validFrom, validTo },
  linkage: { rcaRunId, rcaRunState, incidentId, rcaStartedAt, rcaFinishedAt,
             scoredAttemptId, scoredReportId, reportSchemaVersion,
             reportValidationStatus, reportModel, reportCreatedAt },
  report:  { summary, impact, remediation, references[] } | null,
  evidence: { status, supporting[], refuting[], undetermined[] },
  asOf }
```

- `evidence.status` ∈ `OK` / `NO_REPORT`（verdict 形态决定无评分报告——
  STRUCTURE_REJECTED/TIMEOUT_OR_ABSENT 沿 V10 约束必无 scored_report_id）/
  `UNSUPPORTED_SCHEMA_VERSION`（非 v2 包不猜结构）/ `PACKAGE_UNPARSEABLE`
  （写期已验证的包读回形状校验失败，显式标记不当空吞）。
- 支持/反对/未决 = ReportClaim.status TRUE/FALSE/UNKNOWN 三态直分，每断言带
  `refs[]`：`{ref, resolved, evidenceId, evidenceType, source, timeStart, timeEnd,
  payloadDigest}`。`resolved=true` 的唯一条件：ref 是 UUID 形态 **且** 该证据行
  属于本案例 rcaRunId（`listEvidenceMeta` run+id 白名单双约束）——跨对象引用
  一律 resolved=false 且元数据全 null（§3.4 禁止凭任意 evidenceId 跨对象读取）。
- `scenarioIdentity.resolved=false` 三种真实成因：精确键无匹配、多 dataset 同
  version 命中同一 case_key（归属歧义，不取"最新"冒充）、HOLDOUT 行对
  control_app RLS 不可见（GT 封存面不因投影开口）。resolved=false 时身份字段
  全 null，datasetVersion 恒为 run 直读值。

### 1.2 Run 证据汇总（RunEvidenceSummaryResponse）

```
{ runId, caseCount, casesWithReport, totalRefs, byType{type:count},
  cases: [ { caseExecutionId, scenarioId, roundNo, verdict, rcaRunId,
             scoredReportId, status, totalRefs, resolvedRefs, unresolvedRefs,
             byType{type:count}, supportingRefs, refutingRefs,
             undeterminedRefs } ],
  asOf }
```

- 案例级 `status` ∈ `OK` / `NO_REFS`（有报告但零引用，真实 0）/ `NO_REPORT`
  （如实区分"无统计对象"与"统计为 0"，沿 EV-03 三件套诚实惯例）。
- 单 SQL 扁平抽取（jsonb 只抽 claims 的 status/claim_type/evidence_refs 小字段，
  不上抛 package 大文本；§5.3 不 N+1），分桶装配在应用服务纯函数段。

### 1.3 受限日志比较（EvalLogCompareResponse）

```
{ scenarioId, baselineRunId, candidateRunId,
  compareStatus: OK | NO_LOG_EVIDENCE,
  rounds: [ { roundNo, baseline: CaseLogSummary|null,
              candidate: CaseLogSummary|null, diff: Diff|null } ],
  asOf }

CaseLogSummary = { caseExecutionId, roundNo, rcaRunId, evidenceCount,
                   totalLines, errorLines, truncated, unparseableEvidence,
                   services[], scopeTimeRange, windowStart, windowEnd,
                   topSignatures[{signature,count}] }   // top 20
Diff = { onlyInBaseline[], onlyInCandidate[], increased[], decreased[],
         unchanged }                                    // 各桶 top 20
```

- **受限面**：只收 baselineRunId/candidateRunId/scenarioId 三参数；时间窗
  （windowStart/windowEnd = 证据行内日志行 ts 极值，scopeTimeRange = 证据
  scope 原文）与服务集合（services）全部自案例关联的冻结 logs.query 证据行
  取——**不接受自由查询参数、不发新 Loki 查询**（新查询面见 §5 偏差）。
- 错误特征 = 错误行（error/exception/fatal/panic/severe/traceback 大小写不敏感
  子串，召回优先以覆盖 NullPointerException 驼峰形态）归一化签名分桶
  （去 ISO 时间戳/UUID/hex/数字动态段，截 160 字符；每证据最多扫 2000 行、
  每侧 200 签名上限——双层有界闸）。
- 同 roundNo 配对（uq(run,scenario,round) 保证唯一案例）；任一侧缺席 →
  diff=null（如实"不可比"，不拿空桶冒充）；两侧全程零证据 →
  compareStatus=NO_LOG_EVIDENCE（事实空，与"未统计"区分）。
- payload 形状不符 → unparseableEvidence 显式计数，不吞；源侧截断/读面
  扫描闸截断 → truncated=true。
- 日志原文行不出本读面（只出签名桶与计数）；原始快照内容访问仍属 AM4 证据
  仓储既有面。

## 2. 字段来源表

| 投影字段 | 来源表/列 | 说明 |
|---|---|---|
| caseExecutionId / verdict / rootCauseHit / tp/fp/fn / latencyMs / silencePenalty / failureSample / createdAt | eval_case_result 直读 | EV-03 已冻结身份口径 |

| datasetVersion | eval_run.dataset_version（详情 SQL join eval_run） | 场景身份解析输入 |
| scenarioIdentity.* | case_version ⋈ dataset_version（dv.version + cv.case_key 精确键匹配） | 多命中歧义/无匹配/RLS 不可见 → resolved=false |
| linkage.rca* / linkage.report* | rca_run / rca_report 外键直读（left join） | 环节缺席如实 null |
| report.* | rca_report.package_json（v2 形状校验后的人读段） | 校验失败如实 null |

## 4. 迁移与授权

**无新迁移**。理由（逐表核对既有授权）：

- eval_run / eval_case_result / dataset_version / case_version：V45 已授
  control_app SELECT（case_version 另有 V45 select 策略，HOLDOUT 恒不可见——
  正是 GT 权限边界要求的形态，不绕）；
- rca_run / rca_report：V7 已授 control_app SELECT；
- rca_evidence：V16 已授 control_app SELECT。

V84 号段因此保持空置，留给下一需要写面/新表的卡。R7（V46+）/EN（V60+）
号段未触碰。

## 5. 偏差与未做项

1. **受限日志比较降级为冻结证据投影**：方案字面允许"复用现有日志查询面做
   受限只读投影（时间窗+服务白名单从案例上下文取）"。现实是 LogQueryExecutor
   是 Agent 工具执行器（真查 Loki），在 HTTP 读面发新查询需要查询成本限流与
   "快照 vs 新观察"分离的完整产品面（§3.4"查看当前数据源"另开查询）——
   本卡只做冻结 logs.query 证据的比较投影（时间窗/服务自证据行取），
   **实时 Loki 新查询比较 = NOT_IMPLEMENTED**，待证据/日志读面限流卡。
2. **digest 只携带不重算**：AM4 的读路径重算比对（防篡改五步）在
   EvidenceRepository.findById；本读面走 JdbcClient 直读只带 payload_digest
   值，不做重算（元数据投影非字节回读面）。如需投影面自带篡改检测，
   属后续加固项。
3. **GT 权限**：case_version.payload（GT 原始 artifact）不进任何投影字段，
   只投影身份/digest/分区元数据；HOLDOUT 封存靠 V21/V45 RLS 双策略
   （eval_app 与 control_app 同谓词 partition_class <> 'HOLDOUT'），应用层不绕。
4. **场景身份映射是声明式精确键**（dv.version + case_key），不是 FK——
   M3 注册表驱动线（eval-scenarios.yml）的 scenarioId 不在 case_version 内，
   此类案例 resolved=false 如实显示，不按时间/名称猜测归属。
5. **截断/脱敏标记**：源侧 truncated 只在 logs.query payload 内（日志比较面
   已透出）；证据级统一截断/脱敏列不存在，详情面未编造该标记。
