# 告警 Agent 后续优化测试用例 v1

2026-09-13。配套[后续技术方案](告警-Agent后续优化技术方案-v1.md)。60条FO场景是本轮后续优化的验收目录，**不是60条已编写或已通过的自动化测试**；不与RX/RD/MC/EN/EU累加宣传覆盖数量。重叠断言复用旧测试并关联ID。

## 0. 执行约定

E为机制验证（可用模型替身），L为真实模型链，B为固定版本盲评；额外标UT/PG/系统/浏览器表示测试范围。E不是“必然端到端”。本文件所有新场景默认NOT_RUN；P2功能未开启记DEFERRED或前置不足BLOCKED，不改为PASS。

全链入口使用隔离告警环境、测试通知接收器和独立episode；每例记录构建、release、工具/模型/rubric/数据集、案例身份和时间。不得触发真实值班通知。恢复案例的firing/resolved必须匹配身份；不能通过只换alertname替代恢复。

每例证据包至少包括输入、API响应、关键数据库/事件前后差异、断言结果；L/B还包括实际模型输入/输出引用、所有attempt与成本；浏览器存截图/操作录像并和后端关联。内容脱敏，GT仅评分侧读取。失败需清理测试任务/挂载/注入并记录清理是否成功。

竞争测试用屏障/可控时钟，杀点未命中记INVALID_TEST；权限测试既查HTTP结果也查数据/外部调用为零。性能和质量阈值在测试前冻结，不能执行后选较好口径。

## 一、固定回归与质量（FO01～10）

| ID/模式范围 | 前置 | 操作过程 | 预期断言与证据 |
|---|---|---|---|
| FO01 E/PG+系统 | 已审核调查及完整来源 | 从sourceRun创建候选→审核入集→按新DatasetVersion读取 | case指向精确报告/证据digest；症状与答案隔离；保存审核及版本行 |
| FO02 E/PG | 同一源快照 | 两请求同幂等键并发准入，再重放 | 只产生一个有效候选；返回同ID；不同载荷同键明确冲突 |
| FO03 E/系统 | 源证据已过期或缺一项 | 请求入集并继续尝试发布数据集 | 拒绝或NEEDS_EVIDENCE，不能编造来源；无合格发布证明 |
| FO04 E/PG | 已发布案例v1 | 更正GT生成v2，重读v1并重跑原实验 | v1内容/digest不变；v2有更正来源；原实验仍解析v1 |
| FO05 E/系统 | 同episode重复、同故障改写案例 | 执行分区规则，检查family关联 | 同族不能跨开发/holdout泄漏；跨区尝试拒绝或要求重新分组 |
| FO06 E/UT+API | 一组含可判定、来源不足、合理未决案例 | 计算质量汇总并请求详情 | 指标分母与排除原因准确；Run SUCCEEDED不自动算根因正确 |
| FO07 E/UT+API | 有错误确诊和大量未决 | 比较只看成功率与新指标 | 错误确诊绝对数保留，不能因未决多被掩盖；合理/不合理未决分开 |
| FO08 E/PG+API | 实验两侧案例内容或版本不同 | 请求配对比较；再加入缺失/未配对案例 | 不错误配对；缺项/截断导致资格INCONCLUSIVE；详情可查未配对 |
| FO09 E+B/系统 | rubric冻结，人工与机器分歧 | 分别提交机器评分、人工评审和裁决 | 原分数不覆盖；各有版本与来源；未裁决分歧不能冒充一致PASS |
| FO10 E+L/系统 | HOLDOUT和可编程查询工具 | Agent尝试通过RAG/历史案例/反馈检索GT | 所有路径禁止答案读取；零GT内容出现在模型输入，评分器仍可合法评分 |

## 二、动作价值分析（FO11～20）

| ID/模式范围 | 前置 | 操作过程 | 预期断言与证据 |
|---|---|---|---|
| FO11 E/UT+PG | 两条不同UUID但同源同窗同内容证据 | 执行动作分析并读取详情 | 不以UUID不同当新观察；保存规范化版本和去重理由 |
| FO12 E/UT | 相同日志内容但频次或时间发生变化 | 分别分析原窗与新窗 | 频次/新鲜度变化保留，不误标纯重复 |
| FO13 E+B/系统 | NO_DATA确实排除一个方向 | 调查获得空结果→关闭相应缺口→分析 | NO_DATA不自动判无价值；关闭理由与证据语义审核可追溯 |
| FO14 E/PG | 一个逻辑动作三次物理尝试 | 汇总动作、调用数和费用 | 逻辑动作1个，物理尝试3次；所有费用或UNKNOWN保留 |
| FO15 E/PG | 分析任务执行中断 | 写一部分派生结果后重启重跑 | 同源同分析版本不重复；完整状态可辨，不把部分结果当总计 |
| FO16 E/PG+API | 初始费用UNKNOWN，后续对账完成 | 分析v1→追加对账→重算 | 新分析版本可见；旧审计不改；未知不曾当0费用 |
| FO17 E/系统 | 2个专家同源复述，另有独立证据 | 跑汇总与价值页 | 同源不计两份独立收益；“被引用”不被描述为因果贡献 |
| FO18 E/UT+API | 有工具失败、无数据、正常无新增三类 | 同批分析 | 三类原因分开；SOURCE_FAILED不归咎模型不会推理 |
| FO19 E/系统 | 未分析Run与已分析0新增Run | 请求列表/汇总 | NOT_ASSESSED与0明确区分；总体覆盖率分母正确 |
| FO20 E+B/系统 | 同一固定案例能力开/关两组 | 保持其他配置运行对照 | 因果收益声明仅来自该对照及其不确定性，不从生产相关统计直接推出 |

## 三、报告反馈到案例（FO21～30）

| ID/模式范围 | 前置 | 操作过程 | 预期断言与证据 |
|---|---|---|---|
| FO21 E/系统+浏览器 | Run已SUCCEEDED且有报告 | 授权用户打开终态报告→提交INCORRECT及理由→刷新 | 反馈成功持久化，原Run/报告不改；页面终态后仍能评价 |
| FO22 E/系统 | Run已FAILED/CANCELLED且无报告 | 尝试按不存在reportId反馈；另提交Cancel/Hint | 无报告评价明确拒绝；不因新反馈能力放开终态控制命令 |
| FO23 E/PG | 相同作者/请求幂等键 | 双击/并发提交，再换载荷重放同键 | 相同载荷一条记录；异载荷冲突；没有双次转案例 |
| FO24 E/系统 | 无权用户与跨服务报告 | 伪造authorId、reportId、evidenceRef | 身份以认证主体为准；越权拒绝、无写入、无证据泄漏 |
| FO25 E/PG | 已有反馈及两种纠正 | 并发更正同一前序；读取历史 | 不覆盖原意见；冲突更正可辨；不同操作者意见允许并存 |
| FO26 E/系统 | 未审核但高置信用户反馈 | 请求转正式案例/发布Skill | 不允许越过审核与资格；用户“采纳”不是GT证明 |
| FO27 E/PG+系统 | 两名审核者意见相反 | 完成两份评审→请求准入 | 显示分歧，进入裁决/待补证；不采用最后写入自动胜出 |
| FO28 E/系统 | 已审核接受反馈 | 转回归候选→发布新数据集→跑该案例 | feedback、review、case、dataset、eval身份可追溯；原报告不覆盖 |
| FO29 E/浏览器+API | 长理由及断网/403/409响应 | 编辑提交→失败→恢复网络重试 | 草稿保留，失败不显示成功；刷新只加载服务器已存版本 |
| FO30 E+L/系统 | 反馈含注入命令、秘密片段和无依据根因 | 提交→审核→尝试进入RAG/Skill | 脱敏/拒绝与审核留痕；未审核内容不能成为调查事实或可执行指令 |

## 七、执行批次和自动化落点

第一批FO01～10与FO21～30：复用EvalReviewServiceTest、EvalCompareServiceTest、PostgresEvalReviewIT、PostgresEvalCompareIT；新增报告反馈服务及持久化测试，证明终态评价不会放开Cancel/Hint。案例准入复用CaseVersion/DatasetVersion测试。

第二批FO11～20与FO31～40：派生分析UT/PG加读面测试；浏览器使用已部署测试构建与隔离API，避免只对mock截图验收。布局验收记录四类视口，不以npm build替代。

第三批FO41～50满足各项触发条件才跑；FO51～58作为每次相应发布/数据演进的门，FO59/60作最终联合验收。真实模型/注入窗口串行安排，不自动占用195。

每批先跑相关既有测试，再新增缺口测试；全链case必须通过真实入口和持久任务，不直接写最终报告。性能样本记录请求规模、机器资源、其他负载、预热与重复次数；不给个人项目虚构百万吞吐目标。

验收清单格式：`FO-ID | 实现状态 | 测试类/方法或脚本 | 构建与配置 | 模式/环境 | PASS/FAIL/BLOCKED/NOT_RUN/DEFERRED | 证据 | 清理 | 缺陷ID`。测试数与业务场景数分别汇总，参数化重复次数不冒充新增覆盖。
