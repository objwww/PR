## 1. 背景简报（M2 是什么 / 栈现状 / 首跑警告）

**M2 三大能力**（详见 `docs/M2-技术方案.md`，执行不必通读，矩阵条目自带回指）：

1. **断点续跑 checkpoint**：模型产出（findings JSON + 模型原文）落 CAS 并登记
   `step_checkpoint`；崩溃/租约丢失后下一 attempt 凭五分量契约 digest 复用，
   零模型重调。复用判定 fail-closed：任一校验不过 = 丢弃重跑。
2. **Drift 修复闭环**：DriftReconciler 检出 MISSING 后铸 `repair_request`
   （CHECK_RUN→AUTO 自动修复 / REVIEW→MANUAL 人工审批），RepairPlanner 按
   "最新 CONFIRMED 期望终态"铸修复命令，修复全程过既有 fence/级联语义。
3. **精确 Retry-After**：429/限流 403 按服务端 `Retry-After`/`x-ratelimit-reset`
   精确退避（无头 429 下限 60s、clamp 15min），防 GitHub 二级限流封禁。

**栈现状与首跑警告（重要）**：

- 首轮（v1.0）已完成部署与阶段 A 首跑，195 栈已是 **V4 schema + M2 代码（修复前）**；
  第二轮因 TB-08/09/10 修复有代码变更，**必须重做阶段 0**（tar 同步会重建构建现场，
  符号链接须按 §3 阶段 0 恢复）。
- 首轮基线已建：surefire 541（101/301/139 全绿）+ IT 121（control 52 / publisher 69，
  1 skipped=CT-05，3 败 = TB-08/09/10 已修）。第二轮对照该基线，预期 IT 全绿。
- **栈级关键语义（M2 断言的前置知识）**：静态 stub 的探针恒回空列表，在 M2 语义下
  等价于"远端对象已删"。**每个测试 PR 在 CONFIRMED 后必须经
  `m2_register_pr_resources`（`deploy/m2-lib.sh`）注入"探针可见"运行时映射**，
  否则 DriftReconciler 首轮巡检就会把刚发布的资源当 MISSING 铸 repair 单，
  污染本批次断言。全部 M2 脚本已内建该调用；手工演练（如复现取证）同理必须注册，
  复原 = 摘除映射（脚本 `trap m2_cleanup EXIT` 兜底）。
