## 一、压缩结论

- 原估：85~140 净开发日、2~3 人并行 8~11 周。

## 四、关键路径技术方案：评测拆管线上 127（线1 任务卡）

来源：`docs/告警系统-2C4G评测机迁移实施方案.md` §六/§十/§十一，落为可派发的任务卡。全部改动在 `control-app`，纪律=旧 Live E2E 行为零变化、每卡附测试、`mvn test` 全绿才交付。

| 卡 | 内容 | 工期 | 验收（退出标准） |
|---|---|---|---|
| M1-1 | profile 收口：旧 `eval` → `eval-live-e2e`；标记 LIVE_E2E_LEGACY；加"同一时刻最多一个 Live E2E"锁 | 1d | 旧批可重复执行；双启第二个被拒 |
| M1-2 | 三契约：`ReplayCaseInputV1`（无 expected_*、无注入参数、opaque case id）/ `GoldenAnswerV1` / `CandidateObservationV1`；`EvalCaseInput` 去 `GoldenCase` | 1~2d | 类型上 runner 拿不到答案对象（编译期约束） |

## 五、并行线技术要点

**线2 R16 前段（执行者A，W1~W3）**——顺序即依赖：
1. F15 预算接线：Run 共享原子预算 reserve/settle；UNKNOWN 保守占用；子预算≤父预算；账本不可写=零触网。**这是里程碑 A 的硬前置。**
2. F10/F11/F12：`reclaimExpired` 原子条件更新（state+epoch+owner+lease_until，命中 0 行=竞态失败）；独立续租调度+失租中断；Cancel 单事务锁+CAS+事件。每项附两连接 barrier 实测。
3. F08/F09：执行循环改"推进→领取 READY→执行→回执→再推进"至终态；driver 独占所有权+持久 checkpoint；四边界杀进程恢复测试。
纪律：每修复附竞态/崩溃复现测试，修复后翻转为契约断言（审计已交的 6 项 characterization 测试是起点，禁止把坏行为冻结成规格）。

**线3 R5（执行者B，W1~W3）**：
1. logs.query 真实源：先接已有数据源（OTel/Loki 面盘点后定型，不许为凑数引入虚构后端）；
2. change.query 真实源：部署/配置变更事实面；
3. F07 硬隔离：真实/回放 profile 分开；未接来源显式 ABSENT → 任务 SKIPPED/MISSING_SOURCE；`NativeCapabilityProbe` 改查真实能力而非 Bean 存在。

**线4（执行者C，W1~W6）**：
1. 前端三全局阻断：vite rewrite 剥 /api、零鉴权头、Controller 仅 docker profile——先修这三个，21 个 mock 点才有联通前提（P4 盘点文档直接喂）；
2. AM7 M7-11~18（G1 批后开工）：值班表+override 排班、duty_delivery 六态、webhook 业务码判定（F20）、值班送达链（F21）、127 duty-adapter；
3. R17 真实认证：服务端认证主体、actor 由认证产生、拆前端 mock 登录；
4. MIG-02 Gatus 部署+断链演练（M7-17 adapter 落地后）。

## 六、风险与纪律

1. **同区代码冲突**：线1（eval 包）与线2（alert/harness 包）都动 control-app——分支纪律：各线独立分支、每周向主线合并一次、合并前 `mvn test` 全模块绿；eval 与 harness 包边界由主会话仲裁。
2. **G1 前置**：AM7 增量方案与主计划 v1.1 的 G1 批准是线4 第 2 项的开工闸；用户批前线4 先干第 1 项（前端三阻断，无依赖）。
3. **门禁不压缩**：里程碑 A/B/C/D 进入条件与考卷第 0 层十三项一项不砍；压缩全部来自并行与合并，不来自降标。
4. **127 资源门**：litellm ≤1024MiB / runner ≤1024MiB / scorer ≤1024MiB，启动窗口互斥进 evalctl；压限实测不过则 litellm 留 195（M5b 门控，不影响线1 走通——NATIVE baseline 回放不调模型）。
5. **今日 47 批结果**回填 M0 基线与 glm-5 参照原点；若批中发现新缺陷（BA-64 起），按严重度插入对应线。
