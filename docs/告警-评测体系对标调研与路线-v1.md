### 1.3 业界共识八条（我们据此对标）

1. **故障注入造真值是主航道**：ITBench/AIOpsLab/ChAP/RCA-Bench 同路——GT=已知注入点。
2. **指标要实体级+因果链**，不能只考最终答案：ungrounded diagnosis（服务对但机制/路径错）必须被扣分。
3. **确定性评分优先，LLM-judge 只做补充且必须人工校准**（RCA-Bench 82/18；Langfuse/Anthropic 校准纪律；Kappa<0.7 触发 rubric 修订）。
4. **诚实汇报解决率**：公开基准上 SOTA 只有 13.8%–47%；厂商营销数字不可引用。
5. **告警质量与 RCA 质量分开度量**：precision/recall/detection time/reset time + 压缩比/降噪率，独立于 RCA 命中率。
6. **时间切分与 point-in-time 正确性**：训练/测试按时间切，禁止未来信息泄漏（Meta 回放式评测是极致形态）。
7. **置信度门控+人在环**：输出 top-k 候选+证据链+置信度，不单点断言（Meta/incident.io/Gemini Cloud Assist 同律）。
8. **稳定性是一级指标**：agent 非确定性必须用 pass@k、run-to-run consistency、Majority-at-k 计量，并作为发布门禁。

## 三、路线（P1–P6，每阶段落地即在本文件追加记录）

- **P1（EV-09，已完成）**：稳定性一级指标——`EvalQueryReader.listScenarioRoundStatsForRuns` 批量聚合（禁 N+1）→ `StabilityFacet(passAt1, passAllRounds, scenarioConsistency)` 三件套（RatioStat 口径，无案例落档→UNKNOWN 不填 0）→ 实验列表加"稳定性"列、实验详情质量条加 pass@1/pass@k/轮间一致三卡。对标：ITBench run-to-run consistency、RCAEval Avg@k。
- **P2（执行集接通，已完成）**：materialize 入集案例成为可执行场景——OpenRCA/Meta point-in-time 回放形态落地。要点：`ReplayCaseReader`（case_version×dataset_version 按版本串精确键+适用期+HOLDOUT RLS）→ `DatasetCaseMapper`（回放锚强制 source_run_id+alertname，残缺拒入）→ `ReplayScenarioDriver`（alert_inbox **冻结 firing 载荷原文重投** webhook + resolved 变体清理，重试 3×10s 抗连接竞态，bearer env 注入 fail-closed）→ `GoldenScenarioRegistry.plus` 合并执行集（键冲突拒绝）→ EvalBatchRunner REPLAY 分支（跳过 Prometheus 探针，resolver 走 incident_key 路线）。迁移 V138（eval_app 读 alert_inbox）+V139（阶段词表扩 REPLAYING）。**195 E2E 全链路实证**（run 81c69fa3，2026-09-16）：提名 ArenaOrderStuck（真实已解决事故）→评审 ACCEPTED→入集 arena-replay-ds:eval-ds-1→LAUNCH→冻结载荷重投（inbox 73→74）→新 episode gen=3→真调查 3 分钟→评分 DECIDABLE（Agent 如实 NO_CONFIRMED_ROOT_CAUSE——**point-in-time 衰减首次被量化**）→resolved 清理回 RESOLVED→第二轮 resolved→refire 竞态如实落 TIMEOUT_OR_ABSENT。E2E 过程连环揪出并修复三真缺陷：①REPLAYING 撞 V80 阶段词表冻结约束；②`quote()` 不转义控制字符（多行异常消息炸 jsonb 落档面）；③激活连接竞态需有界重试。另发现并清场 47h 陈旧 eval worker（旧镜像抢跑新命令+其 INSERT 与新 schema 不兼容）。
- **P2**：执行集接通——materialize 入集案例成为可执行场景（DatasetCaseRegistry = YAML 注册表 ∪ 数据集版本案例）；生产案例重放跑通一条 E2E。
- **P3（RCA 三维评分落库，已完成）**：对标 RCA-Bench 定因/定界/过程三维协议的确定性适配版（82/18 规则/LLM 比例中的规则侧，无 LLM-judge——与 ScenarioMetrics 拒评纪律同律）。`eval_case_result` 增 9 列（V140，全可空=null 未评不填 0）：定因维 cause_{component,fault,reason}_hit 逐维同义词命中（部分分=图距离评分的三元组适配）；路径维 checkpoints_{total,covered}+逐点命中 jsonb（GT 检查点 materialize 时人工显式提供，存 rawArtifact 保留键 gt_evidence_checkpoints——EvalCaseV1 契约不动；报告包全文语料 casefold 子串匹配）；结论复核维 conclusion_grounded（TRUE 根因 claim 是否带证据引用——OpenRCA 2.0 ungrounded diagnosis 探针）；过程维 tool_calls_{total,unique}（重复调用观测）。评分器/读面/API/详情页三维列全链接线；单测 4 例。**195 真验**：V140 迁移落地，run daf6f7bd/f87b17a5/f0b7fe31 三轮在役真验打通写路径（案例行落库、三维列如实 null）。**实证定谳一条重放边界**：事故材料哈希去重（RR24 正确语义——无新证据不重查）使同一历史载荷的重放只可能产生一次调查测量；跨轮 resolved/firing 同秒竞态需轮间落定等待（已修）；多轮持续测量必须走故障注入造新材料——这正是业界标准（RCA-Bench/ITBench/AIOpsLab）全用注入做 GT 的根因，我们在自己的系统里实证了它。DECIDABLE 三维列的首行真值落在下一次全新事故材料的回放测量（run-5 形态复现）或注入场景接线后。
- **P4**：红队最小集——REDTEAM 分层下 5–10 条注入/越权用例（告警 label 注入、越权工具意图）；SafetyGate 判定结果 run 级落库+拦截率出数。
- **P5**：告警质量指标补齐——误报率数值化（conclusion_feedback FALSE_POSITIVE 聚合）、静默效果统计（命中省略通知数）、压缩比口径（alerts→incidents）。
- **P6**：LLM-judge 第三判定式+校准——rubric 二元化（美团法）；judge 仅用于自然语言 reason 字段；与 EV-08 人工评审算一致率，<0.7 触发 rubric 修订。难度分层 L1–L4+SMOKE panel 快速回归同批。
