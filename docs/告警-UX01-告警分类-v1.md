# 告警 UX-01 告警分类后端 v1

> 2026-09-11，ev/eval-center 工作区（HEAD 3e1c013 起）。依据：`告警-评测中心与能力版本演进-审查及详细改造方案-v1.md` §六 + §七 UX-01 卡、`告警-UX迭代-分类与值班机器人方案-v1.md` §一。范围：**后端**（迁移/分类器/override 事务/读面投影）；前端 facet 徽章与 195 部署验收不在本轮。

## 一、词表与判定规则表

词表 9 值（`IncidentCategory` 枚举 ↔ V82 CHECK 一一对应，改词表 = 改枚举 + 新迁移）：

| 分类 | 口径 |
|---|---|
| BUSINESS | 订单失败率/SLO/交易损失等业务指标告警 |
| APPLICATION | 异常/延迟/状态机/进程（应用自身） |
| DEPENDENCY | DB/MQ/缓存/下游 API |
| INFRA | 主机/容器/CPU/内存/磁盘 |
| NETWORK | 连接/DNS/TLS/丢包 |
| DATA | 数据质量/新鲜度/流水线 |
| SECURITY | 越权/泄露/策略违规 |
| PLATFORM | 控制面自身异常（独立出口，不混入 7 个业务类） |
| UNCLASSIFIED | 尚无足够信息归类的显式出口；不等于平台异常 |

分类只描述告警所属面，不预断根因；**severity 不参与分类**（升级不换类）。

### 判定规则（`IncidentClassifier`，规则版本 `ux01-rules-v1`，Git 审查演进、首期不热更）

裁决律：下表**行序即冻结优先级**，首条命中即裁决；无权重分值、无概率置信度。输入只取 `alertname` / `domain`|`category` / `service`|`service_name` 四类可信标签，先截 512 字符再归一化（小写、剔除非 [a-z0-9]），只做子串/等值匹配（无正则，复杂度有界）。

| 优先级 | ruleId | 目标类 | 判定 |
|---|---|---|---|
| 1 | PLATFORM-SERVICE | PLATFORM | service/service_name ∈ {control-app, notify-app, duty-adapter} |
| 2 | PLATFORM-ALERTNAME | PLATFORM | alertname 含 controlapp/notifyapp/dutyadapter/controlplane |
| 3 | SECURITY-LABEL | SECURITY | domain/category = security |
| 4 | SECURITY-ALERTNAME | SECURITY | alertname 含 authfail/unauthorized/forbidden/bruteforce/credentialleak/policyviolation/intrusion |
| 5 | BUSINESS-LABEL | BUSINESS | domain/category = business |
| 6 | BUSINESS-ALERTNAME | BUSINESS | alertname 含 orderfail/paymentfail/checkoutfail/sloburn/conversion/businessloss |
| 7 | DATA-LABEL | DATA | domain/category = data |
| 8 | DATA-ALERTNAME | DATA | alertname 含 dataquality/datafreshness/datastaleness/pipelinefail/etlfail |
| 9 | NETWORK-LABEL | NETWORK | domain/category = network |
| 10 | NETWORK-ALERTNAME | NETWORK | alertname 含 dns/tls/ssl/packetloss/networkunreachable/connectionreset/tcpretransmit |
| 11 | DEPENDENCY-LABEL | DEPENDENCY | domain/category = dependency |
| 12 | DEPENDENCY-ALERTNAME | DEPENDENCY | alertname 含 postgres/mysql/redis/kafka/rabbitmq/database/replicationlag/downstreamerror/upstreamtimeout |
| 13 | INFRA-LABEL | INFRA | domain/category = infra/infrastructure |
| 14 | INFRA-ALERTNAME | INFRA | alertname 含 cpu/memory/oom/disk/inode/filesystem/nodepressure/hostdown |
| 15 | APPLICATION-LABEL | APPLICATION | domain/category = application/app |
| 16 | APPLICATION-ALERTNAME | APPLICATION | alertname 含 exception/errorrate/latency/http5xx/crashloop/restartloop/deadlock/statemachine |
| 17 | FALLBACK-UNCLASSIFIED | UNCLASSIFIED | 无规则命中（依据如实写明，不给假概率） |

优先级理由：PLATFORM 置顶（控制面自身异常绝不落入业务类）；SECURITY 次之（越权/泄露语义优先于宿主归属）；APPLICATION 垫底（最泛兜底类）。已知取舍：裸词 `slo` 会误中 `dnslookup` 等子串，业务词表只用可辨识复合词（`sloburn` 等）。

## 二、存储（V82）

`incident` 新增两族列——人工 override 物理上不可能被规则覆盖：

- `rule_category` / `category_rule_id` / `category_rule_version` / `category_classified_at`：规则裁决面（CHECK 同生同灭，重分类可追溯=ruleVersion+classifiedAt）。
- `override_category` / `override_actor` / `override_reason` / `override_at` / `override_revision`：人工面（CHECK 同生同灭、理由非空白、revision≥0）。
- `category` / `category_source`：**STORED 生成列**，生效面唯一真源：
  `category = coalesce(override_category, rule_category, 'UNCLASSIFIED')`；`category_source = OVERRIDE/RULE`。
- 存量行 rule 面 NULL → 生效面 UNCLASSIFIED：**不回填、不改写历史**；下一条"非重复且在 episode 水印内"的事件触发规则重分类（IncidentProjector 投影事务内）。

`incident_category_override`（审计表，insert-only）：`action ∈ {SET, REVOKE}`、`from_category`（动作前生效面快照）/`to_category`、`actor`、`reason`（非空白 CHECK）、`expected_revision`/`result_revision`（result > expected）、`uq(incident_id, idempotency_key)` 幂等锚。

授权：incident 表级 grant 及于后增列（control_app 读写、eval_app 只读不变）；审计表 `grant select, insert to control_app`，`revoke all from publisher_app, notify_app, eval_app, public`（eval_app 不写告警域显式冻结）。

## 三、写面契约

**投影分类（自动）**：`IncidentProjector` 在投影事务内对"非重复且 startsAt ≥ episode 水印"的事件重算规则分类，只写 rule_* 四列；重复通知与晚到事件不重分类。规则重算不动 override_*——EU47 语义由两族列分离结构性保证。

**人工 override**：`POST /api/v1/incidents/{id}/category-override`，body `{category, reason, expectedRevision, idempotencyKey}`；撤销：`POST .../category-override/revoke`，body `{reason, expectedRevision, idempotencyKey}`。

- 裁决序：幂等重放（同 incident+key 返回原审计行，`replayed=true`，零二次生效）→ 行锁读决策面 → `expectedRevision ≠ override_revision` → 409 REJECTED_STALE 零副作用 → CAS 写 + 审计行同事务提交。
- `reason` 必填非空白、`category` 词表校验（400）；incident 不存在 404；无 override 时撤销 400。
- actor = 认证主体（不采信 body 自报，截断 64）；授权归 SecurityFilterChain（/api/v1/** → ROLE_OPERATOR）；浏览器会话需 CSRF token（与 /api/rca-runs 命令面同策）。
- 响应：`{state, action, auditId, category, categorySource, revision, replayed}`。

## 四、读面契约

- `GET /api/v1/incidents`：新增 `category` 过滤参数（词表校验，非法 400）；每行带 `category` + `categorySource`（UNCLASSIFIED 如实返回——前端三态惯例显示"未分类"，不算 0 不算成功）。
- `GET /api/v1/incidents/{id}`：行级 `category`/`categorySource` + `categoryDetail{ruleId, ruleVersion, classifiedAt, overrideActor, overrideReason, overrideAt, overrideRevision}`（命中依据全量可见，**无概率字段**；无 override 时四列 null）。
- `GET /api/v1/incidents/facets`：新增 `category` 维分桶——计数口径 = **当前 status/service/q 过滤下**的生效面数量（方案 §六 facet 口径要求）。

## 七、偏差与未做项

1. **INFRA 词元**：旧分类方案表格写 "基础设施 INFRA"，本实现沿用 `INFRA`（而非 INFRASTRUCTURE），枚举与 CHECK 一致。
2. **重分类时机**：方案未指定具体时机，本实现定为"非重复且 startsAt ≥ episode 水印"（与 §6.7 乱序策略同锚）；晚到/重复事件不刷新分类面。known edge：BA-12 同 episode 迟到 firing（startsAt 在水印内但早于 resolvedAt）会用旧材料刷新 rule 面——无害（override 不受影响），如实记录。
3. **存量行不回填**：迁移前 incident 一律显示 UNCLASSIFIED，待下一条告警事件触发规则分类——遵守"历史重分类需批次与版本，不能改写过去报表而不标记"；如需批量回填应另立带规则版本的批次任务。
4. **未做（卡外）**：前端 facet/徽章/修正入口（alert-web）、195 部署截图验收、历史 override 审计读面 API（审计表已留，列表接口未开）。
