   - 总览统计卡：`OverviewView.vue:10-36` ← `src/mocks/overview.js:8-39`。
   - 监控大盘 6 卡：`MonitorView.vue:13-53` ← `src/mocks/monitor.js:9-54`（14/16 槽位、¥3.86 成本全是假的）。
   - 评测中心：`EvalLaunch.vue:6-26` 六步向导全是写死字符串；`EvalCompare.vue:85` 差异徽标写死；`EvalView.vue:65` `analysisRunId='eval#0907'` 写死。
   - 壳顶栏：`AppShell.vue:15-28` 环境下拉无逻辑、全局搜索 disabled、**SSE 绿点常亮是假的**（:98-101 纯 CSS）。

3. **丑的结构性根源**：无组件库（手写 .btn/.tag/.card 三件套）、无图表库（"图表"全是 CSS 进度条）、设计说明文字直接渲染在页面上（`AlertsView.vue:30,132-134`、`OverviewView.vue:38-41` 把设计依据当 UI）、布局靠手写 grid 挤在一起。
4. **后端缺口**：前端调了但后端不存在的端点 17 个（清单见 §6），统计卡/监控大盘/评测**无任何现成聚合投影**。

## 1. 目标与验收标准

| 目标 | 验收方式 |
|---|---|
| 审美达标：浅色简洁风，功能分区明确，不挤 | 用户逐页截图对比主观验收（这是本线第一验收标准） |
| 零硬编码展示数据 | 全页面数据来自真 API；`grep` 扫描无 mocks 引用、无写死统计数字；页面不再渲染任何设计说明文字 |
| 全链路联通 | 195 部署后逐页验证：改数据库/造告警 → 页面数字变化（数据溯源测试） |
| 工程质量 | `npm run build` 绿；每页 headless 截图自证（复用 `docs/测试证据/EX-D1-duty-chat-deploy-20260910/` 的 Edge+CDP 脚手架） |

非目标：不改后端业务逻辑（只加查询/聚合投影端点）；不动评测引擎内核；不做移动端适配。

## 2. 技术选型（已锁定）

- **Element Plus**（2.14.x）+ `unplugin-vue-components`/`unplugin-auto-import` 按需引入。参照：vue-pure-admin（同栈，20.6k star，视觉克制密度高，直接抄布局）。
- **ECharts 6 + vue-echarts 8**：监控大盘时序图/热力图；监控页数据走后端代理（见 §6，不直连 Prometheus，避免内网地址泄漏与 CORS）。
- **保留**：Vue Flow（RunDetail DAG 图）、axios、pinia（本次开始真正使用：会话 store + SSE 状态 store）。
- **浅色主题**：参照 Datadog 设计性格——零/极浅阴影、hairline 细线分层（`#e1e5e9`）、圆角 6px 保守、平面色块分区；字体栈保留 PingFang/微软雅黑。

## 3. 设计规范（tokens v2，`src/styles/tokens.css` 重写）

**色板**（Element 语义色为基底，severity 五级按 Arco 色板第 6 级）：

| 语义 | 值 | 用途 |
|---|---|---|
| --brand | `#409EFF` | 主色/链接/激活 |
| P0 critical | `#F53F3F` | P0 徽章、色条、失败态 |
| P1 high | `#FF7D00` | P1 |
| P2 medium | `#F7BA1E` | P2、待审查（最高优先级中间态） |
| P3 low | `#165DFF` | P3 |
| info | `#86909C` | 未分类/信息 |
| ok | `#23C343` | 成功/已解决/健康 |
| 背景/卡片/hairline | `#f5f6f8` / `#ffffff` / `#e5e8ef` | 三层分区 |

**规范**：8px 间距网格；圆角统一 6px（卡）/4px（控件）；阴影收敛为单层 `0 1px 2px rgba(0,0,0,.04)`；字号阶梯 12/13/14/20/28；状态徽章全部 `el-tag` 化（动词化标签：排队/执行中/待审查/已完成/已失败/已取消）；severity 用"行首 4px 色条 + 徽章"，不整行着色（incident.io/Grafana 惯例）。

**组件映射**（手写 → Element）：`.btn`→`el-button`；`.tag`→`el-tag`；表格→`el-table`；时间线→`el-timeline`；属性面板→`el-descriptions`；侧滑→`el-drawer`；表单→`el-form`；空态→`el-empty`；骨架→`el-skeleton`。

## 5. 逐页方案

每页给出：参照对象 → 目标布局 → 数据来源（★=需后端新补）。

### 5.1 总览 Overview（参照：Datadog 首页 + Juniper Mist 可点统计块）
- 布局：KPI 卡一行（Firing 告警/待审查 Run/卡住失败/值班当班/通知未读）→ 通栏"最近 24h 告警趋势"（ECharts 面积图）→ 双列（最新 Firing 告警 Top5 表 / 系统健康）。
- 数据：★`GET /api/v1/overview/summary`（聚合 rca_runs/cases/alert events/duty 快照/通知未读）；趋势图 ★同源带 24h bucket。
- 所有 KPI 卡**可点击跳转到对应过滤后的列表页**（Alerta/Juniper 惯例）。

### 5.2 告警中心 Alerts（参照：Datadog Monitor List + Alerta）
- 布局：顶部可点击 severity 统计条（点击=应用过滤）→ 左 facet 栏（状态/严重度/服务/来源，真计数）+ 右 `el-table`（行首色条、checkbox、批量操作条、行尾"打开"）。
- 数据：★`GET /api/v1/incidents`（含过滤/分页）、★`/api/v1/incidents/facets`、★`/api/v1/incidents/summary`。数据源表=现有 alertmanager webhook 入库的 alert event/incident 表（§6 盘点后定）。
- 删除 DSL 假搜索与批量假按钮——批量操作只保留后端真支持的（确认/解决转 Case）。

### 5.3 Incident 详情（参照：PagerDuty 详情页 + Datadog Watchdog 侧滑）
- 布局：header（severity 徽章+状态+服务+时间窗+操作）→ tabs：概览（`el-descriptions` 属性面板+关联 Run 卡）/ 时间线（`el-timeline`，事件类型过滤）/ 原始负载（raw JSON 折叠）。
- 数据：★`GET /api/v1/incidents/{id}`（含事件时间线、关联 rca_run_id）。
- 删"分类说明与修正"假面板；人工修正分类功能后端无支撑，本版移除入口。

### 5.4 历史档案 History（参照：Alerta history 区）
- 已解决 incident 列表 + 右侧只读快照。数据：复用 ★`/api/v1/incidents?status=RESOLVED` 与详情端点，**不单独做 history 投影**（收敛缺口）。删假 SHA-256 归档证明与假 verifyAll。

### 5.5 审查台队列 Runs（已真，视觉重构）
- `el-table` + tab 计数条（真 `/api/rca-runs` buckets）+ SLA banner 保留 + 筛选 URL 持久化保留。认领/取消按钮接真 `POST /api/rca-runs/{id}/commands`。

### 5.6 Run 详情（本线视觉重心；参照：Laminar Transcript + Langfuse + Resolve.ai）
- 顶部：状态 chip + 预算微条 + 操作按钮（接真命令）。
- 主区 tabs：**调查过程（默认）**=Transcript 卡片流——SSE 事件流渲染为"思考/工具调用/结果"三段卡（每卡一行内联预览，点击展开）；**DAG** 保留 Vue Flow；**时间线**=全宽垂直时间线；**Claim 与证据**=三层分级（证据=原始引用徽章 / 假设=validated/invalidated/inconclusive 三态标签+置信色带 / 结论=根因卡）；**报告** 保留。
- 多角色并行：顶部角色卡条（每调查角色一卡：当前动作一句话+步骤计数+证据数）。
- 删底部假状态条（"延迟 0.8s"写死文案）与 11 态写死图例（改从数据生成）。

### 5.7 处置 Cases（已真，视觉重构）
- 双栏改"左队列（el-table 紧凑）+ 右 `el-drawer` 详情"；删 `'c62'` 特判；命令四件套保留（expected_revision+幂等键已是正确姿势）。

### 5.8 值班 Duty（参照：Grafana OnCall Schedules）
- 布局：顶部**当班横幅**（当班人头像+24h 状态条+快照有效期）→ tabs：排班视图（周日历网格渲染轮值层与 override）/ 成员（el-table CRUD）/ 通道（el-table CRUD+优先级排序）/ 测试通知（表单卡）。
- 数据全真已有（DutyQueryController/DutyAdminController），纯前端重构。

### 5.9 群模拟 DutyChat / 5.10 通知 Notifications（已真已部署）
- 纳入新壳与新 token，群模拟保留仿企微消息卡外观（已是页面里最不丑的）；通知页改 el-table+未读徽章。

### 5.11 监控大盘 Monitor（全新；参照：Grafana 24 列网格惯例）
- 布局：一行 4 张 stat 卡（活跃 Run/Worker 槽位/Outbox 延迟/通知积压）→ 通栏时序图（告警接收速率、Run 吞吐）→ 双列（工具调用 TopN / 模型成本）→ 告警列表面板。
- 数据：★`GET /api/agent-ops/summary`（control-app 聚合自身表：rca_run/task/outbox/notification）；时序 ★`GET /api/metrics/query_range`（后端代理 Prometheus，参数白名单只允许预定义查询集，防 PromQL 注入）。

### 5.12 评测中心 Eval（缺口最大，单独成卡）
- 9 个子组件全 mock，后端 `/api/eval/*` 不存在。**但评测线已有真资产**：full-0910b 全量批、registry v2、10 Case 数据集——需先盘点 control-app 评测域已有表/存储，再定投影端点最小集（批次列表/进度/六维分析/案例诊断 4 个端点先行；评分器校准/实验对比/发布门维持"建设中"占位但用 `el-empty` 明示，不放假数据）。
- `analysisRunId` 写死改为从最新批次动态取。

## 9. 风险与防假绿

1. **评测域/alert 表结构未盘点**（B0 是硬前置）——若 webhook 入库表字段不足以支撑 facet，B4 降级为 severity/status 两维，在 UI-1 开工前确认。
2. **防假绿三条**：①每页验收必须做数据溯源（改库看页面变）；②截图取证复用 Edge+CDP 脚手架；③mock 开关物理删除，不是默认关闭。
3. ** Prometheus 代理**只做白名单查询集，不接任意 PromQL。
4. 主观审美验收风险：UI-0 完成后**先出一页样板（告警中心）给你过目**，认可风格后再铺开其余页面——避免 12 页全部返工。
