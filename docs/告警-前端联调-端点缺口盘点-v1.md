## 0. 前置机制结论（client.js / 代理 / 鉴权）

`alert-web/src/api/client.js`（16 行）：

- `api(path, { params, mock })`：**仅 GET**（`http.get(path, { params })`），`baseURL: '/api'`，timeout 15s。返回 `data`（即响应体本身，无外层包装）。
- mock 语义：`VITE_USE_MOCK !== 'false'` 时 `useMock=true`，调用点若传了 `mock` 则**直接执行本地 mock 函数、不发请求**；未传 `mock` 的调用点（本次扫描无）才会真发请求。**前端没有任何鉴权头逻辑**——不带 `Authorization` / `X-Operator-Id`。
- `http` 实例有导出但**全库无第二处使用**，即前端今天不具备发 POST/PUT/DELETE 的通道。
- 无按域拆分的 api 模块（api/ 目录只有 client.js 一个文件）；28 个调用点全部直达 `api()`。

`alert-web/vite.config.js` 代理（联调主通路）：

```js
'/api': { target: 'http://localhost:8080', changeOrigin: true, rewrite: p => p.replace(/^\/api/, '') }
```

**rewrite 会剥掉 `/api` 前缀再转发**；而 control-app 所有 @Mapping 路径自带 `/api` 前缀（无 server.servlet.context-path，application.yml 未配置）。→ 现状下任何请求到后端都变成 `/rca-runs` 这类无前缀路径，**必然 404**。联调前必须二选一：去掉 rewrite（推荐，后端路径已带 /api），或后端加 context-path。

后端鉴权（无 Spring Security，Controller 手工验签，全部常量时间比较）：

- `/api/rca-runs**`、`/api/cases**`：`Authorization: Bearer ${app.operator.api.bearer}`（APP_OPERATOR_API_BEARER），主体取 `X-Operator-Id` 头（缺省 operator）。缺头/错值 → 401。
- `/api/config-bundles**`、`/api/canary/status`：`Bearer ${app.release.api.bearer}`（release 角色）。
- `/webhooks/alertmanager`：`Bearer ${ALERTMANAGER_WEBHOOK_BEARER_TOKEN}`（Alertmanager 入口，非前端消费面）。

**所有业务 Controller 均标注 `@Profile("docker")`**——本机默认 profile（无 DataSource）启动 control-app 时这些端点**根本不注册**。联调需以 docker profile（含 Postgres/Flyway）拉起。

## 5. 意外发现（扫描中捕捉、单列提示）

1. **vite proxy rewrite 与后端 /api 前缀互斥**（第 0 节）：`rewrite: p => p.replace(/^\/api/, '')` 写于"后端路径不带 /api"的假设期，后端落码时选择了带 /api 的全路径——两头都"自洽"，合起来 404。这是一行修复，但**不修则本盘点所有"已通"均为纸面已通**。
2. **前端零鉴权通道**：client.js 不带 Authorization/X-Operator-Id，后端所有业务端点都要 Bearer → 全部 401。且 `VITE_USE_MOCK` 未在任何 .env 定义（alert-web 下无 .env），当前 mock 恒开。
3. **后端业务端点只在 docker profile 注册**：默认 profile（application.yml 排除 DataSource）下连"纸面已通"的 3 个端点都不存在。
4. **后端一批"有前端没用的"端点**：Case 命令 4 个（与 mock 返回形状惊人地完全对齐，显然按 mocks/cases.js 落码）、Run 命令、事件 REST+SSE 三件套、canary、config-bundle×4——**后端比前端接线进度领先**，缺口主要在前端接线而非后端实现（除第 2 节 P1/P2 新投影面）。
5. **ID 形态断层**：前端全链路用 `run#3f2a / case#c91 / eval#0907` 展示态 id，后端 path variable 严格 `UUID.fromString`。联调前需定"外部 id 形态"（前端传 UUID、展示层另行格式化，或后端放宽解析）。
6. **EvalCases.vue L110 硬编码** `eval%230907`（含 URL 编码 #），本身是前端 bug，联调前应先修。
7. RunDetailView 文件头注释的换票路径 `POST /rca-runs/{id}/stream-ticket` 与后端实际 `POST /api/rca-runs/{runId}/events/stream-ticket` 不一致——注释先行于后端落码，接线时以代码为准。
8. RunQueryService 的行投影连中文词典（stageZh/stageTone）都在后端生成，注释声明"M7-09 前端可覆盖"——联调时可验证前端词典与后端词典的双写一致性。
