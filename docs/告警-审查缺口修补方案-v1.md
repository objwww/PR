## 一、缺口盘点（代码逐行核验后的真相，G1~G8）

### G1 模型输入面"盲飞"（B 门硬前置）
`BoundedLlmRoleRunner.promptOf`（`control-app/src/main/java/com/objwww/pr/control/alert/application/agent/BoundedLlmRoleRunner.java:295-328`）发给模型的信封 = `profile.prompt()` + JSON(envelope) + PROTOCOL_SUFFIX（:56-68）。信封字段逐项（:298-324）：

| 字段 | 内容 | 行号 |
|---|---|---|
| role / run_id / task_id / round_id | 身份串 | :299-302 |
| steps_remaining / delegation_batches_remaining | 两个计数 | :303-309 |
| time_window | 冻结窗纪元秒对 | :310 |
| tool_allowlist / tool_schemas | 工具名+args JSON Schema | :311-315 |
| valid_artifact_refs | **纯 UUID 清单**（`validRefsOf` :348-353 = binding inputRefs + `evidence.findByRunId` 的 evidenceId） | :316-317 |
| last_error | 仅上一步可重试失败的修正指引（成功步缺席） | :320-322 |

**没有**：证据内容/摘要（工具取回的正文落库后从不回进 prompt）、累计假设/已排除方向/反证、告警正文与任务目标、历史轨迹、token 预算余量。代码注释自述"不广播历史"（:294）。唯一跨步回喂 = V88 lastError 反馈环（:269-277）。
依据：R7方案 §18.2 L363 原文核对项、§19.1 L414"模型需要知道证据讲了什么，不能只获得允许引用的 UUID"、MC01~04（§21.2 L519-522）。
