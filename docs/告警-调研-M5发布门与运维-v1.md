## §0 总结论：按 M5 任务线的"可借鉴组合"

- **数据集（M5-01/02）【v1.1 新增】**：推翻"全部自建"——三层数据集：订单域私有集（order-arena+脱敏生产回归）= 主质量门决定上线；RCA-100 v1.1（阿里云 STAROps RCA-Bench，103 例，Adapter 接入、固定 v1.1+manifest digest、转冻结 Snapshot+REPLAY_MOCK 夹具、answer key 授权核查前置）= 辅助一致性门；RCAEval RE2/RE3 子集（按 Case 下载 Parquet，不在 2C4G 解压全量）= 辅助回归。统一 DatasetAdapter 转 EvalCaseV1，保留原始 artifact 与来源字段；`source_class=PUBLIC_BENCHMARK` 不冒充私有 HOLDOUT；同故障注入模板按 `scenario_family_id` 整组分区，禁拆跨 TUNING/HOLDOUT。

## §1 特性开关 / Canary

### 1.1 Unleash（13,787★，efe911a，活跃——前日有提交）

机制证据【源码】：稳定分桶 `strategy/util.ts:9-10` `murmurHash3.x86.hash32(`${groupId}:${id}`)` 取模归一到 [1,100]；策略桶 seed=0 与 variant 桶 seed=86028157 分离（:13/:19），同 id 在"是否放量"与"进哪个变体"上互不相关。flexibleRollout stickiness 解析 `flexible-rollout-strategy.ts:26-28`：`userId || sessionId || randomGenerator()`——**缺 id 回退随机，分桶不再稳定**；空 id 则直接 false（:54-55）。variant 选择 `variant.ts:88-117`：override 优先于权重、权重按总和归一、weight=0 永不命中。
优点：算法 30 行可抄全；stickiness/groupId 概念完备。缺点：服务端 TS，Java 侧需重写（murmur3 有 Guava 实现，算法同族可复现）；random 回退是 M5 的坑。
适配性：**抄机制**。MurMur3+groupId+百分比 + variant seed 分离 + override 优先，全部可翻成 Java；强制 stickiness key 存在（session/tenant），不存在=不进 canary 并记录。

### 1.2 flagd（987★，48be8de，活跃）

机制证据【源码】：fractional 分桶 `core/pkg/evaluator/fractional.go:54-56,196-207`——`murmur3.StringSum32` 后 `bucket := (uint64(hash)*uint64(totalWeight)) >> 32`，乘法移位映射避免模偏（Unleash 的 `%100` 在权重非 100 时有轻微偏差）；权重和上限 MaxInt32 配置期校验（:12,186-187）；bucketBy=flagKey+targetingKey 拼接（:97）保证跨 flag 分桶独立；无 targetingKey 返回 nil 不评估（:85-98，不随机——比 Unleash 稳）。targeting 规则=jsonlogic + 自定义 operator（`json.go:12,147`）。
优点：分桶数学更严谨；fail-silent（nil）语义契合"不确定就不放量"。缺点：Go 生态，只能抄算法。
适配性：**抄机制**（分桶公式与校验纪律直接翻 Java）；JSONLogic 规则引擎对 Canary Router 过重，本项目爆炸半径/分桶用确定性配置即可。

### 1.3 Argo Rollouts（3,571★，bdb1496，活跃）

机制证据【源码】：步骤引擎 `rollout/canary.go:307-344`——步骤类型封闭枚举（Pause/SetWeight/SetCanaryScale/Analysis/Experiment/…），Analysis 步骤须 Successful 才推进（:332-335），SetWeight 须权重 Verified（:320-328）。abort `rollout/pause.go:72-91`：Status.Abort 布尔+AbortedAt 幂等（保留原时间戳防热循环）。回退 `rollout/trafficrouting.go:360-396`：abort/回滚时 `min(desired, current)`，随 stable 可用性渐进把流量移回 stable，注释明言"只在权重已移向 primary 后才缩 canary"。
优点：abort 幂等状态位 + 渐进回收 + 分析门三个思想与 M5-14"立即回退 Holmes"完全同构。缺点：全套绑定 K8s ReplicaSet/TrafficRouter。
适配性：**抄思想**（step 封闭枚举、abort 幂等位、回退不瞬间切流）；K8s 资源编排部分不适用。M5"立即回退"应定义为：撤 canary 分桶规则（秒级生效）+ Holmes 旧 digest 继续服务，无需渐进——比 Argo 更简单，但 abort 幂等与"回退事件落库"照抄。

### 5.1 PG16 官方分区（文档级）

【文档】postgresql.org/docs/16/ddl-partitioning.html：①`DETACH PARTITION ... CONCURRENTLY` 只需 SHARE UPDATE EXCLUSIVE 锁（普通 DETACH 要 ACCESS EXCLUSIVE）——"导出校验后 detach"在线可做；②分区表唯一/主键约束必须包含全部分区键——**insert-only 月分区表的主键设计受此硬约束**（建议 (month_key, id) 或全局 UUID 无主键冲突依赖）；③ATTACH 前加 CHECK 约束跳过验证扫描；④分区数千级内可用，但规划时间/会话内存随分区数增长——月分区无压力。

### 5.2 pg_partman（2,811★，c737cc1，branch=development，活跃）

机制证据【源码】：`sql/functions/drop_partition_time.sql:56-58` `pg_try_advisory_xact_lock` 防维护重入；:256-269 retention 三分支：keep_table=false 可先 DETACH 再 DROP、keep_table=true 只 detach 保留整表、retention_schema 非空则移表到归档 schema——**"失败不删热数据"的机制先例**（先导出+校验、再 detach、保留独立表随时可回挂 ATTACH）。BGW 免外部 cron。

## §6 SSE / 事件流

【文档】PG16 LISTEN/NOTIFY（sql-notify.html）三边界：payload 默认 <8000B（大数据应放表、通知只带 key）；通知队列 8GB、满则 NOTIFY 事务 commit 失败；**通知只投递给当前存活监听会话，断连期间丢失**。另：事务内通知 commit 后才投递、同事务同 channel+同 payload 折叠去重。
【文档】Spring MVC 异步（mvc-ann-async.html）：MVC 支持 streaming，"individual writes to the response remain blocking (performed on a separate thread)"——SseEmitter 写出阻塞、无内建背压，背压须应用层实现。
【源码】Unleash delta API（`client-feature-toggle-delta.ts:229-`、`delta-cache.ts:14`）：客户端带 last revisionId，服务端有界事件缓存（默认 20 条）内回放 delta、超窗回 full hydration——after_seq 回放+断档全量快照的直接先例。
适配结论（M5-17）：定型组合——NOTIFY(rca_event, run_id:seq) 只作唤醒；SSE 通道从 rca_event 表按 after_seq 读真身（含脱敏列过滤）；应用层有界缓冲+写阻塞超阈值即断开客户端（不断开 Run）；客户端断线重连带 Last-Event-ID=seq，超窗回"快照+继续流"。LISTEN/NOTIFY 在此架构下不承载可靠性，官方边界全部规避。

## §8 检索

### 8.1 PG FTS / pg_trgm（文档级）

【文档】textsearch-indexes.html：GIN 为 FTS 首选索引（只存 lexeme 不存 weight，用 weight 需回表 recheck）；GiST 有损（siglen 默认 124B）。pgtrgm.html：`similarity()`/`%` 操作符（阈值 `pg_trgm.similarity_threshold` 默认 0.3）、GIN `gin_trgm_ops` 支持 LIKE/ILIKE/正则非左锚匹配——告警标题/错误串的"相似历史"检索用 pg_trgm 比 tsvector 更合身（FTS 依赖分词质量）。

### 8.2 pgvector（22,926★，e48241b，活跃）

机制证据【文档】README:197-208：默认精确 KNN（perfect recall），HNSW 建图换速度、内存占用高；:268-278 `ef_construction`/`ef_search`（默认 40，可 SET LOCAL 会话级）调召回；:291-312 图放得下 maintenance_work_mem 建索引才快、勿超物理内存、并行 worker 默认 2。
