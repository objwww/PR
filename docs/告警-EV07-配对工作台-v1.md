## 1. 端点契约

挂 /api/eval/** 矩阵（ROLE_OPERATOR，SecurityConfig 既有规则；DB 面 control_app
对 eval_comparison 只增读、对源表只读）。400/404 应答沿 {"error": ...} 惯例。

| 端点 | 参数 | 应答 |
|---|---|---|
| GET /api/eval/compare | baseline, candidate（UUID 必填）；group（ALL/IMPROVED/REGRESSED/FLAT，默认 ALL）；cursor（键集）；limit（默认 200，上限 500） | 200 实时对比投影（全读面）；参数缺/非法/两 run 相同/group 非法 400；任一 run 未知 404 |
| POST /api/eval/comparisons | body {baselineRunId, candidateRunId} | 201 同一计算的 insert-only 落档快照 + gateRecord.recordId；400/404 面同上 |

### 1.1 对比响应（EvalCompareResponse）

```
{ baselineRunId, candidateRunId,
  comparability: { comparable, dimensions[], mismatches[] },
  summary: { pairedCount, unpairedCount,
             improved,  regressed,  flat,          // RatioStat 三件套，分母=pairedCount
             verdictChangeMatrix{"基线判定→候选判定": n},
             clusters[], byFaultType[], stats } | null,
  gate: { ruleVersion, outcome, reasons[], maxRegressionRate, ciMargin },
  gateRecord: { recordId, outcome, createdAt } | null,
  cases[], unpaired[], unpairedTruncated, scanTruncated, nextCursor, asOf }
```

- `comparable=false` → `summary=null`、`cases/unpaired` 空表、`gate.outcome=
  NOT_EVALUABLE`——**不出配对结论**，前端只做展示（EU23/EU25）。
- `gateRecord` = 同 (baseline,candidate) 对最新 eval_comparison 落档引用；
  无落档如实 null（GET 实时计算面与落档面分开表达，互不顶替）。
- `cases[]` 逐例行：`{scenarioId, roundNo, group, baseline{caseExecutionId, verdict,
  rootCauseHit, expectedRootCause, selectionPolicyVersion, contentDigest},
  candidate{...}, verdictChange, differenceNote, inputDigestMatch, clusterId,
  faultType}`。`differenceNote` 人读一句（如"根因命中→未命中（判定
  DECIDABLE→UNRESOLVED）"）；持平且判定同形 → null 不出噪声。
- `unpaired[]` 行：`{scenarioId, roundNo, side(BASELINE_ONLY/CANDIDATE_ONLY),
  reason(MISSING_IN_BASELINE/MISSING_IN_CANDIDATE/INPUT_DIGEST_MISMATCH),
  caseExecutionId}`；上限 500 条（超出 `unpairedTruncated=true`，计数仍按全集）。
- 有界闸：单侧案例扫描上限 10_000 行，超出 `scanTruncated=true` 且门转
  INCONCLUSIVE(DATA_TRUNCATED)——部分数据不出资格结论。

## 2. 配对与可比性语义

### 2.1 配对身份

- 配对键 = **(scenarioId, roundNo) 精确键**（uq_eval_case_result 保证 run 内唯一）；
  只统计两侧都有结果且输入 digest 未冲突的案例。
- 单侧缺席如实列入 unpaired，不猜归属（EU25）。
- 输入快照核验：case_version.content_digest 经精确键横向解析
  （dataset_version = run.dataset_version 且 case_key = scenario_id；
  无匹配/多命中歧义/HOLDOUT RLS 不可见 → null，EV-05 同律不取"最新"冒充）。
  两侧 digest 均可解析且不等 → INPUT_DIGEST_MISMATCH 剔除出配对；任侧不可解析 →
  `inputDigestMatch=UNVERIFIED` 不阻断配对（如实标注）。
- 簇键 = scenario_family_id（任侧可解析即用），两侧皆 null 回退 scenarioId。

### 2.2 可比性检查（§3.5 顶部检查带）

严格维度（全等才 comparable，不一致入 mismatches 清单）：

| 维度 | 来源列 |
|---|---|
| datasetVersion | eval_run.dataset_version |
| inputSnapshotDigest | eval_run.registry_digest（场景注册表内容摘要 = 输入快照锚） |
| rulesVersionDigest | eval_run.alert_rule_digest（评测期规则集摘要 = 规则版本） |
| lexiconVersion | eval_run.lexicon_version |
| scenarioDriverVersion | eval_run.scenario_driver_version |
| selectionPolicyVersions | 逐案例 selection_policy_version 去重升序集（评分对象选择策略 = 评分器语义锚） |

非严格维度（equal 照算但不参与 comparable 判定）：

- `graderVersion`：**eval_run 无评分器版本列**（偏差①）——维度如实列出
  `equal=null`（NOT_AVAILABLE），不冒充不阻断；评分器语义由
  selectionPolicyVersions 维度承载。
- `model` / `promptVersion` / `configDigest`：模型与 Prompt 差异正是对比动机
  （§3.5 信息面展示），不参与严格判定。

### 2.3 统计与质量门

- 配对统计复用 PairedTrialStats（cluster-bootstrap-v1 冻结口径）：簇级整组有放回
  重采样，独立簇 < 5 → INCONCLUSIVE 且区间置空（EU24 不伪造显著性）。
  statsSeed 冻结推导 = 两 run UUID 高低位链式混合（方向敏感；同有序对重算
  必得同区间，种子随落档记录可复现）。
- 判定变化矩阵 = 配对案例的 `基线verdict→候选verdict` 计数（如
  DECIDABLE→UNRESOLVED、UNRESOLVED→DECIDABLE）。
- 簇统计 = 按簇键分桶 {paired, improved, regressed, flat, pointEstimate}；
  故障源分桶 = expected_root_cause.fault_type 分桶同四计数（UNSPECIFIED =
  无故障源字段如实）。
- 对比质量门 **eval-compare-gate-v1**（冻结分支序）：
  1. comparable=false → NOT_EVALUABLE(COMPARABILITY_CHECK_FAILED)
  2. scanTruncated → INCONCLUSIVE(DATA_TRUNCATED)
  3. pairedCount=0 → INCONCLUSIVE(NO_PAIRED_CASES)
  4. 独立簇不足/统计 INCONCLUSIVE → INCONCLUSIVE(INSUFFICIENT_CLUSTERS)
  5. 退化率 regressed/paired > 0.10 → FAIL(REGRESSION_RATE_EXCEEDED)
  6. 配对差值 CI 下界 < -0.05 → FAIL(CI_LOWER_BELOW_MARGIN)
  7. 全过 → PASS（reasons 空）

  阈值随 gate 块携带（maxRegressionRate/ciMargin）= 复现锚。三门结论语义：
  PASS=对比资格过 / FAIL=退化越限 / INCONCLUSIVE=证据不足 / NOT_EVALUABLE=不可比。

## 3. 持久化（V85 eval_comparison）

insert-only 落档表：可比性维度清单 + 配对五计数 + stats 溯源快照（jsonb 原文，
无配对如实 NULL）+ 门结论/原因/规则版本 + actor/created_at。落档即冻结，
重落档 = 换新 id 一行（同对"生效面" = created_at DESC, id DESC 最新行）；
DB CHECK 兜底：baseline≠candidate、PASS 零原因/非 PASS 必带原因（解释完整性）。

授权：control_app select,insert；eval_app/publisher/notify/arena/chaos/public
显式 revoke（对比结论是 control 面读侧产物，无 worker 消费面）。

**qualityVerdict 分面接线（EV-03 遗留 UNKNOWN → 真值）**：runs 投影新增
comparisonGateOutcome 子查询（本 run 作为候选的最新落档门结论）→
facets.qualityVerdict：PASS→OK、FAIL→VIOLATED、INCONCLUSIVE/NOT_EVALUABLE/
无落档→UNKNOWN。语义 = 对比资格结论（相对某基线），非单 run 绝对质量。

1. **grader 版本无列**：eval_run 无评分器版本列，方案"评分器版本严格一致"维度以

   评分器语义；若后续补 grader_version 列，可比性维度清单加一行即可（维度表开放）。

   （model/prompt/config 信息面 + mode 分面），臂型同预算同工具的强校验待方案
   冻结阈值后入维度表。

   落档的是**对比质量门**（eval-compare-gate-v1），不冒充 M5-08 单 run 门禁记录；
   qualityVerdict 分面语义因此是"对比资格"而非"单 run 发布资格"。
4. **逐例"结构化根因逐项 diff / 文本差异与评分变化分开"（§3.5）未做**：本卡
