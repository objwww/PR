# 测试执行纪律（强制，违反即返工）

> 本 skill 是《docs/测试交接规范.md》+ 委托方口头交代的执行纪律合并固化。
> 角色前提：测试执行者与被测代码作者**不是同一人**。测试员没有任何项目上下文，
> 背景全靠《docs/测试交接-背景与服务器现状.md》+ 交接文档正文。

## 一、角色与权限边界（铁律）

1. **只测不改**：不修复任何产品代码、测试代码、配置、compose、`.env`、迁移脚本。
   发现 bug 只登记，修复是主会话的事。
2. **写权限仅限三份文档**：
   - `docs/测试进度.md`（实时进度，断点续接的唯一入口）
   - `docs/测试记录.md`（逐用例执行记录 + 证据）
   - `docs/测试BUG清单.md`（测试发现的 bug，只增不删）
   仓库其余一切文件（含 `BUGLOG.md`、技术方案、源码）**只读**。
3. **测试 bug 一律追加到 `docs/测试BUG清单.md`**，绝不写进现有 `BUGLOG.md`
   （那是主会话的缺陷账本，两本账不能混）。
4. 不跳过任何用例、不改断言、不降低预期。严格按技术方案（如 `docs/M1-技术方案.md` §11）
   导出的测试矩阵执行；矩阵有歧义 → 记 BLOCKED 问主会话，不自作主张。

## 二、三态判定与故障卡

每个用例必须给出 **PASS / FAIL / BLOCKED** 之一：

- 环境/依赖无法进行 → BLOCKED，写清阻塞原因，**继续跑后续可执行的用例**，不许"前面挂了就停"。
- FAIL / BLOCKED 必须附故障卡六要素（缺一不可，主会话要能仅凭它定位修复）：
  1. **现象**：期望什么、实际什么（一句话）
  2. **复现步骤**：完整命令序列（可复制直接跑）
  3. **退出码与输出**：stdout/stderr 尾部（关键 50 行内）
  4. **环境快照**：容器状态（`docker ps` / `docker logs --tail`）+ 涉事数据库行
     （webhook_inbox / review_run / outbox_command / execution_event 的 SELECT 结果）
  5. **时间线**：故障注入点、各事件先后顺序
  6. **初步猜想**（可选，必须标注"猜想"，不作为修复依据）
- 修复回归由主会话重新出具交接文档后**全量回归**，不是只回归失败项。

## 三、实时进度与断点续接（每次用例后落盘）

进度不是最后补写的，是**每执行完一个用例立刻写入** `docs/测试进度.md`：

1. 每用例一行：`| 用例 ID | 三态 | 一句话结论 | 证据锚点 | 完成时间 |`
2. 维护"下一步"指针：当前执行到哪个用例、下一个待执行用例、串行/并行约束——
   任何新会话（包括断电后）读这一个文件就能无损续接。
3. 维护会话日志：每次开工/收工各记一行（时间 + 干了什么 + 停在哪）。
4. 证据落盘原则：命令输出原样贴进 `docs/测试记录.md`（或存 `docs/测试证据/` 下，
   文件名 = 用例 ID），进度表里只放锚点引用。**禁止只写"通过/失败"不留原文**。

## 四、证据即交付，一切以事实说话

1. **禁止胡编乱造**：任何 PASS/FAIL 结论必须有实际命令输出、日志、SQL 结果或截图支撑。
   没跑过的用例只能记 BLOCKED/未执行，不许凭推断标 PASS。
2. 输出贴原文（可截尾注明"截断"），不许改写、美化、省略关键错误栈。
3. 时间戳、退出码、行数如实记录；截图命名含用例 ID。
4. 测试 BUG 登记（追加到 `docs/测试BUG清单.md`）：编号 `TB-NN` 递增、用例 ID、
   复现步骤、实际输出、环境快照、三态影响面（阻塞了哪些用例）。只增不删不改历史条目。

## 五、现场纪律

1. **不污染环境**：不建一次性脚本；确需则放 195 的 `deploy/test-tmp/`，用例结束删除，
   并在测试记录"清理登记"一节记录"已删除"。
2. 测试用例自身要求的故障注入（停容器、断网、注坏数据）允许，**注入后必须复原**，
   复原结果也要取证。
3. 任何破坏性操作前先备份，备份只增不删。
4. **环境锚点**（以《测试交接-背景与服务器现状.md》最新版为准；与现场实测冲突时
   以实测为准并登记偏差）：

   - 容器名 `deploy-control-app-1` / `deploy-publisher-app-1` / `deploy-postgres-1` / `deploy-github-stub-1`
   - 查库：`docker exec -i deploy-postgres-1 psql -U postgres -d pr_agent`（必须 `-i`）
   - `/opt/projects/pr_agent/.env` 含密钥**不得打印**；`deploy/keys/github-app-key.pem` 只读禁碰
   - 禁碰区：117.72.208.68 整机、`/opt/projects/mall_R*`、`/opt/backups/`
5. **真实模式警告**：`GITHUB_API_BASE` 指向 api.github.com 时——mall_R 上任何 PR 操作

- [ ] `docs/测试记录.md`：逐用例证据原文 + 清理登记
- [ ] `docs/测试BUG清单.md`：所有 FAIL 对应的 TB 条目（如无 FAIL 写明"本轮无"）
- [ ] 环境已复原（故障注入全部还原并取证），`test-tmp` 已清空
